# VP-001 · 让方法工程进入真实运行

## 意图

将当前已经形成的最小方法工程启动机制投入真实实践，使方法工程能够围绕真实、具体且有边界的问题开展工作，并在实际运行中持续获得对自身结构、规则与适用边界的反馈。

本波次的核心变化是：让方法工程从“我们已经形成一套可以开始工作的最小共识”，进入“我们已经能够使用这套机制持续开展真实 Method Case，并能够根据实践证据识别、定位和修正必要问题”的运行状态。

当前的状态机、Frame、Challenge Gate 及相关纪律只是启动工作的阶段性机制。本波次应首先实际使用它们，而不是继续预先扩展。具体 Method Case 是实现本意图的真实工作与证据来源，而不是本意图本身。

本意图落在现行 Charter `method-engineering@0.1.0` 之内：真实问题优先、证据驱动演化、层次区分；不把框架正确性或某一个具体方法的完成当作本波次成功。

## 方向级退出判据

在同时满足下列方向时，本 VP **可以**有界或完整关门（证据必须在工作区目标内）：

1. 至少一个真实、具体且有边界的 Method Case，已经实际使用当前最小启动机制开展工作，而不是继续停留在对机制的预先扩展。
2. 已有实践证据，能够说明该机制是否足以支持问题界定、研究、工程、评价与重构；若暴露必要缺口，缺口已被识别并定位。
3. 实践记录能够区分三类问题：Case 本身的问题、所构造方法的问题、方法工程框架自身的问题；未把不同层次混为一谈。
4. 对启动机制的修正或补充，仅发生在真实实践暴露必要缺口之后；不存在以“证明机制正确”或“预先补全体系”为目的的扩展。
5. 已形成“通过真实工作持续演化方法工程能力”的基本闭环：真实 Case → 对结构、规则与适用边界的反馈 → 识别、定位并在必要时修正问题。

本 VP 的关门表示进入可持续运行的状态，不表示方法工程能力已经完备，也不表示某一个具体方法已经完成。

## 本波次不追求

- 证明某套 Bootstrap、状态机、Frame、Challenge Gate 或治理结构“正确”。
- 以构建某一个具体方法为最终目的。
- 在真实实践暴露必要缺口之前，预先扩展启动机制。
- 把具体 Method Case 本身写成愿景意图。
