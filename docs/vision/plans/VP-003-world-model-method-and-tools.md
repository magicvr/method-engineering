# VP-003 · 为消费方构建世界模型的方法与工具

> 本 VP 承接真实需求 `WRK-002-world-model-method-and-tools`：下游 `WorldModel.ModernCultivation` 按 [`protocols/consumer-response-protocol.md`](../../../protocols/consumer-response-protocol.md) v1.0.0 提报，本仓于 2026-09-26 受理并形成处理承诺（[`runtime-records/WRK-002-…/record.md`](../../../runtime-records/WRK-002-world-model-method-and-tools/record.md)）。
> 本文件是**意图**的权威落盘；工作区 `primary_plan` 只能引用已存在的本类文件。本 VP 不写 progress%、Goal status、子目标编号或可执行纲领阶段。

## Problem

下游 `WorldModel.ModernCultivation` 维护一个可被多部作品共同使用的世界模型服务（Charter `vision-modern-cultivation@0.2.0`），其承载结构——模型域内部目录与文件结构、条目形态、模型层/状态层归属判定、世界级共享状态承载、跨模型耦合、增长与规模分层、作品事实晋升、缺口诊断归因——在**没有方法论依据时该仓无权自行发明**，已被其显式登记为结构性未知并于正文侧冻结。

该仓的原领域方法需求曾在 `WRK-001` 中被明确「未受理、须另建处理主线」，2026-09-26 其以 `WRK-002-world-model-method-and-tools` 正式提报需求原文《构建按需世界模型方法》：需要一套**可实际运行的工作方法**，使作者在创作中遇到客观裁决需求时，能够判断现有模型能否回答、识别所缺是状态/组合/精度/机制、以最低充分机制模型补足能力，并完成「发现缺口 → 构建模型 → 注册能力 → 完成裁决 → 检查 → 返回创作」的闭环；配套工具与该方法工作版同为其要求交付的对象。

本仓已有的能力缺口是：协议侧（`VP-002`）已建立供需双方如何发起、受理、交付与确认，但**方法侧从未针对「世界模型」这一对象产出过可交付的方法工作版与配套工具**。本 VP 即为该欠缺的正式载体。

## 意图

在已升格的消费方需求—响应协议与单一运行主记录语义之上，为下游构建并交付**世界模型的方法与工具**：

1. **澄清与冻结需求边界**：与下游确认方法工作版的适用对象与退出形态、配套工具的形态与时机（按下游需求原文 §9「结构化和工具化只在重复使用确有价值后进行」）、有界检验用例与授权限额，并把这些结论落到 `WRK-002` 主记录与双边材料。
2. **形成世界模型构建方法工作版**：至少覆盖下游需求原文 §10 的缺口判定次序与 §13 的十项指导（识别裁决需求、能力发现、缺口归类、定义新裁决能力、构造最低充分机制模型、反补丁检查、适用范围与条件敏感性验证、模型组合与冲突、版本与受影响旧裁决、能力回流创作），并明确适用条件、已知边界、限制与未决事项。
3. **界定并形成配套工具**：按澄清结论形成配套工具的可交付最小形态，或明确说明本轮不引入工具及其触发条件；工具不得成为方法有效性的替代条件，也不得与下游 Charter「不以工具或发布产物为成功条件」冲突。
4. **有界检验与交付验收**：在至少一个真实世界问题上完成一次有界检验，把方法工作版与配套工具交付至下游 `exchange/WRK-002-world-model-method-and-tools/`，并按协议完成实际收件、验收或异议迭代、反馈分类路由与结束回路。

## 方向级退出判据

在同时满足下列方向时，本 VP 可以有界或完整关门（具体证据必须在挂接工作区的目标内）：

1. **需求边界已冻结且双边留痕**：方法工作版的适用对象与退出形态、配套工具的形态与时机、有界检验用例、限额与责任已由双方确认，并可在 `WRK-002` 主记录与 exchange 材料中核对；不得以「以后再澄清」越过影响交付的门禁。
2. **方法工作版已形成并可交付**：覆盖上述第 2 项所列指导范围，具备可核对要素（交付版本、适用条件、验证结论与证据、限制、未决事项、后续责任）；未覆盖部分必须显式列为限制或未决事项，不得以措辞掩盖缺口。
3. **配套工具按澄清结论交付或明确说明不引入**：工具形态与方法的重复使用价值判断一致；若本轮不引入工具，须写明触发条件与责任，且不与下游 Charter 非目标冲突。
4. **至少一次真实世界问题上的有界检验完成并留痕**：检验只证明本次闭环在该用例上可执行、可追溯，**不证明**方法普遍有效，也不代表下游承载未知已被关闭。
5. **下游完成收件与验收（或异议迭代至接受），回路结束**：交付、实际收件、验收或异议分别记录，不得相互推导；反馈已按对象问题 / 方法问题 / 运行机制问题分类并路由；运行主记录进入「已退出」或明确终态。

本 VP 关门须链接双边共享追踪线上的实施与结项证据，并明确证据所证明的范围。下游实际未消费交付、未给出验收或异议时保持未关门。下游是否据此关闭其承载未知、是否启用配套工具，**不是**本 VP 的退出前提。

## 范围

1. `WRK-002` 主线的澄清、授权确认与需求边界冻结；下游承载约定与材料路径/格式的沿用。
2. 世界模型构建方法工作版的形成、内部复核与版本管理。
3. 配套工具形态的界定与最小形态形成（或明确不引入及其触发条件）。
4. 至少一次真实世界问题上的有界检验，与其证据、限制记录。
5. 交付到下游 exchange、实际收件、验收或异议迭代、反馈分类路由与结束。
6. 治理衔接：本 VP 挂接工作区与 Root 的目标、信息门禁与审计证据。

## 非目标

- **不替下游做世界观设定或 canon 裁决**：不编写下游 `world/` 设定正文，不替其关闭 `U-1`～`U-8`，不替其裁决 `H-003` / `H-004` 等内容级基线。交付材料不是下游 canon。
- **不承诺方法普遍有效**：一次有界检验不构成对方法普适性的证明，也不构成对下游「按需增长」边界的验证。
- **不承诺下游启用配套工具**：工具在本仓交付即完成本 VP 的义务；是否启用及启用边界由下游用户书面裁决。
- **不建设产品化服务**：不建设 API、Web UI、自动化派发、跨仓同步服务或特定平台适配器。
- **不做领域有效性的大规模实验**：只做澄清约定范围内的有界检验。
- **不建立第二套状态源**：不在愿景层写 progress%、Goal status、子目标编号或可执行纲领阶段；运行状态只以 `runtime-records/WRK-002-…/record.md` 为准。

## 与 Charter、既有 VP 及下游的关系

- **对齐 Charter**：本 VP 服务 Charter 的方向级成功边界 1（从真实、具体、有边界的问题出发形成可被使用、检验和改进的方法）与 3（区分对象问题、方法问题与自身框架问题），不改变 Charter 的目的、边界或非目标；不构成 `strategic` 修订。
- **承接 `WRK-001` 的未竟事项**：[`VP-002-consumer-demand-response-protocol`](VP-002-consumer-demand-response-protocol.md)（有界 `closed`）只定义了供需双方如何发起、受理、交付与确认，其 Non-goals 明确排除「交付某个特定领域方法」。`WRK-001` 的原领域方法需求未获交付，已明写须「另建处理主线」；本 VP 即该主线的愿景层载体，不追溯改写 `VP-002` 的退出判据与结项结论。
- **不重开已关门 VP**：VP-001 / VP-002 的 `closed` 结论保留；本 VP 与它们并列为同一愿景下的不同波次。
- **下游为消费方**：下游 `WorldModel.ModernCultivation` 的 `VP-002-world-model-method-acquisition` 判据 2 要求「方法工作版与配套工具」都可验收；本 VP 的判据 2/3 与之对应，但两边各自保有独立的状态权威与门禁。
