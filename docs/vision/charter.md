# Charter · 可靠的方法工程能力

## 目的陈述

我们要建立并持续演化一种可靠的方法工程能力，其首要目的始终是解决真实、具体且有边界的方法工程问题。

这里的“方法工程”指的是：面对具体、有边界的问题，能够利用已有可靠知识、必要的研究与实际验证，系统地构造、选择、裁剪、评价和改进解决问题的方法。

这种能力的演化服务于解题，而不是取代解题。框架、术语和结构只有在有助于更可靠地解决真实问题时才具有意义。

## 方向级成功边界

在本愿景仍为 `active` 的前提下，下列方向成立即视为仍在愿景内；这些是方向边界，不是一次性验收清单：

1. 持续从真实、具体且有边界的问题出发，利用可靠知识、必要研究和实际验证，形成能够被使用、检验和改进的方法。
2. 优先继承成熟知识与方法；只有当真实问题或实践证据暴露出不足时，才研究、修改或增加新的结构。
3. 持续从真实 Case 获得反馈，并能区分对象问题、方法问题与自身框架问题，避免把不同层次的问题混为一谈。
4. 将经过真实 Case 检验的有效结构、方法和经验，在明确适用边界的前提下积累、复用并继续检验。
5. 在有证据需要时修正自身，同时避免无必要地重复造轮子或无限向基础理论递归。

## 非目标

本 Charter 不要求、也不把下列事项写成愿景成功条件：

- 建立一套试图解释世界的普遍理论。
- 预先设计一套完备且永久正确的方法论体系。
- 假定存在对所有问题普遍有效的方法、框架或流程。
- 让框架、术语或结构的演进取代对真实问题的解决。
- 为了形式上的完整而重复造轮子，或无限向基础理论递归。

## 原则摘要

- **真实问题优先**：方法工程首先服务具体问题，不以抽象体系建设替代解题。
- **证据驱动演化**：优先继承成熟知识；新增或修改结构应由真实实践中的不足、研究或验证结果触发。
- **边界明确**：可迁移的知识、方法和经验必须同时说明适用条件与已知边界，不能把局部有效性写成普遍有效。
- **层次区分**：持续区分对象问题、方法问题和框架问题，并区分事实、假设、暂定定义与已验证结论。
- **可复核与可修正**：关键判断保留可追溯证据；当反例或新证据出现时，允许并要求修正自身。

治理操作原则以 [`docs/architecture/principles.md`](../architecture/principles.md) P-001～P-006 为准；本 Charter 不另立一套更宽或相冲突的规则。
