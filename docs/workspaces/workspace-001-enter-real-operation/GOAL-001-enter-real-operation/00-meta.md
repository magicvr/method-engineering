# GOAL-001 · 让方法工程进入真实运行

## 概述

本 Root 服务 [`VP-001-enter-real-operation`](../../../vision/plans/VP-001-enter-real-operation.md)。主语是**让方法工程进入并能够继续真实运行**：围绕真实、具体且有边界的问题，使用当前最小启动机制开展 Method Engineering 工作，产生可评价的工作结果与实践反馈，并形成后续 Case / 后续工作 / 后续 Intent 可继承的运行基础。

当前状态机、Frame、Challenge Gate 及相关纪律是本阶段的候选启动机制，应先被实际使用，而不是继续预先扩展。它们的充分性观察、必要修正和继承裁决是支撑事实，**不能替代**「已经开展真实方法工程工作」这一结果。

具体 Method Case 是真实工作与证据来源，不是本目标要完成的某一个方法，也不是 Root 关门的充分条件。本目标不以证明候选机制「正确」为成功条件。

## 愿景对齐

- `serves_summary`：使方法工程进入并能够继续真实运行——用当前最小启动机制完成有边界的真实 Method Case 工作，产生可评价结果与可继承反馈。
- `plan_refs` / `primary_plan`：`VP-001-enter-real-operation`
- Charter：`method-engineering@0.1.0`
- 与 VP 方向级阶段的关系：VP D1–D3 只给方向；本 Root S1–S3 是可执行纲领阶段（见 D-002）。

## 成功标准

**主语**：方法工程已进入并能够继续真实运行。下列「启动条件」必要但不充分；Root 关门必须同时具备运行结果与收束事实。

启动条件（必要，不构成完成）：

- [ ] 已固定当前最小启动机制的可核对基线（仓内路径或固定引用），作为使用与比对起点（`I-001`）
- [ ] 已选定至少一个真实、具体且有边界的 Method Case，并开始实际使用当前机制，而不是继续预先扩展机制（`I-002`）

运行结果（Root 关门不可替代）：

- [ ] 至少一个真实 Case 已依靠当前机制完成一段有边界的实际方法工程工作，并产生可被实际评价的方法成果或工作结果
- [ ] 评价与实践反馈已经能够进入后续工作（后续 Case / 后续工作 / 后续 Intent），而不只是回看候选机制是否够用
- [ ] 实践记录能区分 Case 本身的问题、所构造方法的问题、方法工程框架自身的问题
- [ ] 对启动机制的修正只发生在真实实践暴露必要缺口之后

收束与继承：

- [ ] 已形成可供后续 Method Case 与后续 Intent 继承的正式运行基础：对本轮候选运行资产逐项作出 `Promote` / `Retain as experimental` / `Archive` / `Discard` 裁决，每项含适用边界、实践证据与可追溯决策或审计记录（`I-003`）。本项不预先承诺任何资产必然 Promote。

## 纲领路线图（P-001）

> 本表属于本 Root，是可执行纲领阶段。愿景层 VP-001 的 D1–D3 只给方向，不替代本表。
> 解题是主过程；观察、分层与机制修正是真实工作产生的反馈，不是本路线图的主语。
> 响应 `A-001` `F-002` 后的阶段名：S1 建立运行基线 → S2 真实运行 → S3 收束与继承。

| 阶段 | 名称 | 状态 | 退出条件 |
|------|------|------|----------|
| **S1** | 建立运行基线 | 未开始 | `I-001` 已给出可核对基线；`I-002` 已选定至少一个真实、有边界的 Method Case；该 Case 已启动（开始实际使用当前机制，而非继续预先扩展）。对应 VP D1。 |
| **S2** | 真实运行 | 未开始 | 已使用当前机制实际开展 Method Engineering 工作；已产生可评价的方法成果或工作结果、评价结果和实践反馈；观察与分层作为工作中的反馈动作完成（能区分 Case / 方法 / 框架）。对应 VP D2，但主语是解题而非观察框架。 |
| **S3** | 收束与继承 | 未开始 | 实践暴露的必要结构性缺口已处理或已有书面 residual；基本运行闭环成立；候选运行资产已逐项 `Promote` / `Retain as experimental` / `Archive` / `Discard`（`I-003`）；反馈已成为后续 Case / 工作 / Intent 可继承的起点。对应 VP D3。 |

阶段先后：S1 → S2 → S3 串行。S2 与 S3 可在同一 Case 内交替取证，但不得在 S1 的基线与 Case 启动完成前假装进入真实运行或收束。同一纲领阶段内允许并行子目标。单个 Case 跑完或机制「看起来够用」不能自动关闭 Root。
