## D-003 · 响应 A-003 recommended：预置最小 S3 收束协议

### 触发

独立复审 [`A-003-root-freeze-readiness.md`](../03-audit/A-003-root-freeze-readiness.md)（`source: independent`，`verdict: pass`）提出三项低严重度、非阻塞的 `recommended`：`F-004`、`F-005`、`F-006`。用户本轮指令：「响应一下复审A-003，处理一下recommended，然后提交一下」。本轮无冲突意见，也不涉及 required finding 的 residual 或 overruled 裁决。

### 决定

1. **F-004：把反馈去向纳入 I-003 的 S3 证据要求。** 第一次真实收束时，对每条实践反馈登记明确去向：候选资产的 `Promote` / `Retain as experimental` / `Archive` / `Discard`，或在不属于资产时链接到后续 Case / 后续工作 / 后续 Intent 输入、`accepted-residual` 或开放 finding。该要求现在只作为执行层规则记录；在实际 S3 事实产生前，不把 F-004 写成已完成。
2. **F-005：预置 `Archive` / `Discard` 的最小操作语义，并在第一次真实资产裁决时应用。**
   - `Archive`：保留资产及其历史证据，移出默认继承/启用集合；后续如需重新启用，必须有新的明确决策与证据。
   - `Discard`：判定该资产不进入后续继承或默认启用集合；不删除审计与决策证据；重新启用不能被默认推定，须有新的证据与明确决策。
   这只是区分历史保留与后续继承资格的最小操作协议，不构建额外资产治理元模型。
3. **F-006：冻结当前最小字段集合。** 后续 I-003 / S3 记录只要求资产或反馈对象、处置决定、适用边界、实践证据、决策/审计路径；不预先增加成熟度、置信度、风险评级、方法类型或来源分类等字段。只有真实实践暴露必要缺口时，才另行记录决策并增补。
4. 本轮不修改 Root 成功标准、纲领阶段检查点、`status` 或 `progress`；`I-001`、`I-002` 仍为阻断 S1 的 open required，`I-003` 仍为阻断 S3 / Root 关门的 open required。

### 为什么

- F-004 的风险不在当前定义是否正确，而在未来收束时「反馈能够进入后续工作」缺少可核对落点；把明确去向加入 I-003 证据要求能直接补上该落点，同时不虚构尚未发生的 S3 事实。
- F-005 只需要历史保留、默认继承资格和再次启用条件的最小区别；先记录最小语义可以避免第一次裁决时产生歧义，但不应借机建立资产治理分类体系。
- F-006 明确要求保持当前厚度；以范围护栏留痕比现在扩写 Root 或增加元模型更符合 VP-001「先真实使用、再按证据演化」的边界。

### 未选方案

- 现在改写 `00-meta.md` 或新增 Root 成功标准：A-003 已确认定义冻结就绪，F-004～F-006 不要求重构 Root；改写会把执行协议提前提升为目标定义。
- 在没有真实资产的情况下创建资产清单或声称 F-004 已 `fixed`：没有可核对实践事实，违反只记录已发生事实的边界。
- 立即增加成熟度、置信度或风险评级等字段：会把本波次的收束重新膨胀为资产治理元模型，违反 F-006 的范围护栏。
- 将 A-003 的 `pass` 解释为 S1 放行或 Root 完成：A-003 仅覆盖 Root 定义冻结就绪性，不能覆盖 `I-001` / `I-002` / `I-003`。

### 影响与后续

- `01-decision.md` 的 `I-003` 行补充「每条实践反馈的明确去向」要求；实际证据仍须在 S3 的执行、决策或审计记录中产生。
- A-003 原文及其 `F-004`～`F-006` 的 `open` 状态保留；编排响应记录在 A-003 响应节与 `A-004`，不改写独立意见。
- 在 S1 之前先完成 `I-001` 机制基线与 `I-002` 首个真实 Case；到 S3 首次资产裁决时按本条最小 `Archive` / `Discard` 语义复核，并为所有反馈补充明确去向。
