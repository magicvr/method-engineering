# S1 Research-Loop 独立调用后续试跑设计 · v0.2

> **状态：draft / unaccepted / not trialled。** 这是在已接受的 v0.1 设计与 run-01 之后提出的单次后续试跑方案；不替换或改写两项既有记录，不授权研究调用。

## 1. 目的与证据边界

用一次隔离上下文中的 S1 research-loop 独立调用，检查：(a) 不向执行者预置具体机制或检索方向时，研究是否能从有限问题自行形成有出处的机制候选；(b) 研究返回后的候选、证据和推理能否按修正后的调用/回流次序交给 Rule E/F/G。该试跑只提供一次行为样本，不证明普遍方法有效、目标世界事实成立、coverage 穷尽或 handoff-ready。

[run-01](s1-independent-call-trial-run-01.md) 继续作为有效的调用/取证样本。它曾暴露机制名称与检索方向提示，因此不证明自主发现。本方案是新的 run-02 设计，不能把 run-01 改标为无效，也不把两次样本合并成普遍验证。

## 3. 盲测案例候选

本节为合成案例草案，不是 GOAL-004 Probe 1、用户创作 canon 或 GOAL-002 W4 / `I-402` 证据。拟给执行者的唯一问题是：

> 一个偏远小型社区有饮用水送达住户。一次服务中断期间，记录显示住户端情况不一致：部分住户仍能取水，部分住户不能。当地供水系统的具体结构、依赖与中断原因均未提供。请进行一次有界外部研究，识别可能导致同一服务中断期间住户端结果不同的一般机制候选，并说明哪些目标侧事实可用于区分或验证这些候选；资料只能支持一般机制候选及其适用边界，不能证明该社区的真实系统情况。

执行包不预置研究问题以外的机制名称、固定子问题/taxonomy、检索词、来源标题或预期答案。研究问题应从上述输入及 S1 的当前未知中形成，并在调用前记录；不应把研究返回后才形成的条件候选、来源主张或关联推理倒置成调用输入。

案例只供测试资料能否补充机制候选与适用边界。未发现某机制，不等于该机制不存在；目标社区的配置仍是目标侧未知，不能由外部类比直接判定。

## 4. 执行隔离与调用界限

若后续获准执行，应在新建、无历史上下文的隔离执行会话中进行。执行会话可见拟接受的 host、adapter、Core、Schema 和本节问题卡；不得提供 run-01、A-001/A-002、既有来源/查询、已知机制清单或本设计的评审意见。若执行者已接触这些试跑材料，结果只能称为“去提示试跑”，不得声称对既有机制提示保持盲态。

一次调用只处理一项研究问题；最多 5 个定向查询变体、查看最多 6 份来源，计划工作量边界 45 分钟，并在查看 3 份来源后复核是否继续。无法可靠计时则保留查询数、来源数、检查点与停止理由作为可复核边界。不得因未发现预期候选而超额扩搜；证据不足、冲突或不适用时如实停止并登记 residual。

调用输入限于调用时已经存在的原问、目标侧已知锚点/前提（如有）、局部结构位置、未知及 owner、用途标准和已有证据。外部研究生成的候选、支持机制与关联推理只在返回后记录。出现接口契约缺口时保存记录并停止受影响步骤；不得在试跑期间临时修改 Core、Schema 或 Adapter。

## 5. 评估与停止标准

按实际记录评价以下过程证据，不预设必然发现任何机制：

1. 是否准确记录四元组件身份、调用时已知输入、未知 owner、研究问题、用途标准、来源范围和停止边界；
2. 每项证据主张能否追溯至来源定位，并区分来源直接陈述、AI 推论、迁移依据/限制及尚未知的目标事实；
3. 执行输入和查询是否由问题导出，且未依赖预置机制提示；
4. 返回后是否由 Rule E 检查候选的必要结构贡献、输入否定、冗余与既有节点承载；由 Rule F 确定未知归属；由 Rule G 判断 coverage、收束和范围影响；
5. 是否保留未找到与不存在的区别，登记未解决未知、停止原因和下一步 owner。

成功不以发现某个指定机制或必须新增问题节点为条件。核心行为证据是：研究有界、出处与迁移边界可复核、回流时序正确、宿主保留既有裁决权。若类比/间接资料被当作直接目标证据，保存原文与回流处理，记录为试跑发现；继续观察现有 `support`、`limits_and_conditions` 与 `applicability` 是否足够。本轮不增 `evidence_role` 字段。

达到本轮用途标准且无未处理高影响冲突时停止回流；上限耗尽仍不足则记为 `partial/insufficient`、`conflicting` 或适用的 Core 结局，并登记 residual。不得扩成开放式 coverage search、第二次调用、S2 试跑或 GOAL-004 案例复查。
