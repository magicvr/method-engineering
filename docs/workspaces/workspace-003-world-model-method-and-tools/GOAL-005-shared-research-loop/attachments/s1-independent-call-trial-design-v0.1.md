# S1 Research-Loop 独立调用试跑设计 · v0.1

> **状态：创作者已接受为试跑设计基线；尚未集成、未执行试跑。** 本方案选定可核验的 S1 设计参照基线，并提出一个独立、有限的 research-loop 调用试跑。它不修改任何已接受组件，也不等于 host 已完成集成。

## 1. 试跑目的与边界

只验证完成窄 S1 host 集成后，S1 能否从一个局部未知调用 research loop：形成有界问题、按共同记录结构留存可追溯证据、受控地回交候选，并由该 S1 host 的 Rule E/F/G 作后续处理。它检查 S1 调用/回流接口和证据链，不检验 S1 的整体充分性或普遍有效性。

本次使用已接受的 [Shared Research Core v0.1.0](shared-research-loop-core-v0.1.0.md)、[Shared Research Record Schema v0.1.0](shared-research-record-schema-v0.1.0.md) 与 [S1 Research Adapter v0.1.0](s1-research-adapter-v0.1.0.md)，其接受状态见 [D-004](../01-decision/D-004-core-design-baseline.md) 与 [D-006](../01-decision/D-006-components-accepted.md)。试跑期间不得修改或替换这些组件；出现契约缺口时记录并停止受影响步骤。

## 3. 案例候选与研究问题

以下是**试验用合成设定**，不是 GOAL-004 的 Probe 1、不是用户创作 canon，也不计作 GOAL-002 W4 / `I-402` 的真实案例：一个偏远小型聚落从本地水源取水，经处理后由依赖电力驱动的泵向住户供给饮用水；当前不知道停电时哪些系统条件会导致供水中断，哪些会维持供水。

局部未知：“外部电网中断是否足以推出住户饮用水中断，还是结论取决于系统依赖与可用的替代路径？”

单一 research question：**对依赖电力泵送的小型饮用水系统，哪些有资料依据的系统条件会使外部电力中断导致或不导致终端供水中断？**

案例只给出上段明示假设。不得预设任何具体系统配置、故障缓解机制或固定子问题清单；资料中出现的配置、taxonomy、风险类别先作为有出处的候选，由 Rule E/F/G 和创作者按 S1 职责处理。若创作者不接受此合成案例，需替换案例后再授权运行。

## 4. Owner、用途标准与来源策略

- 研究 owner：AI 对指定研究问题负责；来源主张由来源身份和原文定位支持。
- 创作者权责：确认合成设定边界，并对候选是否进入其结构作最终裁决；研究结果不等于目标世界事实。
- 用途标准：形成足以回交 Rule E/F/G 的有界候选证据包——能指出何种系统条件支持或限制“停电导致供水中断”的关系，区分来源直接陈述、AI 推论和目标设定待创作者决定的主张，并写出迁移条件与未决项。无需推出完整供水设计，也不要求必须新增节点。
- 来源策略：优先可公开复查的公共机构/供水系统技术资料与同行评审工程研究；只搜索与泵送依赖、电力中断和供水连续性直接相关的材料。真实系统资料用于支持或反驳现实机制候选，不直接确立合成聚落事实。
- 试跑专用工作量边界：1 个 research question、最多 5 个定向查询变体、最多查看 6 份来源、计划总量 45 分钟，并在查看前三份来源后作一次继续/停止回看。若执行环境不能可靠按墙钟计时，保留 45 分钟作为计划边界，并以查询数、来源数、检查点和停止理由作为可复核预算。上限不是充分性规则；更早满足用途标准可停止，耗尽上限而证据不足则按 partial/insufficient 或 conflicting 结束，不扩成风险大全。

## 5. 调用与 S1 回流路径

1. 在单独获准的 S1 集成候选中指出局部未知及其对当前问题结构可能造成的影响，按 S1 adapter 映射到共同 schema。
2. Shared Core 运行有界研究闭环：识别未知类型/owner、确认外部研究适配性、实施来源策略、逐 claim 评价、说明迁移与限制、综合并登记剩余未知。
3. Adapter 将带来源、评价、迁移条件、AI 推论与目标待验证内容的候选包交回集成版 S1 host 中对应的局部问题。
4. S1 按原方法分别运行 Rule E（候选结构准入）、Rule F（未知归属与下一状态）、Rule G（coverage、收束、残余与范围）；核心或来源权威性不得替代任何一条规则。
5. 局部研究不自动重启顶层 coverage。只有符合 S1 现有回流条件的具体证据才可要求更大范围复查。

## 6. 观察指标、停止与失败处理

记录并评估：

- 四元组件身份、host 状态、调用触发、原未知、研究问题、用途标准、来源策略和工作量上限是否可复查；
- 每项结论能否追到 claim、source locator、支持内容、质量判断、限制与迁移理由；
- 类比/间接资料是否被明确限定为机制参考，是否出现将其误写为合成目标的直接证据；
- 返回的候选是否由 Rule E/F/G 各自处理，是否有证据支持范围变化；
- 结局、停止原因、剩余未知 owner 与下一动作是否相符。

达到用途标准且没有未处理的高影响证据冲突时可停止并回交。若到达预算上限、来源不可得、关键冲突未解、未知实际属于创作者取舍或目标内部事实无法靠外部研究确定，则如实使用 schema 对应结局并保留剩余未知；不得把“本轮未找到”写成“不存在”。若问题展开为多个独立研究问题，则记录 residual 并停止，不自动发起第二次调用。

以下属于**试跑失败或契约缺口**，不是资料不足：来源无法复查却被作为证据；发生迁移但边界丢失；taxonomy 未经 Rule E 进入结构；Core 越权代替创作者或 S1 裁决；未知失去 owner；或者只有改动冻结组件才能继续。出现时保存记录、停止受影响步骤，区分执行偏差、组件缺口或 host 不匹配；不得在本轮临时修改 core/schema/adapter 后继续。

`evidence_role` 只作为观察项：以当前 `support`、`limits_and_conditions` 与适用性/迁移字段记录证据直接支持范围。若实跑发生“间接/类比资料被当作直接证据”，保留原始记录并在试后评审中考虑扩展字段；试跑期间不加字段、不改变 schema 基线。

## 7. 必须另行放行的事项与不验证事项

本设计获创作者接受后，仍不自动授权 host 编辑或研究调用执行。运行前须另行裁定：

1. 是否授权从 v0.16.1 派生并编辑一个窄 S1 host 集成候选、接受其正式版本号与具体插入点；
2. 是否接受上述合成案例、有界 research question、来源策略与工作量上限；
3. 是否启动一次调用及 Rule E/F/G 回流，并在试后由创作者判断证据与候选处理。

本次不验证：S1 全局 coverage 穷尽、semantic zoom、GOAL-004 案例结构、handoff-ready 普遍判据、目标世界客观事实、S2 模型构建、跨案例迁移或最终方法有效性。试跑结果不得回写/重判 Probe 1、run-10 或 GOAL-004 的案例结论。
