# S1 run-02 回流候选协调与 Rule F.2 求解项

> 本文记录 D-016 授权的局部候选协调，并由创作者按 D-017 接受两项候选的当前粒度。它不修改或替代 [run-02 原始记录](s1-independent-call-trial-run-02.md) 与 [A-003](../03-audit/A-003-run02-trial-record-review.md)。run-02 已被接受为有效、相对干净的有界 S1 行为样本；A-003 的两项 MINOR 注意项原样保留。候选接受不等于目标事实确认、一般方法基线接受或总体 S1→S2 handoff 通过。

## 1. 本地候选协调

只处理 run-02 §6 已有的四项，不作其他问题搜索：

| run-02 条目 | 协调结果 | 状态 |
|---|---|---|
| 1. 供水路径、设施状态或故障范围是否按住户区域不同 | 与条目 2 合为一个 B3-1 | 创作者接受并保留当前粒度（D-017） |
| 2. 泵站、处理或供电依赖是否存在差异 | 并入条目 1 的供水路径/设施/故障范围问题；作为相关系统中实际存在时的依赖状态与时序，不另立节点 | 创作者接受合并后的 B3-1（D-017） |
| 3. 若“送达”包含应急或非管网配送，运输/分发安排是否造成覆盖差异 | 保留为独立条件性 B3-2；其所求首先包括核实事件期间是否实际使用 emergency 或 non-piped delivery，再按答案进入适用或不适用分支 | 创作者接受并保留当前条件粒度；适用性未知（D-017） |
| 4. 住户既有储水是否解释仍可取水 | 不准入为当前 B3；保留为未知 residual | 不等同于确认存在或不存在 |

条目 1 与 2 的材料可以共同回答服务路径、设施状态和事件故障范围；run-02/A-003 未显示条目 2 有独立、不可替代的求解贡献，故将二者合并。不构造父子层级，也不把泵、处理或电力依赖写成目标系统事实；仅当目标侧材料证实相应组件属于实际服务链时才调查其状态。

条目 3 的独特贡献是**交付/物流/分发点至住户的覆盖与时序**，不重复普通设施运行。run-02 只说明饮用水送达住户且同一服务中断期间住户结果不同，没有确认应急或非管网交付。这个未知适用条件由该 B3 的首项求解本身核实：答案若确认事件中实际使用 emergency 或 non-piped delivery，则继续调查其覆盖与时序；若证据确认未使用，则该机制分支不适用。当前信息不足既不证明交付发生，也不证明其不存在。

## 2. B3-1 · 服务路径、设施状态与故障范围

**来源候选：** run-02 §6 条目 1 + 条目 2；证据线索见 run-02 §3 的 C-01（配水系统组件）、C-02（失压原因与隔离范围）、C-03（某些系统的泵送/供电依赖）。

1. **所求（sought）**：针对此次服务中断，查明受影响与仍能取水的住户/去标识服务点分别经由哪些实际服务路径连接到相关供水设施；在记录所覆盖的事件时点，各路径上的相关设施、故障/隔离范围及运行状态是什么；并说明路径、区域或设施状态是否与住户端结果差异相对应。泵送、处理、电力/备用供电只在目标侧材料证实其属于实际服务链时纳入。
2. **答案形式与有依据的精度（answer form and justified precision）**：以可追溯的关系表或路径图呈现“住户/服务点组—实际路径—相关设施/组件—事件时点状态—可见服务结果”，并分别标记已知、未知及来源。精度限于系统图、运维/故障/隔离日志与供水记录本身的空间和时间粒度；只有这些记录实际包含时才报告具体区域、时间点或设备状态。没有数据支持时不提供精确水压/流量、分钟级时点、概率或单一因果归因；记录缺口标为未知。
3. **证据支持的分支影响（branch impact）**：**branch awaits S2 / target-side investigation**。C-01～C-03 支持一般候选机制及可调查维度，但没有一项证据证明目标社区存在某条管网、特定设施/依赖、失压或隔离事件，也没有目标侧数据可选择哪个机制分支。需由目标侧系统调查/建模方核对系统图、服务连接、事件时序、设施状态与故障记录后，才能判断是否有路径/区域/设施状态分支及其后续影响。
4. **来源与为何 S1 不能回答（origin / why S1 cannot answer）**：候选源于 run-02 的同一事件住户结果差异锚点及 C-01～C-03 的一般 EPA 技术资料；参见 [run-02 研究记录 §1、§3、§4](s1-independent-call-trial-run-02.md)。S1 外部研究只能提供一般机制和调查建议，不能获知目标社区的拓扑、住户连接、实际服务模式、故障位置/原因/范围或事件时序。run-02 已明确目标事实 owner 为目标系统调查/建模方；本 B3 所需答案须来自该方可核对的系统图、运行与事件记录。

**Rule F.3 归属/下一状态：**B3 客观求解型；owner 为目标供水系统调查/建模方；下一阶段状态为「作为 S2 求解项，答案待系统图与事件记录调查」，在数据覆盖不到处继续标记未知。

## 3. 条件性 B3-2 · 应急/非管网交付的物流覆盖与时序

**来源候选：** run-02 §6 条目 3；证据线索见 run-02 §3 的 C-04（应急供水规划选项及交付安排）。

1. **所求（sought）**：首先确认此次中断期间是否实际使用 emergency 或 non-piped delivery。仅在确认使用后，查明替代供水来源/运输安排/分发点如何连接到住户，分发位置与服务时段如何安排，以及哪些住户/去标识服务点在何时被覆盖或实际收到供水；判断这些交付差异能否解释住户端结果差异。
2. **答案形式与有依据的精度（answer form and justified precision）**：先给出“已确认使用 / 未确认 / 证据冲突或不足”及依据；不得从“饮用水送达住户”的案例措辞推定为应急或非管网交付。若证实适用，用来源、运输批次/路线、分发点、开放时段、可服务区域与收/未收记录的关系表呈现覆盖和时序。地点与时间精度不得超过调度、分发和住户接收记录实际粒度；无完整登记时不报精确覆盖率或完整名单，不把计划安排当作实际交付。
3. **证据支持的分支影响（branch impact）**：**branch awaits S2 / target-side investigation**。C-04 只证明应急规划资料包含多种来源和交付类别，不证明目标社区采用其中任何类别。目标侧先核实实际服务模式；若确认 emergency 或 non-piped delivery 在用，则交付/物流/分发点至住户的覆盖及时序是区别于普通设施运行的独立候选分支；若证据确认未使用，则该机制分支不适用。该适用性检查属于所求，不是采纳前提；当前未知不等于不存在。
4. **来源与为何 S1 不能回答（origin / why S1 cannot answer）**：候选源于 run-02 C-04 与案例中饮用水送达、住户结果不同的有限锚点；参见 [run-02 研究记录 §1、§3、§4](s1-independent-call-trial-run-02.md)。应急规划模板只能提供一般规划类别，不能识别本次交付模式、实际来源、运输/分发点、时段或住户覆盖。上述事实须由目标侧社区供水/应急交付调查方以当地调度、配送及接收记录确认；S1 不能替代该调查。

**Rule F.3 归属/下一状态：**B3 客观求解型；owner 为目标社区供水/应急交付调查方；下一阶段先核实本次事件的应急/非管网交付适用性，答案待目标侧记录调查。若证实适用，再调查交付覆盖与时序；若证实不适用，以该证据停止本条件分支。

## 4. 未准入 residual · 住户储水

run-02 §6 条目 4 仍不准入为 B3。C-01 对应的是系统层面的储水设施，不能支持 household storage；两份 WHO PDF 在 run-02 中不可访问，未读正文，也没有用于支持任何主张。现无目标侧住户储水或取水时点证据。故 household storage 保持**未知且未准入**，不得与系统储水合并，也不得把资料缺失解释为不存在。若新输入或目标侧材料提供正向锚点，再重新评估其是否增加不可替代的求解依赖。

## 5. Rule G 本地边界与交接就绪度

本协调只检查 run-02 已生成的四项候选、上述重复关系、条件适用性与 household-storage residual。创作者已按 D-017 接受 B3-1、B3-2 并保留当前粒度；这确认两个局部求解项的结构，不确认任何目标事实，也不等于完整问题图收束。**没有**进行全局 coverage search、全局 closure，也没有声明总体 S1-to-S2 handoff-ready 或冻结唯一问题集。候选仍受供水模式未明、目标侧系统/事件/交付记录缺失及来源机构集中于 EPA 等限制；未发现资料不构成不存在证明。

创作者已对 B3-1 和 B3-2 分别选择**接受并保留当前粒度**（D-017）。B3-2 的 emergency/non-piped delivery 适用性仍由其 F.2 求解项调查，不预设为真。两项 B3 现有明确求解任务、答案形式/可达精度、阶段二待调查的分支影响、事实 owner 与下一状态，可作为**局部、内容完整的 S2 求解项**；但候选接受不替代 Rule G 对完整问题集的充分性/收束判断。因此，此处结论限于「两个局部 B3 求解项内容就绪」；**整体 S1→S2 handoff-ready 未建立**。D-016 接受的是 run-02 样本并授权本次材料整理；D-017 接受的是这两个 run-02 局部候选的结构与粒度。GOAL-004 Probe 1、父层结构确认、S2 调用、第三次试跑、Core/Schema/adapter/host 修改均不在本记录范围内。
