# S1 Research Adapter · 候选 v0.1.1

> 本 adapter 是 S1 对 [shared core v0.1.0](shared-research-loop-core-v0.1.0.md) 的窄调用/回流契约。共享研究语义和记录字段分别由 [core](shared-research-loop-core-v0.1.0.md) 与 [schema](shared-research-record-schema-v0.1.0.md) 唯一维护；本文件不复制来源评价、迁移、综合或停止规则，也不修改现行 S1 方法版本。v0.1.1 由既有 v0.1.0 候选派生，只澄清外部研究支持条件问题相关性的 Rule E 回流资料；v0.1.0 保持原样。v0.1.1 不修改 core/schema、Rule F/G 或现有 S1 host。对应的 S1 host 修订候选为 [v0.16.3](../../GOAL-004-collaborative-question-framing/attachments/stage1-framing-method-candidate-v0.16.3.md)；两者仍为 draft/unaccepted，不改变既有 host 或运行记录。

## 1. 调用条件

当 S1 正在分析的问题结构时，一个明确未知可能改变候选问题/解释、关系/依赖、反例、边界或局部/全局影响，并且相关外部资料可能提供有用依据时，可调用 shared core。

若未知属于创作者偏好/取舍，adapter 将研究回到“提供选项与后果依据”的位置，不让 core 替创作者选。若只是当前前提上的推理缺口，先继续推理；若答案只能由目标世界内部求解或观测得到，外部研究只能提供机制/模型参考并须明确标记其迁移限制。

外部资料支持的机制可以与一个**明确的当前输入锚点**及其间的显式推理共同支持“某个条件问题与当前任务相关”，但这条关联不证明该条件在目标世界为真。候选能否进入 S1 结构仍须交由 host 既有 Rule E：至少指出输入锚点、来源支持的机制及二者之间的关联推理，并说明纳入该**待答条件问题**会改变必要问题结构或求解依赖；仅可能改变最终答案不足以准入。被输入否定、冗余或已有节点承载的候选应排除。通过准入时明确记为“问题纳入、答案未定”；目标世界中的条件真值保持未知，并由现有 Rule F 确定归属与 owner。

## 2. 最小输入映射

调用时向 core 提供或引用：

- 当前 S1 原问及受影响的局部节点/结构位置；
- 调用时已经存在的当前输入锚点（如有）及其位置；
- 未知的已知/假设/推论状态、信息 owner 与裁定权；
- 未知可能影响的问题结构/关系、反例、边界或下一步；
- 本轮研究问题、用途下的充分标准，以及调用时已经可用的既有证据（如有）；
- 可用的对象/时期/版本边界和任何不能假定的内容。

上述是调用前可提供的已知信息。不得要求调用输入预先包含本轮研究执行或回流后才可能产生的具体条件候选、来源支持机制或机制与输入锚点之间的关联推理。Adapter 只做 S1 输入到共用 schema 的映射。进入条件、来源策略、证据评价、有界停止和剩余未知依 [core](shared-research-loop-core-v0.1.0.md) 处理。

## 3. 回流位置

Core 输出作为带出处、证据评价、迁移限制、推论标记和剩余未知的候选包回到 S1 当前原问及其局部结构。后续只进入已有规则：

1. **Rule E**：判断候选是否达到入结构门槛。来源或行业 taxonomy 出现本身不构成准入；反例的前提也须与当前目标相关。条件问题候选须回交当前输入锚点、来源支持的机制与显式关联推理、纳入待答问题后的必要结构贡献、尚未证明的目标世界事实，以及输入否定/冗余/已有节点承载的检查结果。该证据只可支持条件问题的相关性，不证明目标条件为真；必要结构或求解依赖未改变时，不能仅以“可能改变最终答案”准入。
2. **Rule F**：为已讨论的未知确定归属、owner 与下一步状态。若条件问题准入，明确留痕“问题纳入、答案未定”；目标条件真值仍未知，按现有 Rule F 确定其 owner。
3. **Rule G**：判断对 coverage、收束、残余及局部/全局范围的影响。局部研究不自动重启全局 coverage；只有具体证据依现有规则改变全局所求、必要结构或收束条件时才回流更大范围。

Core 的研究结局不等同于 S1 问题成立、候选准入、coverage 完成或 handoff-ready。所有这些判断仍由 S1 原有规则和创作者协作权责作出。

## 4. 留痕与组件身份

调用记录标明实际 core、schema、S1 adapter 与 S1 host 修订身份，并按共享 schema 保存调用时已知的研究任务、研究返回及 Rule E/F/G 的 host 处理。仅在研究返回后形成条件问题候选时，才记录该候选及其准入依据；不得将这些研究生成的回流结果倒置为调用前置输入。回流记录使用 schema 既有字段，不增设字段：用 `host_return` 记录候选问题与受影响的判断链；用 `target_and_impact` / `host_return` 记录调用时输入锚点和纳入候选后的必要结构贡献；用 `claim`、`source_statements`、`support` 记录来源支持的机制；用 `ai_inferences` 记录机制与输入锚点的显式关联推理及其依据/不确定性；用 `target_hypotheses` / `residual_unknown` 记录未证明的目标事实；由 host 在 `host_disposition` 记录输入已否定、冗余或已有节点承载的排除检查及 Rule E/F/G 裁决。准入时明确记录“问题纳入、答案未定”；目标条件真值仍未知，由现有 Rule F 确定 owner。S1 host 与 adapter 均为候选的试跑调用，不把 adapter 的资料包本身视为准入或答案裁决。
