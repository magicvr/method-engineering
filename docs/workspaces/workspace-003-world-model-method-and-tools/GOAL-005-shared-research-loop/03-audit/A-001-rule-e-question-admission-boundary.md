# A-001 · 独立审查 Rule E 候选问题准入与目标事实边界（2026-09-28）

- **source**：independent
- **auditor**：Codex REVIEWER subagent（gpt-6-sol，medium）
- **类型 / scope**：ad-hoc；GOAL-005 的 S1 Rule E 候选问题准入与目标事实成立边界；核对 shared core/schema/S1 adapter v0.1.0、GOAL-004 S1 host v0.16.2 Rule E/F/G 与 run-01。只读；未修改组件或方法，未重跑研究调用。
- **verdict**：conditional

## 范围与区间

工作区上下文与 canonical root 已校验；本意见仅涉及 S1 研究证据回流时，候选问题的相关性依据与目标条件真值之间的界面。不评定 run-01 全部候选是否应准入，不判定 S1 方法已验证，也不涉及 S2 求解。共享资料目录为 `none`；本次不引用仓库共享资料。

## 成果（有证据）

- Core 已将来源陈述、AI 推论、目标对象待验证主张与宿主裁决分开；`sufficient-for-next-step` 不等同宿主准入或问题解决（Core §§7–9）。
- Schema 已能记录迁移、`target_hypotheses` 与 `host_disposition`；没有证据表明需要扩充共享记录结构。
- S1 Adapter §3 将 Core 输出交回既有 Rule E/F/G，但没有明确要求把“输入锚点—研究机制—关联推理—结构贡献—尚未证明的目标事实”分别呈现给 Rule E。
- Rule E 同时允许由输入可推且具有推理链的候选进入结构，并把其他世界/作品的惯例限于候选池；规则 G.4.2 另承认当前案例内反例差异可成为新分析依据并重新过 E。
- run-01 §6 以目标配置/阈值未给定为由，将整组机制条件留在候选池，并要求后续出现具体案例输入或 Rule G 分析依据后才重过 E。D-012 已接受 run-01 为有效取证样本及 Core outcome，但未整体接受 E/F/G 回流，也未裁定候选准入边界。

## Findings（F-001；required；major）

**现行 Rule E 与 S1 Adapter 对外部研究如何支持“待答条件问题”的相关性依据存在执行歧义。** 可以把当前合同解释为允许“输入锚点 + 外部机制证据 + 显式推理”支持一个条件问题进入 S1 结构，同时不把条件认定为目标事实；但现有文字没有稳定要求这种区分。run-01 的处理把“目标配置未证明”与“条件问题没有当前结构相关性依据”合并，因此同类候选可能被相反方式处理。

**Why it matters：** 若不澄清而直接进行清洁盲试，结构准入结果仍可能反映 Rule E 的两种解释，而无法区分机制发现能力与准入门槛差异。

**建议闭合：** 仅对 Rule E 与 S1 Adapter 做最小解释澄清；保持 Core 与共享 Schema 不变。准入条件至少应要求：当前问题锚点清楚；外部资料支持的机制与锚点之间有显式推理；纳入该待答条件问题会改变必要问题结构或依赖；检查现有节点是否已经承载该条件、并排除冗余或输入已否定内容。只因某条件可能改变最终答案，不足以单独准入。记录中须明确“问题纳入、答案未定”，不得将它写成目标条件为真；后续由 Rule F 归属 B1/B2/B3。逐项候选仍须按规则判断，本 finding 不接纳 run-01 的全部候选。
