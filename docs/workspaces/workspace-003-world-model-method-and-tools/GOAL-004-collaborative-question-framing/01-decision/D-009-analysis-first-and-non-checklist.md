# D-009 · 按创作者试跑裁定收紧回问条件并禁止操作打卡

## 裁定来源

2026-09-27 创作者对第一例 v0.6.0 隔离试跑（[运行 01](../attachments/probe-01-stage1-test-v0.6-run-01.md)）给出判定：**本次试跑未通过**。失败不在节点或关系的正确性，而在 **premature elicitation**——助手识别出「世界」的指称与「有多大」的答案形式存在语义开放性后，没有继续执行有界的候选解释、比较与结构发现，而是把定义这些词的任务重新交回创作者。阶段一的目的正是帮助处理这种模糊输入；**发现歧义只说明需要继续分析，不自动构成回问条件**。

## 修订要求（创作者原意，作为 v0.7 的验收口径）

1. **先分析、后回问**：对合理可分析的歧义，先主动生成并比较候选解释，再考虑是否需要创作者输入。
2. **多个解释默认可暂时并存**：不因尚未选定唯一含义而停止推进。
3. **参数未定但可变量化时继续推理**：能把未定参数当变量继续结构发现，就继续，而不是转为等创作者给定值。
4. **回问条件收紧**：只有当剩余差异构成不可由分析消除的创作者取舍，**且**确实会改变回答要求时，才请求创作者裁定。
5. **「发现一个可以问用户的问题」不构成阶段一分析已够用的理由**。
6. **禁止操作打卡**：认知操作应由当前认知困难触发，而不是为了证明方法被执行而逐项遍历；须检查操作清单是否正在退化为隐式流程。

## 处置

- v0.6.1 原文与本次运行记录保留为历史；形成 [v0.7 候选](../attachments/stage1-dynamic-relation-graph-candidate-v0.7.md)，把上述六项要求落进方法正文、回问条件与操作触发纪律（不是加一句声明）：
  - 新增「歧义处理：先分析、后回问」节（候选解释集 → 并列比较 → 并存推进 → 未定参数变量化 → 三条件回问）；
  - 操作表补入「并列解释与比较」，并新增「操作触发纪律」（未触发如实标注、不得补造实例、证据记结构变化而非完成度）；
  - 风险约束表补入「过早回问」「操作打卡」两行；
  - 收束节的「够用判断」明确不以「有问题要问」为依据。
- 本裁定**不接受** v0.6 / v0.7 任何候选为已接受方法；`I-401` 仍 `open`（实际创作场景与所需剧情/设计判断仍未共同明确），`I-402` 仍 `collecting`（第二个不同案例未选定）。
