# D-010 · 纠正认知操作退化为 elicitation 的结构性缺陷

## 裁定来源

2026-09-27 创作者指出：**当前首先要解决的是认知操作被退化成 elicitation（向用户索取定义）**。这是 [D-009](D-009-analysis-first-and-non-checklist.md) / v0.7 未覆盖的问题——v0.7 只是给「索要」加了门槛（三条回问条件），而**操作本身仍以「未定项」为终点**，因此退化随时会以合规形式复现。

## 诊断（为什么会退化）

| 环节 | 机制 |
|------|------|
| 未定项的出路 | 图中的「未定」被当作待填字段，只有创作者能赋值 → 每次识别歧义都导向一次索要 |
| 操作定义 | 只写「做什么动作」，不写「动作完成后结构里必须多出什么」→ 无法产出结构时，「提出问题」成为动作完成的替代品 |
| 收束判据 | 把「已能提出待创作者裁定的问题」当作阶段一完成态 → 识别歧义越多越早收束，停止分析的激励与产生问题的激励同向 |

第一例 v0.6.0 运行即此形态：八项操作执行完毕后，产出物是两个「请创作者补定义」的提示与一个用途选择提示，没有候选解释及其后果对照。

## 决定（三条对治规则 + 操作定义改造）

1. **规则 A · 产出物规则**：每项操作的产出必须是作用于当前结构的分析产物；**只能产出提问 = 该操作未执行**，不得记入方法表现证据或作为收束理由。
2. **规则 B · 未定项处理次序**：未定项在被提交给创作者前必须走完——解释候选化 → 后果推导 → 可判别性检查（含按需的资料/既有知识检索）→ 变量化继续。
3. **规则 C · 回问条件（末位手段）**：三条同时成立（分析无法消除 / 确实改变回答要求 / 属创作者取舍），且回问必须携带候选、后果对照、已排除项与最小可纠正选项。
4. **操作表改造**：每行给出「触发困难」与「完成后必须出现的产物」两列；触发纪律明确证据口径排除「执行了几项」与「提出了几个待确认问题」。
5. **新增出口退回检查**：收束前逐项审查每个待裁定项是否本可由分析推进；只要求创作者定义词项或给参数值者 → 阶段一未完成，退回分析。

## 未选方案

- **只继续收紧回问条件（v0.7 路线）**：不改变操作终点，退化会以合规形式复现；未选。
- **取消一切回问**：会丢失确属创作者取舍的必要输入，并与 D-002 / D-008 的协作位与两阶段结构冲突；未选。
- **为歧义处理另立子目标**：范围不足以独立交付，且会再次把工作拆成表单；未选。

## 处置与边界

- 形成 [v0.8 候选](../attachments/stage1-dynamic-relation-graph-candidate-v0.8.md)；v0.7 标记为被取代，历史保留。
- **不改变**阶段二边界、两阶段与有条件回流（D-002 / D-008 继续有效）；**不把**资料检索设为无条件义务——仅当歧义可能由上下文外知识消除时执行，结论记入可判别性检查。
- 本轮不运行新探针、不改目标 `status` / `progress`；`I-401` 仍 `open`、`I-402` 仍 `collecting`。事实见 [E-017](../02-execution/E-017-cognitive-ops-anti-elicitation-revision.md)。
