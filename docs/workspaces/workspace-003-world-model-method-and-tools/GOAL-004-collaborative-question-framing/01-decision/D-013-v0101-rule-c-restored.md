# D-013 · 补回 v0.10 缺失的规则 C 并形成 v0.10.1

## 来源

run-03 的隔离执行者在**只读 v0.10** 时报告：规则 C 被正文引用至少 3 处（规则 B 的 N4 行、出口退回检查第 2/3 条、风险表「规则 A/B/C」），但全文未载明其内容。编排器核对**属实**——v0.10 中「规则 C」出现 6 处，而 `## 规则` 定义节只有 A / E / B / D 四节。这是编排器在重排规则编号（A/E/B/D）时的**写入缺陷**，不是执行者的理解问题。

## 决定

1. **不原地修改 v0.10**：它已作为 run-03 的实测基线按 `sha256 8E30DA2F…B2B18B`（21,692 B）指纹固定，改它会使运行记录不可复核。
2. **另出 [v0.10.1](../attachments/stage1-framing-method-candidate-v0.10.1.md)**：补回规则 C（内容沿用 v0.9 的规则 C 并适配本版编号——三条同时成立的回问条件、回问须携带分析、客观争议不回问；另加「**回问是末位手段**：规则 E 与规则 B 已处理的内容不得上浮为回问项」）。其余内容与 v0.10 相同，并在文首标注修正说明与旧基线指纹。
3. **run-03 的证据地位留待创作者裁定**（编排器不代裁）：本轮的方法行为证据（门槛/假定/层级三项检查通过、「未触发」首次出现、回问项 0）建立在缺少一节的基线上。编排器的**建议**是：该缺口涉及的恰是回问条件，而本轮回问项为 0、执行者亦未据以回问，故可采信为**局部方法行为证据**；但不得据此判 v0.10 通过，是否需要在 v0.10.1 上重跑由创作者决定。
4. **执行者提出的两项待确认保持待决**（V2 维度收窄；若 L2 交付方式取「须数值」则回流使 D1 升级为强依赖）——属创作者裁决点，编排器不代裁。
5. **未处理项不变**：触发可判别性缺陷（全局「真触发 vs 清单遍历」无外部判据，本轮执行者亦声明未声称通过）；L1/L2 分层对父级 W2/W3 的潜在影响仍待父级按 P-006 处理。

## 未选方案

- **原地补写 v0.10**：破坏实测基线指纹，使运行记录无法复核；未选。
- **直接重跑以掩盖缺口**：缺口已定位且可修补，重跑不增加信息；未选（若创作者要求重跑，则在 v0.10.1 上跑）。
- **把缺口当作执行者理解偏差**：证据不支持（引用在文件内，定义确实缺失）；未选。

## 处置与边界

- 本修正只补**编排器自身遗漏的方法文本**，不改变 v0.10 的任何规则内容与 run-03 的实测基线。
- 本轮不新建子目标、不改目标 `status` / `progress`；`I-401` 仍 `open`、`I-402` 仍 `collecting`。事实见 [E-021](../02-execution/E-021-probe01-v010-run03.md)。
