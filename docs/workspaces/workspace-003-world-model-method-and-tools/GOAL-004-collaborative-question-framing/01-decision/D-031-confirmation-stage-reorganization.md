# D-031 · 确认阶段反馈：候选结构需重新组织（区分覆盖维度与横切条件），先做一次有界重组

## 来源

创作者对 [阶段一呈示 01](../attachments/case-structure-presentation-01.md) 的校准：**暂不确认**当前候选问题结构——**不是因为其中各项明显错误**，而是因为**当前组织方式没有准确贴合其对阶段一产物的理解**。

## 反馈（结构组织问题）

1. **当前结构混合了两类不同性质的问题**：
   - **(1) 覆盖维度**＝「世界究竟在哪些**相互独立、可并存**的方面有多大」。现有明确出现的是**空间延展**与**体量／内容规模**；**创作者没有把握这已经足够**——并指出：**「实例可以被立即想到」这件事本身，就意味着仍需要方法协助发现他没能立即想到的合理维度**。
   - **(2) 横切结构／度量条件**＝回答**任一**规模维度时都需要处理的**定义／度量／答案形态**条件（尺度是否有定义、是否有边界、尺度结构、是否唯一确定、答案是否需要条件化）。它们**可能完全必要**，但**不一定应与覆盖维度作为同层的问题项平铺**。
2. **Q4（认知／可达限制）需要重新判断**：它究竟是「**世界规模本身的一个覆盖维度**」，还是「**世界规模与主体之间的关系问题**」——**不得仅因覆盖攻击发现了它，就默认它与规模维度同层**。

## 指令（有界动作）

- **不删除**已有发现；**不重新无限执行 coverage attack**。
- **先仅对现有候选结构做一次重新组织**：
  1. **区分**「原问需要回答的**覆盖维度**」与「**跨维度适用的定义／度量／答案形态条件**」；
  2. **标明 Q1–Q5 分别属于哪一种**；**允许某项被重写为横切约束，而不是独立覆盖问题**；
  3. **保留**「**覆盖维度尚未穷尽**」的声明；
  4. **不把任何具体实例写成固定 taxonomy**（含上级举出的实例）——实例**不得**变成预设清单；
  5. **重组后再次呈示**，供创作者判断：「**如果阶段二把这些覆盖维度逐一解决，是否真的会让我觉得『世界有多大』得到了充分回答**」。

## 状态（明确）

- **run-10 的方法运行与第三态判定成立**；
- **创作者尚未确认其案例结构**；
- 本反馈属**确认阶段发现的结构组织问题**，**不是撤销 run-10 的运行判定**。
