# D-018 · 文本一致性小修并冻结 v0.12.1（run-06 基线）

## 来源

2026-09-27 创作者**接受 v0.12 的修复方向**——规则 F 由「变量是否阻断」改为「未决项的 resolution owner / 阶段归属」，B1／B2／B3 与新的交接门禁符合预期——并要求试跑前做下列**文本一致性小修**，且明确「**完成后冻结版本并继续试跑，不再扩写方法**」。

## 决定

1. **规则 B 的 N2 行**改引 **B1／B2／B3 未决项归属**（不再引旧的「暂时／非阻断／阻断」变量分级），必须产物改为「类别（B1／B2／B3）与 resolution owner / 下一阶段状态」。
2. **规则 E** 的 (a)(b)(c) **只作后果/结构影响记录**，不再称「规则 F 的分类判据」。
3. **文末版本状态**同步为当前规则 F，并去掉「M1／M2 仍待修」等旧说明（文首 v0.11／v0.11.1 修订说明中的旧术语**保留为历史**）。
4. **弱化 B3 的分支要求**：F.2 只需记录**当前有依据可知的**分支影响；**若答案空间本身需要阶段二才能发现，就明确标记「分支待阶段二发现」，不得为满足格式制造 A／B／C 分支**。同时把**精度**区分为两种——**创作者要求的精度**属 **B1**（另立 B1 项）、**世界客观可实现的精度**属 **B3**（由阶段二判定世界本身支持何种精度）。
5. **出口退回检查第 7 条**与**后续检验观察项**同步该弱化表述（检查 B3 是否记录了有依据的分支影响、或在未知时明确标记「分支待阶段二发现」）。
6. **本版冻结**为 run-06 的固定基线（跑前不再改动）；**不再扩写方法**（创作者明确要求）。

## 未选方案

- **保留旧术语只加注解**：同一文件内会并存两套术语，下一轮运行仍会报告同一处不一致；未选。
- **把「分支路由」降为纯可选要素、不区分「有依据／待发现」**：无法防止为满足格式硬凑分支；未选。
- **把世界客观可实现精度并入 B1**：会把世界事实问题错当创作者取舍（正是 run-05 死循环的同类混淆）；未选。

## 处置与边界

- 形成 [v0.12.1 候选](../attachments/stage1-framing-method-candidate-v0.12.1.md)：指纹 `sha256 5F303BEB9147EE25A55B1369C7EAA7D785CC3DF20F84E3EDD0CD31048885EE1F`（34,157 B，175 行）；**v0.12 原文保留不改写**。
- 本版**只做文本一致性修正**，不改变任何规则的实质口径。
- 不新建子目标、不改目标 `status` / `progress`；`I-401` 仍 `open`、`I-402` 仍 `collecting`。事实见 [E-027](../02-execution/E-027-v0121-freeze-run06.md)。
