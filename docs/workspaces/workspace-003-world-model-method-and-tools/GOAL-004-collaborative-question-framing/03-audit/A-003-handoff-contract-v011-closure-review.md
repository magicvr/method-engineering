## 对照 A-002 约束

### F-001（required／high）——文本已满足

| A-002 约束 | v0.1.1 落点 |
|------------|-------------|
| 父层整体确认只打开该已确认范围的整体交接 | §1：「才可将该已确认范围整体交给 S2。整体确认只开启这一整体交接范围。」 |
| 节点级交接另需已接受的方法／host 明文允许拆分，并附该方法要求的局部覆盖收束证据 | §1 三项同时成立之第 1、2 项；§3 对未来方法重复同一组条件 |
| 父层确认本身不充当这项方法依据 | §1：「父层确认本身不能替代上述任何局部门禁」「不得以父层整体确认作为缺少这些门禁时的替代出口。」§3 再次写明父层整体确认不替代局部门禁，也不构成替代出口 |
| ①-b／B3-b-01 在整体确认后随整体移交；本合同不授权单独交给 S2 | §1：「即便将来父层整体确认，①-b／B3-b-01 也须随整体结构交给 W2；本合同不授权将其单独交给 S2。」 |
| v0.16.1 与 v0.16.2 没有已接受的局部递归／节点拆分门禁；在带有该门禁的方法被接受之前，节点级路径关闭 | §1 与 §3 都写明这两版没有此类门禁，因此当前节点级路径关闭。§4 写明 v0.16.2 的 host 身份不授予 split gate |

原缺陷是「等父层确认」可以被读成节点级出门。该读法所依赖的句子不在 v0.1.1 的规范条款里。父层确认与节点级门禁分成两套，缺门禁时没有替代出口。

### F-002（required／high）——文本已满足

| A-002 约束 | v0.1.1 落点 |
|------------|-------------|
| hold 限于已经改变所求、必要问题结构或未决归属／下一阶段状态的事项，以及影响判不清的事项 | §2：有证据表明范围外事项已改变这四项时 hold；是否存在这些影响判不清时先 hold。§3 对交接后的证据使用同一谓词 |
| 已写明范围、为何暂不阻断和回流 trigger 的残余，不单独阻断 | §2：trigger 说明何种未来证据出现后回流，不把未来 trigger 可能发生写成当前阻断理由。§3：「已完整登记 Rule G residual（范围、当前为何不阻断、回流 trigger）不得仅因未来 trigger 可能发生而阻断。」证据出现后再按其实际影响处理 |
| 未完成且仍由 S1 持有的节点不得作为可执行求解项，并与 non-blocking residual 分开登记 | §3：`S1-held context` 可作说明性上下文，其自身不得作为可执行 S2 求解项；与完整登记的 `non-blocking residual` 分开记录，不能相互替代。标记本身也不给兄弟节点授权 |

「可能改变边界则 hold」不在 v0.1.1 的规范条款里。R-1 这类已登记、且只带未来回流条件的残余，不再因「可能发生」被整段 hold。
