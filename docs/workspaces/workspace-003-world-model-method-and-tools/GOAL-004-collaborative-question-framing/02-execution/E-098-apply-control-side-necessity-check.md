# E-098 · 应用 necessity check 并修正 run-14 后续判断边界

## 已完成事实

创作者要求对后续控制侧的“必须 X，所以……”判断增加 necessity check，并明确 run-14 的 N/O 解释边界。按该指示形成 [D-059](../01-decision/D-059-control-side-necessity-check.md)。

依 D-059 修正 [run-14 disposition matrix](../attachments/run-14-demand-preservation-disposition-and-evidence-matrix.md) 和本执行记录中的下一步表述：run-14 的 `not observed / inconclusive` 仅表示预定的 research-return 观察现象未发生，不是 S1 漏做必要步骤或方法失败；run-13 的 research 运行仅证明该路径曾实际发生，不将其提升为必经路径。

## 当前边界

- 不创建“更容易触发 research”的 Probe，不把研究触发率设为 runner 目标。
- 若未来仍需判断某个问题是否依赖 S1-level research，先根据当前目标和 S1 Research Adapter 明确该知识为何会改变必要问题结构/条件角色/对象边界；之后再判断是否需要 Probe。即使设计，research 仍按方法条件触发。
- 此前“植物能学习吗？”和“病毒算生命吗？”两项首轮建议按创作者修正的筛选标准撤回，未选定、未形成 runner 输入；后续控制侧也不采用仅为了提高 research 触发概率而提出的候选。
- run-14 outcome、binding SHA、A-019 独立 disposition、v0.18.2 方法与相关组件均未修改。
- 本条没有创建 Probe、binding、runner 或 trial，也没有实际 handoff/S2；Goal status/progress 不变。
