# 世界模型协作定界闭环候选 v0.1

**方法候选，尚未接受或验证。** 本附件面向 [D-004](../01-decision/D-004-reusable-world-model-framing-scope.md) 确认的世界模型构建范围内可复用方法，依据已有方法设计建议整理。它不依赖“世界有多大”的 A/B/C 选择。[探针候选 v0.2](probe-framing-candidates-v0.2.md) 的 A/B/C 仅是三种本轮主要回答任务候选，不是通用歧义分类。

同步选择器未返回答案，不能据此认定创作者选择了任何方向，也没有进入该探针的第二阶段求解。I-401/I-402 保持 open；目标仍 active、33%。

## 意图与边界

方法接受模糊的真实创作问题，并由助手主动协助理解、查找和分析，不能把精确化全部交回创作者。助手也不能自动替创作者确定创作意图、取舍或 canon。若原问题混有非客观创作选择，先协助区分哪些部分涉及世界状态、规律、关系或后果，哪些需要创作选择，再按创作者裁定处理。

[D-002](../01-decision/D-002-two-stage-conditional-return.md) 已确认两阶段与有条件回流的主流程；以下闭环步骤、检查方法和停止规则均为待共同试行的细化候选，不扩写为已接受规范。[D-003](../01-decision/D-003-generic-method-probe-scope.md) 保留其当时试行限额。

## 第一阶段：形成可比较、可裁定的工作基线

1. **保留原问与上下文。** 留下创作者真实表达、已有设定、已有答案、明确约束与未知项，避免为了套框架而改写问题意图。
2. **助手主动形成解释。** 根据上下文提出若干创作用途假设，标明推断依据与关键歧义；按需查找资料、参考和反例，用分析缩小候选范围。没有具体事件时也可作明确标注的假设对照，不把假设当作已选场景。
3. **比较候选问题框架。** 各候选说明可能服务的创作判断、适用边界、拟保留子问题及其必要性、预期答案形式与精度、证据或待收集信息，以及未覆盖部分。呈现内容随问题而定，不要求创作者逐栏填表。
4. **共同确认工作基线。** 创作者选择意图与取舍，确认当前采用的框架及问题集。分别记录助手建议、可核对事实和创作者裁定，保留尚未解决的分歧与假设；确认不是永久冻结。

这组操作用于把模糊问题推进到可讨论的具体候选。不能仅凭产生了框架或填写完记录就宣称第一阶段完成。

## “最小充分”的候选检查

目标是相对于当前用途、边界和精度，找到具有局部充分性、且暂未发现可删除项的问题集候选；不承诺全局数学最小，也不将检查表变成强制问卷。

| 候选检查 | 拟检视的内容 |
|----------|--------------|
| 支持判断 | 得到这些答案后，能否支持当前创作判断；判断用途是否经过创作者确认？ |
| 逐个删除 | 暂时删除一个问题，是否仍能维持上述判断与回答的有效性；是否遗漏必要依赖？ |
| 继续细分 | 进一步细分是否可能改变当前判断或其有效性，还是仅增加当前用途不需要的细节？ |
| 综合回应 | 子答案能否连成对原问的回答，说明边界与未知，而非仅给出一组孤立事实？ |

删除检验可能受问题间依赖或不同组合影响，通过一次检查不证明唯一最优。若尚无足够证据判断必要性或细分价值，可提出有界收集与分析候选，再共同决定。具体操作、证据要求和停止规则仍待共创；本附件不自行确定阈值。

## 第二阶段：处理保留问题并综合（候选，尚未验证）

在工作基线获确认后，围绕保留问题组织必要资料、参考、反例与推理，形成有适用条件的答案。既有答案复用、联合求解或逐项处理的具体组织方式仍待共同确定；无论采用何种方式，都须能追溯每个保留问题如何得到处理。

把子答案综合为对真实原问的回应，明确哪些判断已获得支持、依赖哪些假设、哪些部分仍未知。向创作者呈现结果以审视其创作用途，不自动升级为 canon。当前附件未执行这一阶段，不能充当任何问题的答案或效果证据。

## 条件触发回流（候选细化，尚未验证）

沿用 D-002：求解若要求改变范围、关键假设、精度或重要依赖，或综合答案不足，则返回第一阶段重确认受影响范围。可供试行的留痕是：指出新证据或不足、说明影响哪些问题和判断、给出调整候选，再由创作者裁定新的工作基线。

不将所有未知自动扩成新子问题，也不以已确认基线为由忽略有影响的新证据。本段不自动授权扩大当前探针范围，具体回流操作仍待共同试行。

## 待验证内容

I-401 仍要求在实际应用中共同明确创作场景、判断用途、资料及精度，才能验证真实场景的充分性。I-402 仍要求在 S2 退出前共同确定跨问题最低验证范围与证据强度；本附件没有规定探针数量，也没有提供可复用性通过结论。

下一步可以审视、修改这份独立于 A/B/C 的方法候选；任何探针方向和问题集确认仍须真实用户裁定。没有答复不能被解释为采纳或许可。
