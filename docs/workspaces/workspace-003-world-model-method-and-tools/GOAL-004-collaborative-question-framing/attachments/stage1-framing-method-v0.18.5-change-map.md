## 对 A-023 歧义及后续创作者明确化的逐项对应

**A-024 状态说明：** A-024 的 Reviewer verdict=`ACCEPT` 针对当时提交的 v0.18.4 原文，仍然有效；v0.18.4 方法本身仍为 `draft / unaccepted`。v0.18.5 不修改 v0.18.4 或 A-024 审计记录，也不把后续新增的更明确请求前门槛倒推成 A-024 的错误。v0.18.5 是在该经独立审查且 closure 通过的候选之上的后继澄清，落实创作者随后要求的“先完成当前层适用分析，再请求局部三态”。

1. **外部知识是否改变当前 S1 framing**（A-023 §1）：v0.18.5 仍按 Rule B 的 N3 判断与可判别性分析。确有当前层知识缺口，就给出能区分／排除的结论和依据，或说明为何仍不可判别；不能因原问没有研究提示而跳过识别。具体事实未知若属于 B3，保留给阶段二，不以“研究过”冒充目标世界事实。
2. **按需研究与跳过理由**（A-023 §2）：当前层判断是否存在适用 N3；只有既有 Adapter 调用条件及判断需要成立时才研究。纯推理缺口可用现有输入与结构推理处理。没有每轮必搜、每个 N3 必搜或固定“不需要研究”证明仪式。
3. **semantic zoom 三态与 Rule C**（A-023 §3）：三态只处理已呈示节点的保留／下一层授权／否定，不能借措辞让 creator 裁定需求。若实质请求 creator 选所求、含义、需求参数或必要结构取舍，先遵守 Rule C 的末位条件与回问前分解判断；未实例化对象或参数本身并非 B1。
4. **确认前 AI 自主检验与时点**（A-023 §4）：先完成该节点当前层适用的 Q 支持与关系、问题族诊断、候选生成／比较／攻击与 E 准入／排除或有据无准入、B/F 未决归属、适用 G 攻击／差异处置、真正 N3 的可判别性，再逐项呈示 handoff-ready 四要素状态和三态后果。仅宣称完成、展示待办或把分析交给 creator，都不能请求局部三态。这个局部门槛不是整个 S1 的最终收束。
5. **run-16 当前请求的归类**（A-023 §5）：本候选提供以后判断“局部授权”与“最终收束”的文本标准，不倒填 run-16 行为证据，也不判它 pass/fail。run-16 仍暂停且没有 creator 答复。

## 关键边界与情形

| 情形 | 当前层请求前的处理 | 三态和最终边界 |
|---|---|---|
| 纯推理缺口 | AI 用当前 Q、已知结构和适用 E/F/G 进行分析与举证；不凭“有疑问”自动变成 N3 或调用研究 | 分析完成并有当前层证据后方可请求；未完成的最终收束仍留在 S1 |
| 真正影响当前 S1 定界的 N3 | Rule B 做可判别性和路由；外部研究仅在既有 Adapter 条件满足且有用时调用，回流仍按 E/F/G | 已识别的当前层缺口不能无理由跳过；也不把研究设成每轮必经步骤 |
| 抽象 W／对象参数尚未实例化 | 继续从 raw Q 生成必要结构、保留抽象对象或变量，判断具体值是否真的影响所求／结构；不凭未给值判 B1 或不唯一 | 仅真实 creator-owned 阻断按 Rule C 回问；问题集唯一不要求 W 具体取值 |
| 适用的局部 G 增量 | 按 G.1.3 处理已出现的当前子树增量；仅当改变父层三项判据时向上回流，不自动重开全局搜索 | 未处理的当前层增量不能交给 creator；局部请求也不要求最新结构的全局 G 收束证明 |
| 保持粗粒度 | 先完成当前层分析并说明保持后尚有何工作 | 可保留节点；若四要素未就绪，不能交接，最终 E/F/G 和出口仍要做 |
| 不接受节点 | 先呈示成立／问题族依据、候选与后果 | creator 否定后由 AI 处理受影响结构和未决项，不要求 creator 写替代子问题 |
| 继续展开 | 当前层分析完成且呈示下一层拟分析范围 | 只授权向下一层，把节点作局部 Q* 复用方法；不要求请求前递归处理所有子节点 |

**三个就绪状态**：当前层请求就绪＝节点现阶段适用 AI 分析和发现处置已完成，允许询问粒度；handoff-ready＝四要素足够明确的候选求解节点；最终全局收束／handoff＝整体问题集经 Rule G、Rule F、出口检查、creator 确认及冻结交接合同的独立门禁。前者不推出后两者，handoff-ready 标记不授权独立节点交接。

## 兼容性与刻意不变项

- **Rule C / run-15 修复**：从 raw Q 主动分解仍先于不必要回问；对象／参数未实例化不等于 B1 或不唯一；无法继续时须指出受阻位置、已有分析和 creator-owned 剩余差异。v0.18.3 的相关条文与出口第 1 项没有重写。
- **semantic zoom / E/F/G / bounded convergence**：只补请求时点与现时证据门槛，不引入固定 checklist、taxonomy、候选数量或统一树深；当前层适用发现须处理，局部请求无需全局 G 关闭、所有候选穷尽、递归处理每个子节点、或为授权重复最终停止攻击。Rule G 的最终收束判据及“已处理增量”与“最新结构上无新增量”的区别仍在真正收束时完整适用。
- **研究 Adapter/Core/Schema 与 Demand Preservation**：文件和调用合同不变；N3 研究仍按需。research-return 进入 E/F／结构／B3 时，原有 demand baseline、条件角色、B3 scope diff、必要时 B2 fallback 与出口第 11 项仍适用；普通非研究 N2 不新增 baseline。
- **handoff 边界**：粒度三态既不确认最终整体结构，也不启动 S2。节点级独立 handoff 仍需另行接受且明文允许范围拆分的 method/host、冻结合同 §1 三项门禁及实际交接授权。
- **证据与治理**：A-023/A-024、run-16 trace、v0.18.3/v0.18.4、任何 ledger 或 goal 状态均不改；本映射不作审计 verdict、方法接受、试跑绑定或实际运行判定。
