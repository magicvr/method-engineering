# GOAL-011 · R4 真实用例 black-box 检验与交付验收

## 概述

承接 Root R4。正式真实用例的原始问题为 `修真具体怎么修`，直接作为方法输入；方法构建方不得预拆题、预分类或预判答案。R4 记录方法自身产生的澄清、停止、条件结果或缺陷；试运行结果由维护者在本仓验收，方法工作版与 no-tool 记录随后仍按 consumer-response-protocol 交付下游并完成实际收件、验收/异议迭代、反馈路由与结束。正式交叉审计由维护者在工作流外调用外部工具完成，AI 助手不代调用、不冒充 independent。

## 非目标

- 不由方法构建方替方法拆解或预答 `修真具体怎么修`。
- 不写 canon、剧情、主题、角色取舍或作品事实；不实现完整模拟器/固定软件架构。
- 不围绕该用例定制方法，不以单次用例证明方法普遍有效。
- 不实现工具；本轮沿用 R3 的 no-tool 分支和 I-006 限定残余。
- 不由 AI 助手执行正式 independent/cross 审计；该门禁由维护者外部完成。
- 不解除 I-010、旧 H/H3 或其他未授权门禁。

## 成功标准

- [x] S1：登记原始问题原文、正式 R4 授权、消费者/验收与交付目标；不预拆题。
- [ ] S2：核对最终方法版本适配、no-tool 分支、证据/停止计划和外部审计模式。
- [ ] S3：用原始输入执行一次 black-box 有界运行，记录方法自身的澄清、停止、条件结果或缺陷。
- [ ] S4：本仓试运行结果验收完成并留证。
- [ ] S5：方法工作版与 no-tool 记录按协议交付下游，实际收件、验收/异议迭代、反馈路由与结束留证。
- [ ] S6：维护者外部独立审计意见落盘，无开放 required；用户确认后才置 done。

## 审计模式

正式 independent/cross 审计由维护者在工作流外调用外部工具执行，AI 助手不得代调用或冒充。S1～S5 可使用 self/内部核对；S6 必须落盘维护者外部审计意见并处理 findings，才可提议 R4 done。
