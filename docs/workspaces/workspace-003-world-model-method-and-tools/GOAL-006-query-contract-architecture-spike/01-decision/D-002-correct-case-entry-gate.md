# D-002 · 修正真实用途情境与案例准入门槛

- **日期 / 状态**：2026-09-30；accepted。Creator 选择采用最小修订。
- **决定**：
  1. 本 spike 的真实使用情境是 VP-003 对应下游仓提出、并等待方法与工具交付以开展实际构建的需求：「构建星际时代的修真世界观」。此情境由 creator 于本轮对话直接确认；不依赖读取其他工作区材料。
  2. E-002 所记四项 creator 提供/确认的问题构成本次 S1 的真实问题池，可处于同一个实际用途情境中；不得要求额外项目、用户或虚构 persona 来满足案例门槛。
  3. 「现有 capability 不足」改为 S1 的待评估结果，不再要求试验开始前先证明某一问题能力不足。S1 按 I-002 的现有能力基线逐例分类；若没有观察到能力不足，或证据不足，则记录为 `not observed` / 未决并限制相应结论，不补造案例。
  4. I-001 只负责确认真实问题、来源及真实用途情境，现有四项问题和 creator 确认已满足，状态改为 `verified`。查询类别与 capability / gap 分类留待 S1 观察。
  5. I-002（当前能力基线）与 I-003（本次判读阈值、未观察类别的结论边界和 S2 入口）继续作为 S1 必需前置门禁。
- **理由**：原门槛把样本输入与试验后才可得到的能力分类混在一起，也可能将同一真实需求误解为必须另找外部案例。候选架构应在真实下游用途及其真实问题中接受检验；能力不足应由基线对照得出，而不是作为选样前提。
- **未选方案**：要求额外独立项目/用户或预先证明 capability 不足的案例。该要求会把试验结果倒置为入口条件，并可能诱发无关或合成样本。
- **影响**：D-001 中“现有 capability 不足”的类别要求按本决策修订；`00-meta.md` 的成功标准、S1 退出条件及 I-001 已同步。GOAL-006 保持 `active`，不启动 S1/S2；v0.18.5、run-19、方法文件、handoff、GOAL-004 / GOAL-003 状态与历史审计均不变。
- **后续**：补齐并核实 I-002；提交 I-003 的本次试验判读标准供 creator 决定。两项就绪后再冻结案例包及 S1 判读条件。
