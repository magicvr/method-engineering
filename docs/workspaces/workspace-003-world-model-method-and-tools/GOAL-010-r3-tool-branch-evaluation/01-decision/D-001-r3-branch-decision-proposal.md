# D-001 · R3 工具分支决定建议

## 用户裁决

2026-10-04，用户接受推荐方案 D：本轮暂不引入工具，理由是启动工具投入的证据尚不足，而非工具已被证明不值得；将 I-006 记为限定 accepted-residual（非 verified）。

## 问题

I-006 为 required/open，要求在 R3 退出前依据现行人工过程/既有实践证据判断工具化是否值得。S1 已确认：人工方法、步骤和手填结构已文档化；但没有真实重复率、任务级人工成本、实际收益、维护负担或实际失败/停止事件的观察证据。真实案例受 I-002 控制且未授权。

## 方案比较

| 方案 | 内容 | 主要风险/影响 |
|---|---|---|
| A | 立即 no-tool，但直接写 verified | 把未知改写成已证，不符合 P-005 |
| B | 先做有界人工走查/纸面演练 | 可增加过程证据，但演练耗时不等于真实成本，未必回答价值问题；需新增信息收集授权 |
| C | 支持工具化并定义最小 Skill 接口规格 | 缺少支持投入的价值依据；规格不能证明收益或方法有效 |
| D | 限定 no-tool + 用户接受 I-006 残余 | 保留未知并允许 R3 在本轮边界内退出；需要用户书面接受残余风险 |

## 推荐（待用户裁决）

采用 D：本轮暂不引入工具，理由是启动工具投入的证据尚不足，而不是工具已被证明不值得。

建议残余范围：

- I-006 记为 `accepted-residual`，非 `verified`。
- 仅解除 GOAL-010 S2～S4 分支冻结与 R3 退出门禁。
- 不解除 I-002/I-004/I-010、真实案例、工具实现/安装、下游写入、外部模型、自动验证或 R4 交付门禁。
- 继续使用人工方法工作版、两项手填结构和停止/回接规则。
- 责任：同一维护人复评；触发：获得任务级成本/重复/遗漏证据、需求或步骤实质变化、提出有依据的工具候选、R4 方案冻结前。

## 未选分支说明

- B 仅作为备选；若用户不接受残余，可改为有界信息收集，但需单独授权输入、范围、预算、停止与证据用途。
- C 当前不推荐；若未来选择工具，接口规格只能证明职责/权限/输入输出/失败路径已定义，不能证明工具收益或方法有效性。

## 用户裁决点

本 D 条目在用户书面确认前保持 `proposed`。未确认时 I-006 继续 open，S2 不冻结，R3 不就绪。
