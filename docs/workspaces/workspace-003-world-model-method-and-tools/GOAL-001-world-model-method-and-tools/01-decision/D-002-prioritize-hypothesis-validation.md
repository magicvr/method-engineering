## D-002 · 优先验证假设、失败转向的路线选择

### 触发与用户裁决

用户要求架构师重新设计 workspace-003 Root 的路线图，优先考虑以下假设：多个自洽机制模型回答明确问题；用世界内部角色的身份与情景澄清模糊问题并形成可求解的问题集合；以典型身份→情景→问题的采样冷启动机制模型集合，后续按需增长。用户同时要求将其视为有潜力但可能失败的思路，路线须允许中止验证并转向其他构想和验证。

架构师形成只读设计意见后，用户选择架构师方案 **「AI 推荐：先验证、失败转向」**。本条记录接受的是路线选择，H1/H2/H3 尚无实证结论，也未被接受为正式方法。

### 决定

1. 保留 Root 的 R1/R2/R3/R4 四个纲领检查点与 **R1 → R2/R3 → R4** 顺序；均未开始，`progress: 0%`（0/4）。R2a～R2d 仅为 R2 内部安排，不新增进度分母或子目标。
2. R1 先冻结需求、授权、试验范围与预算：H1/H2/H3 的预注册判据、停止规则、是否允许修订复验及其有限次数/资源上限，以及替代方向的有限数量、试验回合/资源上限与责任。现有用户路线裁决不替代 `I-001` / `I-003` 的双边澄清与冻结。
3. R2 依次操作化假设（R2a）、有界试验（R2b）、证据选路与必要转向（R2c）、暂定方法工作版（R2d）。分别验证 H1 机制模型求解、H2 身份/情景转译、H3 冷启动覆盖；局部失败不推导整套世界模型方法失败。结果按 `supported` / `partial` / `refuted` / `insufficient` 记录，证据不足不当作通过。
4. 身份/情景先作有界采样与澄清入口，不假定组合可穷尽；已明确的问题可直接求解。用直接「对象—条件—所求结果」作轻量对照，检验额外转译步骤的价值，不建设第二套完整方法。
5. 世界状态/时空切片先作机制模型显式输入，角色认知与客观状态分别表达；独立状态层须待共享状态、跨模型一致性或重复使用证据支持后再判断。核对必要模型接口与组合冲突，未覆盖内容列为未验证。
6. 反例触发预注册停止规则；仅在原因可定位且 R1 已授权时按冻结限额修订复验。失败或局部失败后在冻结限额内构想/验证替代方向；不得无限添加模型、身份或场景直至通过。证据不足、限额用尽仍无可选路线、或须改变范围/授权/预算时，暂停受影响阶段并请用户裁决、留痕。
7. `I-002` 保持 `open`，任何 R2b 真实案例使用前须由下游/用户书面选定；本仓不代选。R4 仍检验最终工作版端到端闭环，复用 R2b 案例只证明该有界案例可执行，不宣称独立泛化验证。
8. `I-003` 保持 `open`：R1 确认是否引入工具与最小边界，R3 落实/核对交付或不引入说明；R3 可在 R1 后并行界定，工具实现等方法接口稳定。`I-004` 仍为 R4 交付前独立审计模式/provider 门禁。
9. 新增 required / open 的 `I-005`：H1/H2/H3 在冻结范围内是否足以支持方法选路，R2c 前由证据回答。只有 `supported` / `partial` / `refuted` 的可核对证据足以形成路线选择时，才可形成选路结论；`insufficient` 保持 `open` / `collecting` 并阻断 R2d。R2d 工作版须覆盖 VP-003 意图第 2 项的全部指导范围；未试到内容标注限制/未决，不以本次路线选择声称有效性。

### 为什么

假设可拆分检验，可识别机制求解、问题转译或采样覆盖哪一环失败，并保留有证据的部分。先冻结判据与限额，可避免在反例出现后不断补充内容直至宣称通过。转向分支保障本目标继续服务消费需求，同时让试验失败、证据不足和授权耗尽各自有明确处理方式。

### 未选方案

- **失败时暂停再裁决**：优先验证假设，但失败后暂停 R2，另轮由用户裁决替代方向；控制更严、范围更小，但可能多一轮等待。用户选择在 R1 冻结限额内设置替代方向构想/验证分支，超出该边界时仍须暂停并裁决。
- **并行比较两种方法**：在同一获授权问题上同时比较身份/情景/机制路径与直接按对象/条件/结果路径；偏差风险较低，但早期成本与案例评估更多。用户选择先检验假设并使用轻量对照，证据需要时再有界转向。
