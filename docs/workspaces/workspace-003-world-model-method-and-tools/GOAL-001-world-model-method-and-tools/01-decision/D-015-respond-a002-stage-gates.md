# D-015 · 响应 A-002 并按阶段修正信息门禁

## 决策与授权

用户要求修正 [A-002](../03-audit/A-002-r1-i003-gate-deadlock-review.md) 审计发现的问题，并明确上游与下游由同一维护人维护，不得设置形式确认或要求后继阶段成果的前置门禁。经方案裁决，用户明确选择 **方案 A：R1 条件策略 + R3 独立价值评估信息项**。本决策落实该选择，取代现行草案中的错误阶段门槛；历史 v0.6.2 与 D/E 原文保留。

## 阶段边界

- **I-001 / R1**：只冻结方法用途与退出材料、一般适用/排除边界、输入授权核对协议、证据类型/标签、总体资源上限、停止/变更机制及责任。逐次问题、模型/版本、输入/样本、逐格预测、局部判据/严重度由 R2a 操作化；对应运行的完整预登记为 R2b 开跑前要求，不反向阻断 R1，也不另包为新信息项。
- **I-003 / R1**：只冻结 D-009 已选的独立 Codex 项目 Skill 条件策略、最小职责/权限与产物类型、价值评估依据/触发时点/责任及两条分支。R1 不要求已有重复使用证据、Skill 名称/源路径、精确字段、持久化、安装或实现验收细节。关闭 I-003 不表示价值已验证或工具已实现。
- **I-006 / R3**：新增 required 信息项，评估既有实践与 R2 人工方法过程证据，并落实本轮工具化分支。R3 最迟退出时必须有结论：支持则等待稳定方法接口形成最小工具；证据不足或价值未成立则明确本轮不引入，记录证据范围与理由、下次评估触发条件和责任人。此项不阻断 R1/R2，不要求肯定价值，不无限追加运行，不以先实现/启用 Skill 或 R4 使用反馈为前提。证据不足不冒充已验证工具价值。

两仓的同一维护人负责实质决定；AI 可在授权范围整理信息与证据。既有 D-005～D-011 / D-014 等用户选择按授权继承，上游记录一次实质裁决，下游同步版本/提交引用，不要求共同维护组对同一版本再次书面确认、重复签字或待完整稿重新接受。

真实案例仍由 I-002 在 R2b 使用前控制，R4 前复核最终版适配；维护身份不能推定任意案例已授权。I-004 的 R4 独立审计与 I-005 的 R2c 证据选路门禁语义不变。R4 交付、实际收件、验收/异议处理分别记录真实事实，同一人可承担不同角色，引用不代替这些事实。

## 为什么

A-002 的 F-001/F-002 把 R2/R3 才产生的使用证据与实现细节要求在 R1 完成，形成依赖循环；F-003 把 R2a 的逐次操作化提前为 R1 门槛；F-004 在同一维护人事实下重复要求形式确认。按信息实际需要的阶段拆分，可保留 required 信息控制而消除循环。

VP-003 退出判据 3 已允许“本轮不引入 + 触发条件与责任”。VRev-006 的 V-F-001 是 recommended；选择该标准分支不要求先书面拒绝 Skill，也不新设愿景复审门禁。若以后实质改变 VP 边界，则按愿景治理另行处理。

## 实施与边界

实施事实见 [E-029](../02-execution/E-029-respond-a002-stage-gates.md)。当前修正草案为 [v0.6.3](../attachments/R1-freeze-proposal-v0.6.3.md)，未决清单按 R1/R2a/R3 分配。方案 A 的选择只接受本次门禁修正，不表示整份方法草案接受或 R1 已完成；信息项仍 open，阶段顺序和四检查点进度不变，不产生试验、案例授权或工具实现授权。A-002 的正式审计响应及 finding 合法闭合另记审计台账。
