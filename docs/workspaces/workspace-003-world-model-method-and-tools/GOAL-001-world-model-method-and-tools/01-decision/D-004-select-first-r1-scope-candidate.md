## D-004 · 选择 R1 第一轮方法范围候选

### 触发与用户裁决

上游 R1 提案 v0.6.1 提出第一轮方法范围候选。候选要点为：创作者实际执行方法；面对有界客观世界问题时先查现有裁决能力及所需状态/参数，再诊断缺状态/事实、缺组合/求解、精度不足或新机制；只有确认新的模型能力缺口后才进入新增/扩展模型步骤；AI 可协助但不代劳；保留两个可人工填写的最小结构。用户选择「按此继续」，其选项明确为将该候选设为两仓当前范围澄清基线并更新下游指针，同时保持 draft 与门禁开放。

### 决定

1. 接受 v0.6.1 作为 R1 下一步澄清与后续候选设计的**当前范围基线**，并授权将下游 WRK-002 当前 R1 草案指针更新至此精确提案版本。
2. 此选择只确定当前澄清对象，不接受或冻结完整方法，不改变 `I-001` / `I-003` / `I-005` 状态，不授权真实案例使用、试验、复验、替代验证、工具实现或阶段放行。
3. H1/H2/H3 的具体范围、预注册判据、证据充分性、停止/复验/替代流程与数值限额，及 Skill 边界/验收/分发仍逐项待后续候选与裁决；两个最小结构的职责与字段也未冻结。
4. 下游旧 D-003 / E-004 及旧冻结材料继续作为当时真实发生的历史记录，不删除、不改写；当前指针更换后，不用旧冻结内容替代本候选，也不推导下游 M1 完成。

### 为什么

该候选与已受理需求及执行主体修正版相符，并补明只有确认新模型能力缺口后才启动新增建模。用户选择先按此作为范围澄清基线，可让后续假设判据围绕同一问题范围展开；逐项记录未决字段，避免把范围方向误当完整 R1 冻结。

### 未选方案

- **调整候选后再更新**：未选；本次选择确认按 v0.6.1 继续。
- **暂缓并补充使用情景或授权依据**：未选；仍须裁决的使用情景、信息源和授权字段保持开放，继续在后续 R1 候选中澄清。

### 影响与后续

- 下游当前 R1 指针改为 `magicvr/method-engineering` 提案 v0.6.1，需以精确上游提交和路径记录；下游实际写入由后续执行记录确认。
- Root 保持 `active`、`progress: 0%`、纲领检查点 0/4；R1 尚未退出。没有新建子目标，没有案例选择、试验或工具实现。
- 用户本次决定原文为「按此继续」；其它未决字段不由该短答推定。
