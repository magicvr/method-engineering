# D-019 · 建立 R2 子目标并明确父子职责

## 决定

按用户本轮选择，在 workspace-003 中新建平铺子目标 [GOAL-002-r2-method-validation](../../GOAL-002-r2-method-validation/00-meta.md)，承载 Root R2 的 R2a–R2d 执行、证据与审计上下文。R2 阶段状态改为「进行中（R2a 准备）」；Root 状态仍为 `active`，纲领进度仍为 25%（R1 完成 1/4）。

Root 继续作为全项目目标、纲领路线、对 VP-003 的实现承载及全局信息门禁的唯一权威。子目标复用 R2 已有范围，不修改 R1 冻结、R3/R4 顺序或父级成功标准。Root I-002 控制真实案例运行授权；Root I-005 控制 R2c 证据选路及 R2d；Root I-006 仅控制 R3。

## 理由与未选方案

R2 是一条具有独立执行事实和证据包的顺序交付链：操作化假设、有界试验、证据选路与形成方法工作版。由独立子目标保存其阶段台账，便于追踪 R2a–R2d 的证据与复审；Root 保留整体路线和门禁，避免子目标形成第二套全局状态。

未选方案：将 R2 的全部执行留在 Root 台账。该方案未按用户选择采用。

## 下一步

先推进 GOAL-002 的 R2a 逐项操作化。当前准备方案不是已冻结预登记；具体试验问题、输入/模型、局部判据和任何真实案例授权均须按既有用户裁决与门禁另行落实。
