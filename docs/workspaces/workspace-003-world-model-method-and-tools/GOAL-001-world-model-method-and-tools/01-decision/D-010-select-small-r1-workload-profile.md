# D-010 · 选择 H1/H2/H3 小型可行性工作量档

## 决策

用户于 2026-09-30 选择 Root `E-019` / 候选 A「小型可行性轮」。未来首轮计划上限为：

- **H1**：1 个清晰问题、2 个预先声明的机制模型、基线与 1 个预先声明的条件变化，最多 4 个结果格。
- **H2**：1 个预先确认确需澄清的问题，分别使用身份/情景路径与直接「对象—条件—所求结果」路径，最多 2 个结果格。
- **H3**：1 个预先封闭的抽样框，最多 3 条身份→情景→问题链。
- **全项目资源上限**：共同维护组最多 3 人时；全项目最多 1 次可定位原因后的定向复验，并最多 1 个替代方向、验证 1 次；任何上限达到后停止扩展并按已冻结判据记录。此选择没有授权额外付费服务、API 或专用工具。

## 决策边界

此项只冻结后续小型可行性轮的**计划规模上限**，不能作 H1/H2/H3 结论，也不代表该轮已经启动或已获实际试验授权。具体问题与案例、H1/H2/H3 的精确范围和输入、支持/否决阈值、样本抽取方法、H2 效用标准、人时核算责任和完整停止判据仍须在 R1 合并冻结稿中明确；实际使用真实案例前仍须关闭其 `I-002` 范围。未完成余下 R1 必需信息与双仓同版记录前，不放行 R1/R2。

选择小型档的理由是它先回答方法流程能否在紧凑范围内留下可追溯证据；按 D-006 的声明范围规则，即使所有结果符合，也只能支持已覆盖的局部主张，不构成对整体 H 或方法普遍性的证明。
