# D-014 · 选择创作者主责的方法使用边界候选

## 决策

用户接受“创作者主责”候选，作为 I-001 待共同维护组确认的使用边界：方法由创作者运行，主题、取舍和最终判断由创作者作出；AI 助手可选，可提供提示、引导、候选、示例、反例、检查、追问与整理，但建议和创作者裁定应分开留痕，创作者不能退化为被动确认。

方法从实际创作中的客观世界问题开始，检查现有能力及所需状态/参数；只有确认新的模型能力缺口后才新增或扩展模型。该方向承接下游需求原文与 2026-09-26 构建主体澄清，见下游 `exchange/WRK-002-world-model-method-and-tools/需求-2026-09-26.md` 与 `需求澄清-2026-09-26-构建主体.md`。

该候选待共同维护组对完整 R1 方案书面确认。具体使用情景与排除项、输入来源/授权、维护组在澄清及验收中的职责、交付格式、H1/H2/H3 局部判据与完整接受程序仍待确定；`I-001` 保持 `open`。本决策不表示完整方法接受或冻结，不授权试验、真实案例使用、复验或工具实现。

## 为什么

来源材料已把创作者明确为主要构建者和最终裁决者，同时允许 AI 充分协助但不得代劳。选择此候选保留创作者能独立运行方法的要求，并允许有界、可追溯的人机协作；它也与已选的创作者局部裁决预登记路径一致。

## 未选路径

- 创作者与共同维护组成员作为共同日常操作者：本次未选；这会增加介入点、权限与责任分配，仍可在共同维护组确认时提出。
- 暂不形成使用者候选、完全等待共同维护组提供输入：本次未选；完整方案仍须由共同维护组书面确认。
