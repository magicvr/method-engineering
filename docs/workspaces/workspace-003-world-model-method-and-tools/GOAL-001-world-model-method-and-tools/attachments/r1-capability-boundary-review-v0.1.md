# ARCHITECT R1 能力边界复审 v0.1

来源：ARCHITECT 只读复审，基线 d7fa29c。非正式审计，不替代维护者外部 independent/cross 审计。

## Verdict

R1 冻结的是一个混合契约：有实质价值的需求、责任、资源与工具边界，加上一套偏重材料完整性和阶段流转的交付协议。它不是毫无意义的形式打卡，但也没有充分冻结一个可据此验收的最低能力承诺。

关键缺陷：R1 明确了方法应涉及哪些功能、交付哪些描述、不得越过哪些边界，却没有足够明确后续方法至少必须产生什么正向能力表现，以及什么表现即使记录完整也算失败。

## R1 实际冻结了什么

- 对象与任务方向：创作中的有边界客观世界问题；判断已有能力是否能裁决，并在确有机制缺口时补足。
- 使用主体与决定权：创作者运行并保留最终取舍；AI 可追问、建议候选、解释、提供反例和检查，但不替作者决定。
- 缺口判断与建模节制：先检查已有能力，再区分状态、组合、精度和机制；不能无证据假定机制缺口。
- 允许结果与模型约束：值、范围、机制依据下的不确定、低精度或无法裁决；不伪造精度；模型说明范围、依赖、组合、一致性和反例并返回创作。
- 排除边界：十一项非目标；世界状态、角色所知、观众所知分开；不写 canon。
- 工作版最低材料内容：目的、适用条件、步骤、每步输入/输出/停点、决策点、AI 边界、证据版本、限制及责任。
- 输入与证据规则：来源/版本/用途/权限；观察、推断、假设、建议和决定分开；不外推局部支持。
- 条件工具策略：根据重复任务、人工成本、收益和维护负担决定工具化或 no-tool；不提前要求实现。
- 后继阶段分工：真实案例、证据选路、工具分支和交付审计分别由 I-002/I-005/I-006/I-004 控制。

## 能力边界 vs 形式

有价值的可检验边界：处理什么/不处理什么；已有能力足够时不新增模型；区分状态/组合/精度/机制；不把假设/AI建议写成事实；模型说明输入、输出、条件、依赖和拒答；作者保留设定与采用决定权；工具不替代方法有效性。

有价值但不是能力证明的工程控制：来源/版本固定、授权范围、预算与停止、有限复验、交付收件事实区分、工具价值评估与 no-tool 分支。

材料/形式要求：结构是否存在、章节字段版本映射是否齐全、当前引用是否同步、审计索引是否登记。它们能帮助追踪，但不能证明能力。

## 缺什么

R1 没有冻结最低正向能力承诺。至少缺少：

- 从尚未结构化的真实需要形成候选理解与暂定分解；
- 至少形成一个可裁决问题并说明它回答原需要的哪一部分；
- 形成有限的候选机制范围；
- 围绕选定问题形成可检查的局部模型；
- 产出对创作有用的有限答案，并说明条件变化的影响；
- 明确失败标准：核心工作退回作者、只有清单/字段而无模型、偷换问题、虚构事实或作者决定、仅凭材料齐全声称能力通过。

R1 的“只证明协议冻结，不证明理论/方法适用”合理地区分了边界承诺与有效性证明，但把能力承诺本身也一起推迟掉了。

## 根因

- R1 冻结了许多“怎么控制工作”的规则，却没有同样牢固地冻结“这项工作至少必须让用户获得什么能力”。
- 后继阶段继承了这一缺口：R2-W 主要验证文本覆盖，R3 验证工具分支，直到 R4 才第一次暴露入口能力失败。
- 历史重复签字已整改，不能用“没有重复签字”证明 R1 的能力规格已经充分。

## Recommendation

主推荐：保留 R1 的历史成果，定向重开“能力边界规格”的补缺；不是全面重跑 R1，也不能只靠重解释宣布它原来已经完备。

保留：v0.6.4 历史冻结事实、对象与非目标、作者决定权、条件结果与证据分层、权限/资源/停止约束、条件工具策略与 no-tool 分支、既有审计原始意见与合法整改记录。

修订：形成继任的能力边界承诺；修订 Root 的 R1 及后继退出条件，使 R1 目标包含“最低能力承诺及验证边界已明确”；必要时澄清 VP-003 对尚未结构化需要的表述；停止继续扩写不回答能力问题的细节和签核仪式。

不建议扩建治理包，也不建议再做一轮全面 prior-art 调查；研究应只针对尚不知如何实现的具体能力问题。

## 最小能力边界模板

- 服务对象：小说创作中的客观机制、状态或交互裁决需要；不代作者决定主题、剧情或 canon。
- 最低入口：原始需要及用户已有资料；允许尚未结构化。不要求预先提供机制模型、完整问题契约或专业分类。
- 方法承担的工作：提出候选理解与暂定分解，协助明确所求结果；检查已有能力及缺口；围绕选定问题形成局部模型。
- 用户承担的工作：说明真实意图和已有事实，决定关键设定与是否采用；不替方法完成核心分解和模型设计。
- 最低输出：与原需要有关联的可裁决问题、局部模型及调用条件、有限答案、检查结果、可再次调用的能力说明和创作用途。
- 正向验收底线：至少一个获准真实问题跑通上述闭环；模型实际产生答案，并能解释一个相关条件变化的影响。不承诺普遍有效或全局最小。
- 明确失败：核心工作退回作者；只有清单/字段而无模型；偷换问题；虚构事实或作者决定；仅凭材料齐全声称能力通过。
- 停止与证据边界：权限不足或不可代作的设定决定可停止相关范围；未知但可探索时允许候选与条件分析。正确停止不替代正向能力证据。

R1 要冻结的是这项承诺；R2 要把它做出来；R4 要检查是否兑现。
