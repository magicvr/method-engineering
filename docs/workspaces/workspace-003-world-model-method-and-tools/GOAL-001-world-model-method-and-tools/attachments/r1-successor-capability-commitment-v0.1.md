# 继任 R1 能力边界承诺 v0.1（草案，待用户确认）

本轮承诺：提供一套方法（必要时包含工具），能够从创作者的模糊、不完整设定出发，构建可长期使用、可按需扩展的世界模型机制。该世界模型必须具备预期的裁决问题能力；若构建出的世界模型不能回答预期的裁决问题，则方法/工具交付失败。承诺对象是能力，不是文档、流程或签核的完整性。

## 核心关系

- 主承诺：构建世界模型。方法/工具必须能够吸收创作者设定，形成长期可用、可按需扩展的世界模型机制。
- 验收条件：构建出的世界模型必须具备预期的裁决问题能力。若模型无法回答预期裁决问题，则方法/工具没有完成承诺。
- 辅助能力：问题拆解、问题族形成和具体查询转换，是为构建、验证和使用世界模型服务的辅助活动；它们不是主产品，也不应成为创作者的前置作业。
- 问题族边界：预期裁决问题族可由方法提出、用户选择，并可随模型扩展演化；重点是模型实际具备回答能力，而不是要求创作者预先提交固定问题清单。

## 运行时交互允许

运行时交互是方法能力的一部分，不是失败或违规：

- 方法可以在运行中提出候选理解、暂定分解、候选机制范围和具体追问；
- 创作者可以在运行中回应意图、补充设定、作出关键选择或要求调整方向；
- 方法可以据此迭代、修正和继续构建世界模型；
- 一次运行不要求完全自动或一次性完成。

边界：交互必须由方法承担主要认知工作，提出可修改的具体候选；不能把“请创作者先完成问题工程/机制模型/专业分类”作为继续条件。运行时交互记录属于运行证据的一部分。

## 预期裁决能力必须可登记、可验证

预期裁决能力不是一句目标描述，也不是签字确认，而是世界模型自身必须具备的接口：

- 可登记：世界模型机制内应有最小能力登记，至少记录问题族标识/描述、输入条件、期望输出类型、依赖的机制/状态、适用范围与拒答条件、版本与扩展状态。该登记是世界模型的一部分，不是额外治理表单。
- 可验证：每个登记的问题族必须有可执行的验证方式，至少包含代表性查询/条件、期望答案类型、对机制/状态/证据的追溯、通过/失败判据、停止/拒答处理，以及新增问题族的扩展验证。
- 验证依据是模型实际回答行为，不是字段齐全或签字；有登记但无法回答，按失败处理。
- 登记必须支持按需扩展：新增问题族时可以补充或修订模型机制，并检查对既有回答的影响，不要求一次性登记所有未来问题。

## 1. 服务对象与真实需要

服务于只有部分、模糊或不一致世界观设定的创作者。帮助其逐步回答可抽象为“这个世界是怎样一个世界”的一系列问题，使设定能够长期组织、调用和演化，而不要求一次性构造庞大的完整世界模型。

## 2. 最低输入

接受尚未结构化的设定、片段、想法和用户已有资料；未知可以保留。不要求创作者预先提交完整机制模型、问题契约或专业分类。连用途也不明确时，由方法协助澄清，而非要求用户先完成问题工程。

## 3. 方法承担的工作

吸收、整理已有设定，区分已确定内容、矛盾、未知与候选；构建初始世界模型机制，明确哪些内容现在需要、哪些可以以后再建；允许并主动承担运行时交互，提出候选理解、暂定分解和具体追问；为保证模型具备预期裁决能力，形成可登记的问题族并执行可验证回答、复用和增量扩展，而非仅提供记录槽位或问题清单。

## 4. 用户承担的工作

提供真实意图、已有资料和确定设定；决定关键设定、创作取舍及是否采用候选。用户不替方法完成核心问题分解和模型设计。方法不得虚构用户的选择，也不得将建议自动确认为世界事实。

## 5. 最低输出

在获准真实需要上产出：

- 可持续使用的局部世界模型机制：必要结构、规则、状态，以及适用范围、扩展接口和拒答边界；
- 可登记的预期裁决能力：问题族、输入条件、期望输出、机制/状态依赖、范围/拒答、版本与扩展状态；
- 至少一个实际可回答且可验证的问题族，而非只有问题目录或登记表；
- 新问题到来时如何复用、补充或修订机制，以及如何检查对既有回答的影响；
- 结果如何支持具体创作的说明。

这些是功能要求，不预设固定目录、软件架构或工具形态。

## 6. 正向验收底线

至少一个获准真实需要跑通：

模糊设定 → 运行时交互与候选构建 → 世界模型机制构建 → 预期裁决能力登记与验证 → 有依据的有限回答 → 新问题驱动的按需扩展。

须展示构建出的世界模型确实能回答登记的问题族；展示既有机制能够再次使用，并通过一个新增问题检验增量扩展及对既有回答的影响。字段、清单、签字或停止记录不能代替通过；只有问题拆解而没有可回答模型不能通过；运行时交互本身不是失败。“长期可用”先以可复用、可维护、可演化的实际表现检验，不以一次运行证明永久有效。

## 7. 明确失败

以下情形不得按原承诺验收：核心工作退回创作者；只有记录没有机制；只写流程却不能回答问题；构建出的世界模型不具备预期裁决问题能力；只有问题拆解而没有可回答的模型；有登记却无法验证回答；把运行时交互本身当作失败；要求先完成整个世界，或无必要地为未提出的需求建造超大模型；偷换真实需要；虚构设定或作者决定；扩展后无法说明既有机制和回答的适用变化。

## 8. 停止与证据边界

权限不足或必须由作者决定的设定，可停止相关范围；未知但可探索时，允许明确标注的候选、假设与条件分析。保留实际输入、关键选择、机制、回答、扩展结果及限制。正确停止不等于能力通过；条件推演不等于设定已确定或领域有效性已证明。

## 9. 对原 R1 的处理

保留对象与非目标、作者决定权、证据诚实、实质授权和条件工具策略；补正最低入口、方法责任、正向能力及失败底线；废弃其作为验收依据的用途：重复确认、材料齐全即能力就绪、未知一律整体停止。历史冻结事实保留。

建议同步澄清 VP-003 的能力范围：从模糊设定形成可演进世界模型，而不只是处理预定义裁决问题；不能仅替换 R1 标题。是否构成实质范围修订由用户确认，不默认改 Charter。

## 10. 用户必须裁决

确认上述入口与能力范围；确认候选设定的允许边界、首轮投入上限及“复用＋增量扩展”的验收底线；确认 VP-003 的相应澄清或修订。初始问题族由方法提出、用户选择，不要求用户先自行设计。工具仅在确有助益时引入，不作为能力成功条件。
