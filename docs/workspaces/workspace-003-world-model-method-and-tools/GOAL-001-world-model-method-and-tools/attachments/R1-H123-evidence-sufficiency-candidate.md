## 1. 需明确的层级

为避免一个局部演示直接变成整个 H1/H2/H3 的结论，候选区分两种结论：

- **检验单元结果**：一个事先限定的问题、情景、条件切片或采样单元上的 `supported` / `partial` / `refuted` / `insufficient`。
- **假设范围汇总**：对预先定义的 H 范围内哪些切片已有充分证据、哪些被否决、哪些未覆盖的汇总。只覆盖部分范围时，整个假设不能标为整体 `supported`；需标 `partial` 或 `insufficient` 并列明未覆盖部分。范围/切片须在执行前冻结。

共同规则：预注册后才开始收集证据；只能按预先声明的范围与判据评定。预先登记的否决观察出现时才可 `refuted`；缺输入、缺案例或样本不足时为 `insufficient`，不得以补充材料自动扩成通过。任何结论均不超出实际证据范围。

## 2. 各假设的最低证据包候选

### H1 · 机制模型求解

每个检验单元至少留存：明确客观问题；模型及版本；所需状态/参数与适用条件；目标精度；结果或无法裁决说明；从输入、规则/机制到结果的可追溯依据；预先选定的条件变化/反例及对应输出。若缺条件变化证据，只能评价该单次推导，不能据此声称满足 H1 的条件敏感性主张。具体问题数、变化数、容许近似和否决界限待确认。

### H2 · 身份/情景转译

每个检验单元至少留存：同一项需要澄清的原问；身份/情景转译路径和直接「对象—条件—所求结果」路径的并列记录；相同的可用信息与边界；子问题到原问的映射；综合结果是否保留原问约束；两路揭示的所需输入/可求解性/结果边界差别；额外步骤成本。若没有同问对照，只能描述转译过程，不能据此声称 H2 获得比较性支持。什么增益足以抵偿额外步骤仍待确认。

### H3 · 冷启动覆盖

每个检验单元至少留存：预先声明的有限采样框及排除项；身份→情景→问题→所需能力的对应记录；重复项、未能处理项及范围外未知；“足以启动”标准；初始模型集合按该标准的覆盖矩阵。若采样框、启动标准或所涉样本范围未定，结论为 `insufficient`；不得据此声称代表性或完整覆盖。采样方式、实际数量、遗漏严重度及“足以启动”标准仍待确认。

## 3. 互斥的证据充分性路径

1. **已选择：按声明范围判充分（AI 推荐）**：允许对明确、预先冻结的窄范围给出局部 `supported`；未覆盖的更广 H 范围保持 `partial` / `insufficient`。每个假设使用上述最低证据包；具体范围、阈值和数量后续逐项裁决。优点是可将局部证据与整体外推分开；风险是仍需把“窄范围”和每项最低包具体化。
2. **未选：任何 H 的 `supported` 都要求跨情景证据**：单个问题/情景只可形成局部记录，不能形成任何 `supported` 假设项；至少覆盖多个预先区分的情景/问题类型后才允许该标签。优点是降低单例偶然性；风险是需要扩大案例、样本与资源，且具体数量/类型仍须预先决定。
3. **未选：暂不选充分性规则**：先等待 I-002 所需案例、可用范围和资源信息，再决定证据充分性；期间不为 H1/H2/H3 赋予任何结果标签，R2 继续被门禁阻断。优点是不提前假设样本与预算；风险是 R1 判据冻结会继续等待这些信息。
