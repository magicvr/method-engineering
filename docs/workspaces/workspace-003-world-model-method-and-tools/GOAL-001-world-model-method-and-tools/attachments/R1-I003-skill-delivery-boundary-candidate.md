# I-003 · Skills 工具交付边界候选（待裁决）

> 本候选聚焦 Skills 工具的最小交付边界与承载路径，不把前一轮黑箱探针输入或输出作为设计依据。用户已经提出以 Skills 方式交付的方向（Root `E-005`）；本候选不重复询问「是否 Skills」，而比较其承载范围。用户已选择路径 A（Root `D-009`）：这一方向选择不等于完整边界冻结，所有实施仍未授权，`I-003` 尚未关闭。

## 共同的功能边界候选

无论采用哪种分发路径，建议的最小工具都是一个**由创作者显式调用、供 AI 协作执行方法步骤的 Skill 工作流**，须等待 R1 方法范围冻结后再实现：

- 输入一项创作者提供且允许使用的世界构建问题及相关上下文；缺少 required 信息时询问或停在未决，不以猜测补齐。
- 引导区分现有裁决能力、缺状态/事实、既有模型组合或求解、精度不足、新机制缺口；仅在问题确有歧义时才走身份/情景澄清。
- 输出可追溯的单次方法运行记录：问题范围、使用的信息及来源、采用路径、模型/条件或精度边界、缺失项、未决事项，并区分 AI 建议与创作者裁决。
- 不代替创作者决定主题、取舍或最终内容；不自动写入 `world/` 或其他 canon；不运行 H1/H2/H3 实验，不在缺少单独门禁时调用外部模型或执行自动验证。
- 不引入数据库、脚本校验器、独立 UI/API 服务或通用模型编辑器。R3 再以用户确认的验收项核对交付是否符合本边界。

这只是工具功能范围提议。H1/H2/H3 的具体冻结步骤、输入字段和证据格式仍依赖 `I-001`；不能由工具候选反向冻结方法本身。

## 可核对的现状

- 下游项目已有 `.agents/skills/` 下的治理入口，也保留 Claude、Codex、Grok 的治理 Skill 安装源；下游 README 将现有 `skills/` 定义为目标治理框架包，并明确不是世界模型设定正文。
- 本仓 `skills/README.md` 将 `skills/` 定义为可复制的 Goal Governance 包，含 core 镜像、多宿主 wrappers、安装器与发布/兼容证据门槛；当前目录中没有世界模型方法 Skill。
- 因两边现有 Skills 都服务于治理产品，把方法 Skill 加入哪一包会改变维护与发布边界。当前扫描只是路径事实，未在下游写入，也没有把其他工作区状态混入目标状态。
