# I-001 · H1/H2/H3 局部支持判据候选（待裁决）

> 本候选承接已选的 A 档工作量、组合观察项、声明范围充分性和分立 H 检验单元。用户已选择路径 A（Root `D-011`）：执行前须由创作者书面登记该测试单元的局部规则；此项不指定问题或样本内容，不使用 Root `D-008` / `E-016` 的黑箱探针材料，也不授权试验。

## 共同结果规则

- 每项结论都只覆盖预先声明的局部主张，H1/H2/H3 分开判定。
- `supported`：该局部主张的全部预注册必要条件均有可核对证据。
- `partial`：有支持部分、未支持/未覆盖部分及边界可明确分开。
- `refuted`：发生预先登记、适用于该范围的否决观察；不得把信息不足当否决。
- `insufficient`：必需输入、对照、样本或证据不足以判断；不得补充扩大范围后追认通过。

## H1 · 多机制模型回答明确问题

按已选 A 档，用一个清晰问题、两个分别声明的机制模型，各自检查基线与一项预先声明的条件变化。

- **局部支持候选**：最多四个结果格都能回溯到已声明模型版本、问题输入、状态/参数、适用条件与规则；基线/变化输出符合该模型在执行前写下的条件预测，没有靠未声明前提补成结果。
- **局部/不足处理**：只有部分模型/条件格满足时记 `partial` 并精确标出格子；必要模型、输入或预测未冻结时记 `insufficient`。
- **否决观察候选**：预注册范围中出现模型自相矛盾、条件变化与事先声明的机制预测冲突，或必须事后增加规则才能给出所期望结果。具体严重度及“自相矛盾”判别须在冻结稿中落成可核对项。

## H2 · 身份/情景澄清相对直接整理的增益

只对一个在运行前确认确需澄清的问题比较两条路径，保持原问与已知信息相同。

- 两路输出均须保留到原问的映射；身份/情景路径不得丢失原问约束或增加无来源前提；额外步骤、问题数和人时须记录。
- **定性门槛候选**：身份/情景路径至少揭示一项对原问裁决确有影响、而直接路径未揭示的条件/缺失输入/可求解子问；并且创作者明确记录此增益是否值得额外步骤。只有两项都成立才考虑该局部范围 `supported`。
- 没有增量，或综合时丢失必要约束，按预注册否决观察决定 `refuted` / `partial`；问题是否需要澄清、同信息比较或代价记录缺失时为 `insufficient`。
- 是否要求数值化“值得”的阈值仍待裁决；不得用未经预注册的复杂度、效用分数事后调节结论。

## H3 · 有界抽样对冷启动的贡献

按 A 档，在一个事先封闭的抽样框中最多检查三条身份→情景→问题链，记录到达的能力需求、初始模型集合及未覆盖项。

- **定性门槛候选**：每条样本链都可追溯至其所需能力并映射到“初始模型可处理”或“明确缺口”；至少一条样本可由初始模型集合启动回答，且遗漏/未知有明确记录，才对这一抽样框的“能启动并显露边界”作局部 `supported`。这不表示覆盖全部样本或完整世界。
- 若部分链具可追溯映射或仅部分满足启动要求，记 `partial`；若三条链都不能在声明范围内启动初始模型，且属于预登记否决观察，则可 `refuted`；采样框、链条或启动标准缺失则为 `insufficient`。
- “足以启动”的最小模型/能力条件、是否必须逐链可回答及关键遗漏定义仍待裁决。
