# H1/H2/H3 有界检验单元结构候选（待裁决）

> **非冻结候选**：承接 D-002 的路线、用户选择的组合观察项（D-005）和按声明范围判充分（D-006）。本稿只讨论 H1/H2/H3 的检验单元共享还是分立；不选现实问题/案例、样本、范围数值或证据阈值，不授权执行、测试、试验、复验或替代验证。下游仍绑定上游 v0.6.1，I-002 继续 open。

用户于 2026-09-30 选择“共享背景、分立单元”作为后续澄清基础（Root `D-007`）。本选择仅确定组织方式，不指定实际共享背景或案例，不构成使用授权。

## 1. 各 H 所需的不同检验单元

- **H1 · 机制模型求解**：一个边界清楚的客观问题单元，声明所用模型、模型版本、状态/参数、条件与精度，记录规则到输出的推导及预先选定的条件变化/反例。
- **H2 · 身份/情景转译**：一个确实需要澄清的模糊问题单元；对同一原问分别记录身份/情景路径与直接「对象—条件—所求结果」路径，并核对是否保留原问意图、减少缺失输入或改善可求解性。
- **H3 · 冷启动覆盖**：一个预先限定的身份/情景采样框；记录所采样问题、它们需要的能力，以及初始模型集合是否达到事先约定的启动标准。它不是单一问句的结果检查，也不证明完整覆盖。

任何共享源材料若不能满足对应 H 的输入特征（例如清晰问题不能测试 H2 的澄清增益），该材料不得被计作该 H 的检验单元。共享背景也不等于共享判据或证据；每个 H 仍须单独报告 `supported` / `partial` / `refuted` / `insufficient`。

## 2. 互斥的检验单元组织路径

1. **已选择：共享有界背景、分立 H 检验单元（AI 推荐）**：若用户最终选择的一个消费方问题背景同时包含合格的清晰问题、需澄清的问题和有限采样入口，则可在相同背景下派生不同 H 的单元；各 H 各自登记输入、判据与结果，不要求同一问句覆盖全部 H。优点是语境一致、减少范围扩散；风险是一个背景可能无法为每个 H 提供有效单元，H3 也仍须独立采样。
2. **未选：各 H 分立问题/样本组**：为每个 H 单独挑选最适合其观察项的问题/样本范围。优点是更容易隔离不同假设，避免一个问题形状迁就所有 H；风险是要准备多组输入与证据，案例选择和资源成本较高，仍须分别满足 `I-002` 与授权。
3. **未选：暂不确定组织方式**：继续保留 H 的独立判据模板，等 `I-002` 案例选定后再判定可否共享背景。优点是不预判案例适配；风险是 R1 的检验范围与资源计划无法完整冻结，R2 继续不得启动。

## 3. 不随路径变化的门禁

- `I-002` 仍 open：任何真实案例的选定、用途范围和使用授权须书面完成；此候选本身不构成选择或授权。
- 每个 H 的声明范围须预先固定，局部 `supported` 不外推到未覆盖的更广范围；共享背景不合并 H 的结果。
- 若共享背景无法产生某 H 所需的有效问题形状，应标明该 H 无合格检验单元，而不是把其他 H 的证据转借过去。
- 具体问题、样本数量、阈值、精度、停止/复验/替代规则、限额、责任与工具边界仍按 `I-001` / `I-003` 逐项裁决；未经冻结不得试验。
