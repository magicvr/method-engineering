## A-002 · R1 / I-003 门禁合理性独立审计（2026-09-30）

- **source**：independent
- **auditor**：独立 Reviewer 子代理 `r1_gate_audit`（`gpt-6.1-sol` / high）。工具未提供完整角色适配器；已显式应用 Reviewer 配置中的模型与 effort，并按只读任务执行，审计期间未写入其他文件。
- **类型 / scope**：design-plan；workspace-003 Root 的 R1/I-001/I-003 阶段门禁、VP-003 判据 3、当前 v0.6.2 R1 提案及下游 WRK-002 交接材料。用户明确说明上游与下游由同一维护人维护；下游《澄清与授权》亦记录“两仓维护人为同一人”。
- **verdict**：fail

### 范围与区间

只读审查 R1 退出条件、I-003 与 R2/R3 的依赖顺序、I-001 预登记字段的阶段归属，以及书面确认要求。用户要求不设置同一维护人之间的形式确认门禁，并避免以 R2/R3 产物作为 R1 前置条件。本审不验证 H1/H2/H3，也不裁定实际 Skill 是否应立即实现。

独立审查依据包括：`00-meta.md`、decision/execution/audit 索引及相关 D/E、v0.6.2 提案与未决清单、I-001/I-003 候选、P-003～P-005、VP-003、下游 exchange/README 与 WRK-002 需求、授权和澄清材料。A-001 只审过较早的路线图设计，不覆盖后来加入的具体 I-003 门禁。

### Findings

#### F-001 · required · BLOCKER · open · 关联 I-003：重复使用价值证据可能形成 R1→R2/R3 循环

- **证据**：`00-meta.md` 规定 R1 先于 R2/R3；R2d 才形成暂定方法工作版。I-003 未决清单却把“方法工作版承载的具体重复协作任务、可核对实践依据及工具价值”列为 required，并要求 R1 前确认。v0.6.2 也称重复使用价值尚未成立、相关实践依据待确认。
- **影响**：若所需价值证据依赖待形成、待使用的方法工作版或 Skill，则需要先越过 R1 才能取得的证据，反过来成为退出 R1 的条件。现稿未写清可用的既有证据、证据不足时的条件冻结路径或后续验证点，因而无法保证无循环。
- **建议**：R1 冻结工具决策规则、允许边界、最小能力、价值判定标准与后续验证时点；R2/R3 实际产生的使用证据只影响后续是否形成/启用 Skill，不阻断方法验证本身。若能提供既有重复实践，可作为 R1 的当前证据；若没有，就按预先冻结的触发条件延期，不得伪装成已验证或无限期卡住 R1。

#### F-002 · required · MAJOR · open · 关联 I-003：R3 实现细节同时被列为 I-003/R1 关闭条件

- **证据**：I-003 候选的已选路径写明源位置、名称和安装操作在 R3 实现前确定；同一候选又把源路径/名称、具体接口、持久化及安装细节列为关闭 I-003 的待冻结内容。未决清单将这些内容纳入 R1 的 I-003 阻断项；路线图则规定工具实现等待方法接口稳定。
- **影响**：同一事项既被允许在 R3 确定，又被要求在 R1 退出前确定。接口还可能依赖 R2 形成的稳定方法内容；前置冻结会让 R1 等待后继阶段，或要求基于未验证接口提前实现设计。
- **建议**：R1 只冻结“是否引入、最小功能/权限边界、价值条件和验证方式”；精确 Skill 名称、路径、字段、持久化、安装/更新及实现验收放在 R3 实施前。R3 实施可依赖 R2 产物，不得反向成为 R1 退出条件。

#### F-003 · required · MAJOR · open · 关联 I-001：R2a 运行前登记细节被混入 R1 关闭条件

- **证据**：Root 将 H1/H2/H3 的具体问题、输入输出、样本、正反例和预注册判据操作化列为 R2a；I-001 却将具体局部主张、输入/样本、严重度、责任和完整预登记列为 R1 关闭待办。预登记工作表自身只要求相关字段在每次运行前填写，并未要求全部在 R1 完成。
- **影响**：R1 协议级冻结与 R2a 每次试验的运行级预登记没有清楚分界，容易把尚未进入的具体试验工作提前变成 R1 门禁，也难以判定进入 R2a 的条件。
- **建议**：R1 冻结有限范围、预算、判据制定/记录规则、停止与变更控制，以及 R2a/R2b 的先后门槛；R2a 再为具体试验填问题、模型/版本、样本、逐项预测和局部判据；将“预登记完整”设为 R2b 开跑门禁。I-002 继续独立控制真实案例及其授权。

#### F-004 · required · MAJOR · open · 同一维护人仍被写成待“共同维护组”确认

- **证据**：下游 `exchange/WRK-002-world-model-method-and-tools/澄清与授权-2026-09-26.md` 明确记载双仓操作授权及“两仓维护人为同一人”。然而上游 E-006、D-014、I-001/I-003 未决清单仍要求“共同维护组”对完整稿书面确认，并把确认形式/程序列作待办；I-003 后备路径还要求先书面拒绝当前 Skills 候选。
- **影响**：已由同一用户作出的明确选择仍等待未定义的“共同维护组”再次确认，形成无新增信息价值的形式门槛。两仓引用本身是追溯需要，不等于需要两名维护人分别签字或重复审批。
- **建议**：记录并沿用用户已经作出的选择；需要新的范围、预算、授权或工具决策时，用户在上游主记录作一次明确裁决，下游仅同步引用/回执。移除额外的共同维护组签字、确认方式及“必须先拒绝候选”顺序条件。保留实际收件和验收等确实发生在交付后的事实门槛，但不把它们提前到 R1。

### 必改项汇总

- F-001：拆开当前决策与后续价值证据，提供证据缺失时不阻断 R1 的明确分支。
- F-002：把工具概念冻结与 R3 实现细节分期。
- F-003：把协议级规则留在 R1，把具体运行预登记放到 R2a，并设置 R2b 开跑门槛。
- F-004：以同一维护人的单次书面裁决作为决策依据；双仓记录用于追溯，不再要求重复确认。

### 成果（有证据）

- I-002 的真实案例授权位于 R2b 实际使用前，属于必要的案例/权限门禁，不是 R1 死锁。
- I-005 的 H1/H2/H3 证据选路位于 R2c，`insufficient` 阻断 R2d；没有要求 R1 先拿到实验结果，此阶段分配合理。
- I-004 的独立审计要求位于 R4 交付前，不阻断 R1。
- 双仓精确引用已同步；它提供可追溯性，不证明草案接受或冻结。

### 结论与建议

当前 R1 门禁设计不合理，必须整改后才可按该门禁放行。整改对象是信息项的阶段分配、工具价值判断的时序及不必要的形式确认，不是把未知标成已验证，也不改变 R1/R2/R3/R4 的目标顺序。按 `/govern` 响应本条 findings 并修订门禁文档；不得仅保留“共同维护组书面确认”原句作为闭合证据。
