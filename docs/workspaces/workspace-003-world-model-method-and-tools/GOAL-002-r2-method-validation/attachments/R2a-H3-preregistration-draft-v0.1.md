# R2a · H3 冷启动模型形成与能力核对预登记草稿 v0.1.0

> **边界**：本稿汇集 D-004～D-021 已接受的候选路线、链、输入和判据，供创作者复核准确版本并补齐运行责任、隔离、证据、人时和停点。它不是冻结预登记，不含实际问题链、模型条目或运行观察，不授权运行。`H3-SEM-001` 仍为 `required / OPEN`；未关闭前不得最终冻结 H3。

## 1. 目标与判定范围

从空的已登记机制模型集合出发，在封闭的供水站合成框内，依据采样链形成一个参考揭示前冻结的实际纯文本模型集合，再由创作者按冻结判据核对 C-01～C-04。最低模型形成条件、逐链证据映射和关键遗漏规则依 [D-015](../01-decision/D-015-set-h3-minimum-model-startability.md)；形成模型不等于 H3 `supported`。

本轮两条初评组合已选：`H3-01` 值班操作员 × `CTX-017`，三步；`H3-02` 检修员 × `CTX-042`，两步。依 R1，每条尝试链各计 1 格；H3 初评上限 3 格，当前候选占 2 格，剩余 1 格未分配、未授权。H1/H2/H3 共用 9 格和 180 人分钟绝对上限；不得跨 H 转移各自未用格数。结果范围只覆盖冻结的合成框和实际尝试链，不外推到其他角色、情景、设备或一般因果公式。

## 3. 评估端候选参考与能力矩阵

评估候选参考为 `H3-BALANCE@0.2`：仅损失情景每窗潜在减量 1 均匀发生，正常情景无额外下降，且存量不低于零。该扩展与历史离散版 `@0.1` 分开保留。参考的准确文件/版本、来源、完整公式、封存位置、访问权限及揭示责任待创作者固定。参考和下表仅属评估端，不能进入生成输入或取代实际模型形成。

能力边界依 D-007～D-011：C-01 是必须正确遵守的输入/范围前提；C-02～C-04 是核心机制能力。D-021 的下列分类和理由仅为候选，必须结合最终准确快照在问题生成前复核并冻结。`applicable` 仅表示存在核对机会，不代表已观察到模型证据。

| 能力 | H3-01 候选 | H3-02 候选 |
|---|---|---|
| C-01 输入/范围前提 | applicable：三步、无补水 | applicable：两步、无补水 |
| C-02 需求/实际供水 | applicable：步 1 触及供水上限，步 2 由需求限制，步 3 由步初库存限制 | applicable：含需求主导和需求/上限相等的输入；不触及库存绑定 |
| C-03 供水后情景变化 | applicable：前两步为无额外下降的负对照；第 3 步仅用于 C-02 | applicable：有供水后下降及非零存量归零的候选核对机会；不识别一般因果公式 |
| C-04 状态承接 | applicable：核对三步状态更新与承接 | applicable：核对两步状态更新与承接 |

H3-01 三步、H3-02 两步的长度不对称须在链级解释及集合汇总中明确，不按步数加权。逐格矩阵的冻结理由、非直接矛盾的链间冲突处理、证据可靠性边界、严重度及是否报告链级标签尚待创作者填写。

## 4. 模型形成、记录与汇总规则

参考揭示前须由采样链实际形成至少一个非占位纯文本模型条目；每个纳入集合的条目均须可定位 R1 §2 的 12 类最低信息，不适用项注明理由；至少一条可追溯的具体关系连接状态/输入、规则/约束、输出/状态变化及适用范围/次序，并指回本轮链证据。问题列表、能力列表或事后参考比较本身不证明模型已形成。

每条尝试链 × 每项 C-01～C-04 留存：冻结输入/快照版本、运行上下文、运行前适用性及理由、链原始证据、冻结模型条目段落、运行后证据状态（`represented` / `explicit-gap` / `not-elicited` / `contradicted`）、评估理由及可复核的工具输入/输出。适用性与实际证据状态分轴记录；不得根据输出事后修改适用性。模型集合标签依 D-007～D-011：有可核对核心矛盾或错述 C-01 时 `refuted`；无矛盾但核心不可评且影响总体判断时优先 `insufficient`；核心均可评而集合仍有核心缺项时 `partial`；仅在范围内覆盖 C-02～C-04、有可追溯证据且符合 C-01 时 `supported`。单链未触及不自动判失败；最终集合可补足的中间 `explicit-gap` 不自动降级。
