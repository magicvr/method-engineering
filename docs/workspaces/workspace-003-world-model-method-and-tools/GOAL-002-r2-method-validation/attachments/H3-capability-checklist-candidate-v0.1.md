# H3 · 首版模型与能力逐项核对候选 v0.1

> **局部边界、汇总优先级、逐链适用性/证据分轴规则及两条初评组合已选择；具体输入与矩阵仍待填写，不构成冻结预登记或运行授权。** 用户已选择可审查的纯文本机制模型条目和逐项能力核对（D-005）；接受 R1 §2 的 12 类最低字段信息（D-006）；将 C-02～C-04 设为核心机制能力、C-01 设为须遵守的输入/范围前提并接受本稿初步 H3 标签边界（D-007）；选定最终预登记所选链共同形成的冻结模型集合为最终 H3 标签单位，保留逐链证据，单链未触及不自动算失败（D-008）；若某链的 `explicit-gap` 在冻结前由集合其他条目补足，不自动降为 `partial`（D-009）；全链未触及且集合无可评证据、导致整体无法可靠判断时为 `insufficient`（D-010）；任一核心能力不可评且影响整体结论时优先 `insufficient`，`partial` 仅适用于核心均可评但最终集合仍有缺项，可核对的核心矛盾仍为 `refuted`（D-011）；运行前逐链按冻结输入登记是否适用及理由，运行后另记实际证据状态，不能事后改适用性（D-012）；`H3-01` 值班操作员×`CTX-017` 与 `H3-02` 检修员×`CTX-042` 已选为两条初评组合（D-013）；H3-01 的第一步需求5/实际供水4及相应水位轨迹已选为待审定候选片段（D-014）。准确完整输入、具体矩阵、严重度及执行字段仍待完成。

## 1. 评估边界

此表供**评估端**在问题链与首版模型集合完成并在参考揭示前冻结后使用。下方能力项源自合成参考候选 `H3-BALANCE@0.1`，用于揭示后核对；不可放入生成上下文、提示或可见输入，也不构成 H3 生成端模型的预置答案。用户已选两条初评组合（D-013），准确角色可见输入与逐链适用性矩阵仍未冻结；没有真实问题链、模型条目、能力命中或观察结果。

能力项只描述本次封闭的两步供水站框，不外推到其他设备、情景、角色或完整世界。用户按 [D-007](../01-decision/D-007-set-h3-core-capability-boundaries.md) 确定 C-02～C-04 为核心机制能力，C-01 为必须正确遵守的输入/范围前提，而非单独的机制能力项。评估时，文本表述、正确推导或适当计算都可作为机制证据；是否使用计算工具由证据需求决定，不能仅凭工具使用本身判通过。

## 2. 首版纯文本模型条目的字段候选

以下 12 类信息来自已冻结的 R1 v0.6.4 §2「模型条目最小结构」契约，用户已按 [D-006](../01-decision/D-006-accept-r1-model-entry-fields-for-h3.md) 选择全部作为 H3 首版条目最低内容。无须使用这些字段名作为固定标题，但每类信息均须能从纯文本中定位；确实不适用时写明 N/A 及原因。可用简洁文字填写；不要求可执行、数值化或形式化。

| 最低字段信息 | 条目要表达的内容 |
|---|---|
| 问题类别 | 此模型裁决哪类客观世界问题。 |
| 现有模型不足 | 初始为空模型时，说明待形成何种裁决能力；不得伪称已存在模型。 |
| 前提 / 参考 | 所依赖的明示条件、假设与参考来源。 |
| 状态输入 | 机制运行所需的初始状态、需求、情景或参数。 |
| 机制输出 | 状态如何变化、输出如何得到；可用可审查的文字关系表达。 |
| 适用范围 | 适用的角色/情景、时间步与明确边界。 |
| 精度 | 输出能支持的精度、范围或不确定程度；未知应明示。 |
| 组合 | 本机制与其他规则/步骤如何共同作用及次序。 |
| 拒绝条件 | 何种输入不适用、矛盾或不足时不作确定裁决。 |
| 反例 / 条件变化 | 可用于检查模型的反例，或条件变化时机制结果应如何变化。 |
| 版本 | 可追溯的条目标识与版本。 |
| 创作者裁定 | 区分模型描述、证据、AI 建议与创作者最终判断。 |

## 3. 评估端能力清单候选

以下均为揭示后对照 `H3-BALANCE@0.1` 的核对项草案。用户已定 C-02～C-04 为核心机制能力、C-01 为输入/范围前提；清单是否还需增加能力项及遗漏严重度仍待创作者裁定。文本可以准确表达等价规则；如果文本不足以支持核对，可以按证据需要使用数学推导、数值计算、统计、程序核验或模拟。

| ID | 机制能力候选 | 参考核对点（仅评估端） | 关键性 / 标签影响 |
|---|---|---|---|
| C-01 | 状态与步界 | 区分每步开始/结束存量；遵守两步范围且没有补水。 | 输入/范围前提；须正确遵守，不单独计作机制能力覆盖。 |
| C-02 | 需求与实际供水 | 区分需求和实际供水；实际供水受需求、每步上限 4、步初存量共同约束。 | 核心机制能力；缺项 `partial`，直接矛盾 `refuted`。 |
| C-03 | 供水后的情景损失 | 区分正常/损失情景；损失仅在供水后计入，且不能超过供水后的剩余存量。 | 核心机制能力；缺项 `partial`，直接矛盾 `refuted`。 |
| C-04 | 状态转移与两步组合 | 用正确次序从步初状态推到步末状态，再把步末状态作为下一步输入；不重复扣减或遗漏损失。 | 核心机制能力；缺项 `partial`，直接矛盾 `refuted`。 |

角色掌握信息与客观状态是输入边界，不另算机制命中。若需判断问题链是否暴露了某项能力，须分别记录该链是否触及、实际条目是否表达，不能把“未触及”直接算成模型失败。

## 4. 逐链记录结构候选

对每条已尝试链、每个 C 项分别留证：

| 字段 | 候选取值或记录 |
|---|---|
| 链 ID / 运行快照 | 精确输入版本及执行上下文标识。 |
| 能力项 | C-01～C-04；若创作者修改清单，使用冻结版本。 |
| 适用性（运行前） | `applicable` / `not-applicable`；按冻结链输入和任务范围说明理由。该矩阵只用于评估，不能传给生成端，且不能根据输出/参考事后更改（D-012）。 |
| 链证据 | 链中提到、推导或没有触及该能力的原始证据位置。 |
| 冻结模型条目证据 | 参考揭示前模型条目版本及相应段落。 |
| 实际证据状态（运行后） | `represented`（明确表达或可核对推导）/ `explicit-gap`（明确承认缺口）/ `not-elicited`（链未提供判断证据）/ `contradicted`（冻结模型主张与参考不兼容）。 |
| 评估理由与工具 | 简述比较过程；若使用数学/计算/统计/程序核验/模拟，链接输入、输出及可复核证据。 |

适用性与实际证据状态是两轴记录：前者须在运行前基于冻结输入定下，后者在运行后按实际材料记录；`not-applicable` 只排除该链对此项的证据，不排除该核心能力。状态不会单独决定 H3 汇总标签。`explicit-gap` 与 `not-elicited` 必须区分：前者是已显露的缺口，后者不能单独证明能力缺失。

## 5. H3 标签边界与已接受的集合级优先规则（D-007～D-011）

以下边界已依 D-007～D-011 接受；最终标签以所选链共同形成的冻结模型集合为判定单位，逐链映射证据留存（D-008）。链上明确缺口若在参考揭示前由冻结集合补足，不自动降级（D-009）。所有适用链均未触及某核心能力且集合无可评证据、影响整体判断时标 `insufficient`（D-010）；混合可评/不可评时按 D-011 处理：

- `refuted`：有可核对的冻结模型集合与任一核心机制能力 C-02～C-04 直接矛盾，或错误表述 C-01 输入/范围前提；该结论优先于其他核心项的不可评证据（D-011）。
- `insufficient`：无上述可核对矛盾时，参考揭示前没有可审查的实际模型集合、证据污染/必要输入缺失使判据无法可靠应用，或任一核心能力不可评且影响整体判断；包括所有适用链均未触及某核心能力且集合无其他可评证据的情况（D-010、D-011）。
- `partial`：所有核心能力均可评，但 C-02～C-04 至少一项在最终集合中仍未覆盖/未补足；没有核心机制矛盾，且 C-01 未被错述（D-011）。
- `supported`：参考揭示前形成并冻结的模型集合在所测范围内覆盖 C-02～C-04，相关逐链证据可追溯且模型集合无矛盾，并正确符合 C-01 前提。

逐链证据映射与留存是必需的；单条链未触及某项能力不自动导致整体失败（D-008）；中间 `explicit-gap` 若在冻结前被集合补足也不自动降级（D-009）。混合可评/不可评的总体优先级已由 D-011 裁定；逐链适用性与实际证据分轴规则已由 D-012 裁定。仍须在正式预登记中填入适用性矩阵及理由、逐链→模型/缺口映射、非直接矛盾的链间冲突处理、证据可靠性边界、严重度及是否另报链级标签。所有结论仅覆盖冻结的合成抽样框与实际尝试链。
