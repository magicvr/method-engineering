# H3 · 首版模型与能力逐项核对候选 v0.1

> **待创作者裁定；不构成冻结判据或运行授权。** 用户已选择可审查的纯文本机制模型条目作为 H3 最低产物类型，并选择能力清单逐项核对作为判定基础（D-005）。本稿提供可复核候选，具体必填字段、能力项、关键遗漏与汇总标签尚未接受。

## 1. 评估边界

此表供**评估端**在问题链与首版模型集合完成并在参考揭示前冻结后使用。下方能力项源自合成参考候选 `H3-BALANCE@0.1`，用于揭示后核对；不可放入生成上下文、提示或可见输入，也不构成 H3 生成端模型的预置答案。两条身份—情景链仍只是候选安排；没有真实问题链、模型条目、能力命中或观察结果。

能力项只描述本次封闭的两步供水站框，不外推到其他设备、情景、角色或完整世界。评估时，文本表述、正确推导或适当计算都可作为机制证据；是否使用计算工具由证据需求决定，不能仅凭工具使用本身判通过。

## 2. 首版纯文本模型条目的字段候选

以下 12 类信息来自已冻结的 R1 v0.6.4 §2「模型条目最小结构」契约，用户已按 [D-006](../01-decision/D-006-accept-r1-model-entry-fields-for-h3.md) 选择全部作为 H3 首版条目最低内容。无须使用这些字段名作为固定标题，但每类信息均须能从纯文本中定位；确实不适用时写明 N/A 及原因。可用简洁文字填写；不要求可执行、数值化或形式化。

| 最低字段信息 | 条目要表达的内容 |
|---|---|
| 问题类别 | 此模型裁决哪类客观世界问题。 |
| 现有模型不足 | 初始为空模型时，说明待形成何种裁决能力；不得伪称已存在模型。 |
| 前提 / 参考 | 所依赖的明示条件、假设与参考来源。 |
| 状态输入 | 机制运行所需的初始状态、需求、情景或参数。 |
| 机制输出 | 状态如何变化、输出如何得到；可用可审查的文字关系表达。 |
| 适用范围 | 适用的角色/情景、时间步与明确边界。 |
| 精度 | 输出能支持的精度、范围或不确定程度；未知应明示。 |
| 组合 | 本机制与其他规则/步骤如何共同作用及次序。 |
| 拒绝条件 | 何种输入不适用、矛盾或不足时不作确定裁决。 |
| 反例 / 条件变化 | 可用于检查模型的反例，或条件变化时机制结果应如何变化。 |
| 版本 | 可追溯的条目标识与版本。 |
| 创作者裁定 | 区分模型描述、证据、AI 建议与创作者最终判断。 |

## 3. 评估端能力清单候选

以下均为揭示后对照 `H3-BALANCE@0.1` 的候选核对项。文本可以准确表达等价规则；如果文本不足以支持核对，可以按证据需要使用数学推导、数值计算、统计、程序核验或模拟。清单是否完整、哪些项是关键能力、遗漏的严重度均待创作者裁定。

| ID | 机制能力候选 | 参考核对点（仅评估端） | 关键性 / 标签影响 |
|---|---|---|---|
| C-01 | 状态与步界 | 区分每步开始/结束存量；遵守两步范围且没有补水。 | 待创作者裁定 |
| C-02 | 需求与实际供水 | 区分需求和实际供水；实际供水受需求、每步上限 4、步初存量共同约束。 | 待创作者裁定 |
| C-03 | 供水后的情景损失 | 区分正常/损失情景；损失仅在供水后计入，且不能超过供水后的剩余存量。 | 待创作者裁定 |
| C-04 | 状态转移与两步组合 | 用正确次序从步初状态推到步末状态，再把步末状态作为下一步输入；不重复扣减或遗漏损失。 | 待创作者裁定 |

角色掌握信息与客观状态是输入边界，不另算机制命中。若需判断问题链是否暴露了某项能力，须分别记录该链是否触及、实际条目是否表达，不能把“未触及”直接算成模型失败。

## 4. 逐链记录结构候选

对每条已尝试链、每个 C 项分别留证：

| 字段 | 候选取值或记录 |
|---|---|
| 链 ID / 运行快照 | 精确输入版本及执行上下文标识。 |
| 能力项 | C-01～C-04；若创作者修改清单，使用冻结版本。 |
| 链证据 | 链中提到、推导或没有触及该能力的原始证据位置。 |
| 冻结模型条目证据 | 参考揭示前模型条目版本及相应段落。 |
| 映射状态 | `represented`（明确表达或可核对推导）/ `explicit-gap`（明确承认缺口）/ `not-elicited`（链未提供判断证据）/ `contradicted`（冻结模型主张与参考不兼容）。 |
| 评估理由与工具 | 简述比较过程；若使用数学/计算/统计/程序核验/模拟，链接输入、输出及可复核证据。 |

状态是逐项观察记录，不自动决定 H3 汇总标签。`explicit-gap` 与 `not-elicited` 必须区分：前者是已显露的缺口，后者不能单独证明能力缺失。

## 5. H3 汇总标签候选（未接受）

下列只是供裁决的边界草案；须先决定关键能力与最低覆盖，才能在最终预登记中实例化：

- `supported`：参考揭示前形成并冻结的模型条目满足全部预先标记为必需的能力项，相关链证据可追溯，且没有必需项被矛盾证据否定。
- `partial`：已形成可审查模型条目并满足部分必需能力项，但至少一项必需能力仍为明确缺口或未覆盖；没有足以否决主张的必需项矛盾。
- `refuted`：冻结模型在至少一个由创作者事先标记为关键的机制能力上作出可核对的相反主张，或触发另一个创作者预先声明的否决条件。
- `insufficient`：揭示参考前没有实际模型条目，或污染、链缺失/输入不足等使已登记判据无法可靠应用。单纯 `not-elicited` 是否导致本标签取决于覆盖规则，不能自动判成失败。

创作者仍须决定哪些 C 项关键/必需、是否所有关键项都必须覆盖、`explicit-gap` / `not-elicited` 如何影响结果、何种矛盾足以 `refuted`、严重度及是否需每条链分别给标签。所有结论仅覆盖冻结的合成抽样框与实际尝试链。
