# R2a · 假设操作化准备方案 v0.1.6

> **状态与边界**：这是把已冻结的 R1 协议转换为 R2a 准备步骤的工作稿，不是任何 H 的逐次运行预登记，也不授权运行、复验或替代方向验证。用户已按 [D-003](../01-decision/D-003-select-synthetic-package-preregistration-baseline.md) 选择 [H1/H2/H3 合成候选包](R2a-H123-synthetic-candidate-pack-v0.1.md) 的基线结构继续补齐正式预登记；准确输入、预测、局部判据/严重度、责任、预算/停点、最终冻结及运行授权仍待逐项完成。

**依据**：父目标 `GOAL-001-world-model-method-and-tools` 的 R2 路线、I-002 / I-005 信息门禁、D-016、冻结协议 [v0.6.4](../../GOAL-001-world-model-method-and-tools/attachments/R1-freeze-proposal-v0.6.4.md)。既有 [R1 预登记工作表候选](../../GOAL-001-world-model-method-and-tools/attachments/R1-I001-H123-preregistration-worksheet-candidate.md)只作字段结构参考；其空白或历史版本不能替代本目标具体、冻结的预登记。

## 已选 R2d 探针与 R2a 的边界

用户提供的准确问题“世界有多大”已按 [D-002](../01-decision/D-002-reserve-r2d-full-method-blackbox-probe.md) 预留为 R2d 单次完整方法黑箱核对，并明确禁止围绕该题设计或定制方法、工具。因此本题不用于本准备方案、H1/H2/H3 操作化或 R2c 选路；下方 H 单元仍须另行选择与预登记。旧 Root D-008 修真问题的来源、哈希与授权不沿用。

先行 H 证据须完成 R2c 选路、满足 Root I-005 对进入 R2d 的要求；其后形成并冻结通用方法版及通用判据，再输入本题。核对允许澄清或信息不足；运行前须登记有限的人工作业预算/截止点及通用终止条件，当前具体预算和截止点未定，达到任一停点即记录并停止。不预设数值答案，不据本题临时补造或调参。本题不自动构成 H 证据或 R4 用例；若实际用于 H 可行性评价，计入 R1 对应 H 格数及累计 9 格 / 180 人分钟上限，不能借 R2d/R4 绕限额。Root I-002 仍 open；R4 复用须另行复核最终版适配性与授权。

## 已冻结的工作约束

- H1 最多 4 格、H2 最多 2 格、H3 最多 3 格；各 H 不转移未用格数。初评、符合条件的至多一次定向复验、至多一个替代方向的一次验证，共用最多 9 个累计结果格。已尝试后输入不足或中途停止的单元也计格。
- H 可行性工作累计最多 180 人分钟，覆盖 R2a 预登记、准备、执行、评估、记录与允许的复验/替代。多人按各人实际投入相加；无人值守等待不计。逐人登记实际活动与分钟；本准备方案不估算或虚构人工耗时，也不把 AI 时间换算为人时。
- 不增加付费 API、服务或工具。额度是上限，不等于必须用满，也不等于预先授权运行、复验或替代方向。
- H1/H2/H3 分别登记、分别判定，不设跨 H 总分，不把局部证据外推为普遍有效。结果只用 `supported` / `partial` / `refuted` / `insufficient`。
- 创作者在运行前书面给出各单元最终的局部主张、支持/否决条件及严重度判断；AI 可提出建议与反例，但不代替创作者结论。

## 分假设操作化清单

### H1 · 多机制模型求解

冻结结构：一个清楚问题、两个运行前声明的机制模型、基线与一项条件变化，最多 4 格。

运行前需要补齐：

1. 明确客观问题、所求结果及适用范围。
2. 选择两个机制模型及其版本；明确必要状态、参数、时空切片与输入来源。
3. 固定基线与唯一条件变化，写出四格逐格预测。
4. 创作者写明可核对的支持证据、partial 分界、否决观察及严重度；区分矛盾、输入不足与无法裁决。
5. 记录必要模型接口、客观状态与角色可知信息的边界，以及每格证据落点。

### H2 · 身份/情景转译

冻结结构：只选一个运行前确需澄清的问题；使用完全相同的原问和已知信息，对比身份/情景路径与直接「对象—条件—所求结果」路径，最多 2 格。

运行前需要补齐：

1. 说明为何该问题达到预先声明的「确需澄清」条件。
2. 固定原问、约束与两路径共用的信息快照。
3. 写明身份/情景路径、直接路径的记录形式和原问答案映射核对方式。
4. 创作者书面定义何种新增信息会改变原问裁决，并判断该局部增益是否值得额外步骤；不事后增加效用分数或复杂度阈值。
5. 预先处理约束丢失、无决策相关增益、输入不足及创作者判断不确定的情况。

### H3 · 有界冷启动抽样

冻结结构：先封闭一个有来源、范围和排除项的抽样框；最多 3 条身份→情景→问题链，不外推到完整世界或总体覆盖。

**H3-SEM-001（required / OPEN）仍阻断 H3 正式预登记最终冻结。** 用户已按 [D-004](../01-decision/D-004-select-h3-form-first-model-set-from-zero.md) 选择从零形成实际首版模型，并在隐藏评估参考揭示前冻结产物；两链安排仅作基线。按 [D-005](../01-decision/D-005-define-h3-text-model-and-checklist-basis.md)，首版最低产物类型为可审查的纯文本机制模型条目；分析手段按证据需要选择；能力清单逐项核对是后续映射/遗漏/局部判据的起草基础。按 [D-006](../01-decision/D-006-accept-r1-model-entry-fields-for-h3.md)，R1 v0.6.4 §2 的 12 类条目信息均为最低内容。初稿见 [H3 能力清单候选 v0.1](H3-capability-checklist-candidate-v0.1.md)，供创作者审定，不可提供给生成端。能力项、最低覆盖、关键遗漏与标签边界仍待创作者裁定（登记见 [D-003](../01-decision/D-003-select-synthetic-package-preregistration-baseline.md)）。[Root D-011](../../GOAL-001-world-model-method-and-tools/01-decision/D-011-select-checklist-creator-judgment.md) 要求这些局部规则在执行前定义；[R1 判据候选](../../GOAL-001-world-model-method-and-tools/attachments/R1-I001-H123-acceptance-criteria-candidate.md) 的额外“至少一条样本可回答”门槛未被接受。问题清单或事后参考比较不能单独证明模型形成；路线选择未形成实际产物、未冻结预登记或授权运行。

运行前需要补齐：

1. 固定抽样框、来源、排除项及封闭时间。
2. 按已选从零路径登记生成端空初始机制模型集合及版本、由采样链形成实际首版模型的程序及产物冻结/留证要求，以及独立评估参考（先登记、后揭示）；实际首版模型必须在揭示参考前冻结。
3. 按 [D-005](../01-decision/D-005-define-h3-text-model-and-checklist-basis.md) 与 [D-006](../01-decision/D-006-accept-r1-model-entry-fields-for-h3.md) 使用已接受的纯文本模型条目类型和 R1 §2 的 12 类最低字段信息，再由创作者定义「足以启动」的能力条件、每条链到能力/模型或明确缺口的映射方式，以及关键遗漏的记录方式。文本模型条目不要求可执行、数值化或形式化；分析手段按证据需要选择。
4. 预先说明抽样和停止规则、局部支持/partial/否决判据、输入不足处理。
5. 明确结果只适用于该封闭抽样框，不声称身份/情景组合有限穷尽或覆盖完整世界。

## 共用预登记与运行前检查

每个测试单元各自记录：预登记版本及冻结时间；局部主张与边界；H 单元与共同背景 ID；输入来源、版本、用途与权限；创作者/判据作者、运行者、评估者、记录者；模型/样本与预测；结果标签适用范围；证据存放位置；人时预算、当前累计格数；停止、偏离与暂停裁决规则。

运行前逐项确认：

- 该单元所需字段已填，不以空白或默认值代替。
- 局部裁决规则和预测在运行前冻结，且能被事后独立核对。
- 当前累计格数与逐人累计人时在 R1 限额内，为评估和记录留有额度。
- 输入、用途及权限适用；如为真实案例，案例、范围和授权已有维护人明确书面选择，且已关闭父目标相应 I-002。
- 未把 Root D-008 / E-016 的 R1 草案黑箱探针授权外推为 R2b/R4 方法检验授权。
- 预注册否决、必要输入缺失、证据不足、限额到达或需改变范围/授权/预算时，清楚知道停止并回到用户裁决的触发点。
