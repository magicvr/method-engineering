# R2a · H2 身份/情景澄清对照预登记草稿 v0.1.1

> **边界**：本文件整理已接受的候选输入与判据，供创作者补齐正式逐次预登记。它不是已冻结的预登记，不记录运行结果，也不授权开始 H2。文件包含隐藏回答卡及评估规则，不能作为路径运行上下文的输入包；冻结后仍须按角色与路径制作隔离材料。

## 1. 目标与范围

比较同一含混原问在两种信息整理路径中的局部表现：

- **H2-01 身份/情景路径**：从请求者身份和所处情景整理缺失信息，再映射回原问。
- **H2-02 直接路径**：按“对象—条件—所求结果”整理缺失信息，再映射回原问。

唯一原问是“这次能供上吗？”。两格必须使用相同原问、已知信息和请求者回应规则。范围只覆盖本合成候选，不推断现实供水或一般方法有效性。依父目标 [D-010](../../GOAL-001-world-model-method-and-tools/01-decision/D-010-select-small-r1-workload-profile.md)，H2 初评计划最多 2 个结果格。R1 冻结协议 [v0.6.4](../../GOAL-001-world-model-method-and-tools/attachments/R1-freeze-proposal-v0.6.4.md) 限制全项目初评、允许复验与替代验证累计不超过 9 格，且 H2 上限覆盖初评与复验。当前初评安排 H1 4 + H2 2 + H3 2 = 8 格；剩余 1 格未分配、未授权。澄清轮数不增加结果格。

## 2. 候选输入与信息隔离

下列内容均为 AI 构造的合成候选。输入基线依 [D-024](../01-decision/D-024-accept-h2-candidate-question-snapshot-and-card.md) 接受，具体字段仍待正式预登记核对。

### 2.1 共用初始快照 `H2-SNAPSHOT@0.1`

1. 水箱容量 10，第一步初始存量 8；共两个运行步，无补水、无其他损失。
2. `H2-SERVICE@0.1` 每步每项请求最多供 4；实际供水为 `min(该步需求, 4, 步初存量)`，供水后扣减；无并发请求。
3. 请求成功表示在请求指定的步完整满足需求，不可延期补齐。
4. 合成请求：R-A（应急取水者）第一步需求 8、第二步需求 0；R-B（常规配送者）两步需求各 4，总需求均为 8。
5. 初始提问未说明“这次”指哪个请求，不得自行选择请求或从两项中任意挑选。

依 [D-026](../01-decision/D-026-accept-h2-question-as-must-clarify-candidate.md)，R-A 对应按时供水答案“不能”，R-B 对应“能”；该差异是候选输入上的筛选推演，不是运行观察或路径效果证据。正式预登记若改动会消除此差异的关键输入，必须重新检查入选理由。

### 2.2 回应规则 `H2-CARD@0.1`

候选隐藏所指为 R-B。下表仅供回应者/记录者使用；不得放入任一路径的起始上下文，也不得向路径运行者透露隐藏选择、另一条路径的材料或候选判断。

| 已识别的提问字段 | 回应候选 |
|---|---|
| 所指请求 / “这次”是哪次 | “指 R-B，常规配送请求。” |
| 请求者身份 | “我是常规配送者，问的是 R-B。” |
| 需求 / 步骤 | “步 1 要 4，步 2 要 4，都要当步供齐。” |
| 完成条件 / 能否延期 | “两步各供齐 4 才算完成，不能延期补齐。” |
| 水箱、能力、补水等快照事实 | 仅重述快照中的对应字段，不新增条件。 |
| 无法识别的模糊问法 | “请说明你要确认的是请求、身份、需求时点还是完成条件。” |
| 快照未提供的外部事实 | “此合成输入未提供该信息。” |

同时询问多个已列字段时按同一回应规则逐项回答；每个提问和回应都须原样保存。每路径最多 2 次额外澄清 exchange、分别计数不转移、合计最多 4 次，依 D-029 接受为候选上限；共同原问不计，每次澄清请求及回应计 1 次，同一消息中的复合提问按 1 次。到限后停止追问并按 D-027 基于现有证据分类。复合/未覆盖问法的回应、异常无回应或传输失败、最终作答夹带新问题等情形仍待创作者在冻结前明确。回应者不得补设定、直接给路径结论或按路径差别化回应。

## 3. 两条路径与原问映射

| 结果格 | 候选记录形式 | 回答原问时的必要核对 |
|---|---|---|
| H2-01 身份/情景 | 从共用快照记录请求者身份、所指请求、相关情景、缺失条件、每次澄清问答及所得可求解子问。 | 说明如何由已澄清请求与供水规则回答原问，核对每步需求、供水时点与完成条件。 |
| H2-02 直接路径 | 从同一快照按“对象—条件—所求结果”记录对象、条件、缺失输入、每次澄清问答及可求解问题。 | 使用同一约束、来源与映射检查回答原问；不要求身份/情景术语。 |

两路径均须保持原问的对象、需求、时点和完成条件；不得换题、使用快照外前提或改变回应卡。身份/情景路径是否取得直接路径未取得的决策相关信息，必须用两边逐项记录作对照，不能从措辞差异推断增益。

## 4. 候选局部判据

依 [D-025](../01-decision/D-025-accept-h2-local-gain-candidate-rule.md)、[D-027](../01-decision/D-027-accept-h2-four-label-candidate-boundaries.md) 与 [D-028](../01-decision/D-028-accept-h2-qualitative-severity-candidate.md)，按以下次序核对。规则仍未冻结。

1. **`insufficient`**：比较记录不完整/不可比，关键输入或答案映射证据缺失，或创作者没有明确判断增益是否值得额外步骤。不得从证据缺失推导失败。
2. **`refuted`**：在完整可评对照中没有身份/情景路径的额外决策相关增益；或该路径破坏原问重要约束/引入无依据前提；或虽有增益，创作者明确判断它不值得额外问答步骤。
3. **`partial`**：完整可评对照显示有创作者认为值得的部分决策相关增益，但仍不足以完整回答原问，且没有重要约束破坏或无依据前提；须列出已取得与仍缺少的信息。
4. **`supported`**：保持原问约束，身份/情景路径取得直接路径没有且足以影响答案的决策相关信息，并由创作者明确判断该增益值得所记录的额外步骤。

不设数值效用分数或阈值，不预设任一路径更优。创作者须在运行前写出对“决策相关”的适用说明、逐格局部主张和可适用的否决观察；其判断与理由均须留证。

### 严重度记录形式

依 D-028，按受影响路径/比较格与偏离性质逐项定性记录，说明其对原问约束、答案或决策相关信息的影响及理由；不另设等级或跨 H 分数。该项只确定记录形式；适用于具体预登记的偏离清单与严重度判断仍待创作者填写。

### 澄清轮数与计数（D-029 已接受为候选，尚未冻结）

用户依 [D-029](../01-decision/D-029-set-h2-clarification-exchange-cap.md) 选择每条路径最多 2 次额外澄清 exchange，两路径分别计数、不转移，总计最多 4 次。共同原问不计；每次澄清请求及回应计 1 次；同一消息同时询问多个字段仍计 1 次，但须记录字段。到达路径上限后不得继续追问，只能基于现有记录作答或报告仍不足，并按 D-027 结合证据和创作者价值判断分类；耗尽次数本身不自动判 `refuted`。该有界选择不证明两轮最优、在预算内可完成或任一路径有优势，也不增加结果格。

仍待正式预登记明确复合/未覆盖问法的回应、没有收到回应或纯传输失败的处理、最终作答含新澄清问题如何计数，以及澄清 exchange 与其他操作步骤如何并行记录。不得把 AI 先前提出但未纳入 D-029 的异常处理建议记作已裁决。
