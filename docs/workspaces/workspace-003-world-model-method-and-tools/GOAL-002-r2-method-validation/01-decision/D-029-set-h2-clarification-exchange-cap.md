# D-029 · 设定 H2 每路径澄清轮数上限

## 用户裁决

2026-10-01，用户选择推荐方案：每条路径最多 2 次额外澄清 exchange；两路径分别计数，不转移，总计最多 4 次。共同原问不计；每次澄清请求及回应计 1 次，同一消息中的复合提问仍计 1 次。到达上限后停止追问，按 [D-027](D-027-accept-h2-four-label-candidate-boundaries.md) 基于现有证据分类。

## 决定与理由

将 H2-01 身份/情景路径与 H2-02 直接路径的澄清预算分别设为 2 次。此上限允许每条路径在第一次回应后进行至多一次针对性追问，并使执行保持有界。所选上限是预登记设计选择，不证明两轮最优、可在现有人时预算内完成，亦不预设任一路径有优势。

澄清轮按一次“请求—回应” exchange 计。将多个已识别字段放在同一澄清消息中，仍占 1 次；须分别记录字段。两条路径各自封顶，未使用次数不能转给另一条。共同原问不计入额外澄清次数。

到达每路径上限后不得继续追问，只能以现有记录作答或报告信息仍不足，并按 [D-027](D-027-accept-h2-four-label-candidate-boundaries.md) 结合比较证据与创作者价值判断分类；耗尽次数本身不自动判为 refuted。计数与停点只定义澄清次数上限，不替代总人时、逐格步骤记录或异常中断处理。

## 后续与边界

本决定仅接受每路径 2 次、计数方式及到限停问候选，不冻结 H2 正式预登记、不授权运行或复验，也不改变 H2 两个结果格、目标状态/进度或父目标门禁。正式预登记仍须写明复合/未覆盖问法、异常无回应/传输失败如何记录、最终作答含新澄清问题如何计数、步骤计数和停止/偏离处理、角色与隔离、证据位置、人时预算及创作者逐格判断。
