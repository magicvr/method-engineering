# D-027 · 接受 H2 四标签候选边界

## 用户裁决

2026-10-01，用户接受推荐版 H2 `supported` / `partial` / `refuted` / `insufficient` 候选边界，并另裁决：若完整对照显示身份/情景路径取得决策相关增益、但创作者明确认为增益不值得额外步骤，标为 `refuted`。

## 候选判定顺序

按以下顺序评估，避免把证据不足与可判反例混为一类：

1. **`insufficient`**：两路径没有可比的完整记录，或关键输入/映射证据缺失；也包括创作者未明确判断增益是否值得额外步骤、因此不能判定其价值。不得因缺少证据默认支持或否决。
2. **`refuted`**：在完整、可评的路径对照中，身份/情景路径没有取得直接路径之外的决策相关增益；或它丢失原问的重要约束/引入无依据前提；或虽有决策相关增益，创作者却明确判断增益不值得额外步骤。上述均是对 H2 局部主张的可判反证。
3. **`partial`**：完整、可评的对照显示身份/情景路径取得了创作者认为值得额外步骤的部分决策相关增益，但仍不足以完整回答原问，且没有重要约束破坏或无依据前提。记录具体已取得与仍缺失的信息。
4. **`supported`**：满足 [D-025](D-025-accept-h2-local-gain-candidate-rule.md) 的全部候选条件：保持原问约束、取得直接路径未取得且足以影响答案的决策相关信息，并由创作者明确判断增益值得实际记录的额外步骤。

判定依赖同一原问与已知信息的公平对照，并保留原问映射、请求/回应、实际问题数与步骤记录；不设数值效用分数或阈值。缺少有效对照或价值判断证据时，先适用 `insufficient`，不从内容缺失推导方法失败。

## 范围与门禁

本决定确定 H2 四标签边界的候选写法，不是冻结登记或路径运行结论。逐次预登记仍需核对这些边界、严重度、记录字段、责任、轮数/停止、预算与偏离处理；没有冻结或运行授权，不改变 H2 两格上限、目标状态/进度或父级门禁。
