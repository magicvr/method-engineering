# D-024 · 接受 H2 候选问题、共用快照与回答卡

## 用户裁决

2026-10-01，用户接受推荐候选：将含混问句、两路径共用的信息快照及请求者回答卡作为继续补齐 H2 预登记的候选输入。全部均为 AI 构造的合成内容。

| 项目 | 接受的候选内容 |
|------|----------------|
| 原问 | “这次能供上吗？”，未说明所指请求，因此不能仅凭初始快照作唯一回答。 |
| 共用初始条件 | `H2-SNAPSHOT@0.1`：容量 10、步 1 初始存量 8、两步、无补水或其他损失；每步本次请求最多供 4，实际供水为 `min(需求, 4, 步初存量)`，供水后扣减；请求须在各自指定步完整满足，不可延期。 |
| 候选请求 | `R-A`：应急取水者，步 1 需求 8、步 2 需求 0；`R-B`：常规配送者，步 1、步 2 各需求 4。 |
| 歧义依据 | 若指 R-A，步 1 最多供 4，不能按时供齐；若指 R-B，两步各供 4、可按时完成。因此该问的候选答案随请求对象变化。此为设计推演，不是运行观察。 |
| 隐藏回答卡 | `H2-CARD@0.1`：候选选择 R-B（常规配送者）；按预定字段统一回应身份/请求、逐步需求、完成/延期条件、已知快照事实、未识别的模糊问法及未提供的外部事实。 |

两条路径从同一快照起步并使用同一回答卡与回应规则。回答卡只交给回应者/记录者，不能进入任一路径初始输入；不得按路径补充不同信息、临场设定或提前给结论。该接受仅针对候选输入及回答卡，不接受 H2 的局部增益/效用判据，也不认定身份/情景路径优于直接整理路径。

## 后续门禁

创作者仍须确认该问是否满足运行前“确需澄清”条件，定义何种新增信息改变原问裁决、增益是否值得额外步骤，并确定复合/模糊问法、轮数与停止处理、两路径约束映射、局部标签/严重度、责任及证据位置。准确运行输入须在预登记中核对并冻结；本决定不授权冻结或运行、不改变 2 格安排及目标状态/进度。
