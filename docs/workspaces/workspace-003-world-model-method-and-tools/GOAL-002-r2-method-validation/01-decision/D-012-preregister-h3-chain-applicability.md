# D-012 · 预登记 H3 逐链能力适用性

## 用户裁决

2026-10-01，用户选择将 H3 的「逐链适用性」和「实际触及/证据状态」分开记录：运行前按冻结的链输入与任务范围，逐条链、逐项 C-02～C-04 记录是否有机会检验该能力，并给出理由；运行后再单独登记该链实际提供的证据状态。

适用性矩阵属于评估端预登记，不得提供给生成端；不得依据生成输出或揭示后的评估参考事后改变适用性。`not-applicable` 只排除该链对此能力的证据判断，不排除该核心能力本身；某核心能力最终不可评且影响整体 H3 判断时，仍按 [D-011](D-011-prioritize-insufficient-over-partial.md) 判 `insufficient`。本决定不要求每条链实际触及每项能力，也不把某条链的 `not-elicited` 单独判为失败。

## 落地与未决范围

正式预登记仍需填入实际链×能力矩阵及每格理由，区分 `applicable` / `not-applicable` 与运行后的 `represented` / `explicit-gap` / `not-elicited` / `contradicted`。具体链输入、适用性单元、能力→模型/缺口映射、非直接矛盾的链间冲突处理、严重度和其他执行字段未因此自动确定。

H3-SEM-001 继续 `required / OPEN`；本决定不授权冻结或运行，不改变目标状态/进度、预算、Root I-002 或 Root I-005。
