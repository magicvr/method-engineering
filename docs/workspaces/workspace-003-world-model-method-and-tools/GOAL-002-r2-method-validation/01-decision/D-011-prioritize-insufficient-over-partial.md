# D-011 · 确定不可评证据优先于部分缺项

## 用户裁决与标签优先级

2026-10-01，用户选择：若 C-02～C-04 中任一核心能力不可可靠评估，且因此影响总体 H3 判断，则总体优先标为 `insufficient`。`partial` 只用于核心能力都可评估、但最终冻结模型集合仍缺少至少一项核心能力的情形。若有可核对的核心机制矛盾，或模型错误表述 C-01 前提，则仍标为 `refuted`，即使其他项存在不可评证据。

合并为下列候选优先级，适用于创作者在运行前登记的证据：

1. 有可核对的 C-02～C-04 矛盾或错述 C-01 → `refuted`；
2. 否则，任一核心能力不可评且影响总体判断 → `insufficient`；
3. 否则，核心均可评但最终集合仍缺能力 → `partial`；
4. 否则，所有核心能力均满足且无矛盾、符合 C-01 → `supported`。

核心不适用与证据覆盖须在预登记中逐项说明，不由 AI 根据运行后结果临时排除。此顺序不改变 D-008 的模型集合级判定单位，也不将中间 `explicit-gap` 自动当作最终缺项；D-009 所述可在冻结前补足。

## 仍待登记与门禁

逐链证据到能力/模型/缺口的精确映射、哪些链适用某能力、证据引用、链间相冲突但不构成明确反命题的处理、严重度及运行前输入/责任/预算/停止/偏离/冻结字段仍待补齐。

H3-SEM-001 继续 `required / OPEN`；完整预登记完成前不得冻结 H3 或运行。此决定不改变目标状态/进度、额度或 Root I-002/I-005。

`insufficient` 的全链未触及规则见 [D-010](D-010-label-unassessable-core-as-insufficient.md)，能力和基础标签边界见 [D-007](D-007-set-h3-core-capability-boundaries.md)。
