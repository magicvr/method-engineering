## 前言

### 本方法是什么

一套**按需增长**的世界模型构建方法：让创作者在遇到关于世界客观规律、客观状态或交互结果的问题时，能判断现有世界模型是否已经能回答；不能时识别所缺的是**状态、组合、精度还是机制**，以最低必要成本补足相应的机制模型，并让这类问题以后能够稳定、可追溯地裁决。

**本方法不要求预先建完整世界。** 最低可用结果是：针对一个真实创作中出现的客观问题，完整跑通「发现能力缺口 → 构建最低充分模型 → 注册能力 → 完成裁决 → 检查 → 返回创作」这一闭环（第 2 章）。

### 执行主体与协作位

- **执行主体是创作者**。世界模型的**主题、取舍与最终裁决属于创作者**。
- **助手不得代劳**：不得在创作者未实际参与判断的情况下确定结论并直接采用；不得用自己产出的判断冒充创作者判断。
- **助手应尽可能协助**：可提供提示、引导、候选方案、示例、追问、反例、检查与整理；对判断点**可以给建议与理由**，但**结论由创作者作出**。
- **界线判据**：助手给建议 + 创作者裁定 = **协助**（允许且鼓励）；助手直接定结论并被采用、或创作者退化为**被动确认** = **代劳**（禁止）。
- 本方法**不以任何 AI 能力为前提，也不禁止使用助手**；验收口径是「创作者能据本方法作出决定并完成闭环，且协作位与留痕清楚」。

### 留痕约定（建议与裁定分开）

| 栏位 | 写什么 |
|------|--------|
| 判断点 | 本章/本步要求作出的决定 |
| 建议 | 助手（若有）给出的候选与理由；无助手时写"无" |
| **裁定** | **创作者**的结论 + 依据 |
| 依据 | 引用的状态、模型、精度、适用条件或条款 |
| 后续责任 | 下一步由谁做什么 |

**禁止**：只有建议没有裁定；裁定栏写"确认"而无实质内容；用建议栏内容当作结论。

### ③ 层「默认设计」的标注约定

本方法区分三件事：**原文硬约束**、**由原文推出的方法要求**、**尚未决定的实现方式**。凡属第三类、本版给出一种可做法的地方，一律以 **〔默认设计〕** 标记，含义是：**可采用，也可替换**——它不是方法要求，替换它不需要改本方法的主干。

- 判断依据：这项做法**是否改变本方法的语义或责任边界**？改变 → 属方法要求；不改变、只关乎承载与形式 → 默认设计。
- 本版全部默认设计见**附录 C**（便于逐项审阅与替换）。

### 明确不主张

- 不主张本方法**普遍有效**；它只声明本轮可用、可检验。
- 不关闭下游承载未知（`U-1`～`U-8`），不替代下游 canon 裁决。
- 不以工具或发布产物为成功条件。

## 第 1 章 最小概念导入：世界模型 / 世界状态 / 裁决结果

| 概念 | 职责 | 回答 |
|------|------|------|
| **世界模型**（机制层） | 描述运行机制：可作为默认参考的现实规律、虚构世界必须直接接受的基本前提、条件→作用→结果的机制模型、模型间必要的依赖与组合关系 | 世界**怎样运行** |
| **世界状态**（状态层） | 记录当前具体事实：对象、位置/资源/能力/关系、环境参数、已发生并**被接受**的历史事实、实例值 | 现在**具体是什么** |
| **裁决结果** | 一次「状态 × 模型」的求值产物 | 给定状态下**会怎样** |

### 归属判定谓词（可操作）

1. **替换检查**：把这条内容里的具体对象、地点、时刻替换掉，关系**是否仍然成立**？仍成立 → **机制**；只有在特定取值下才有意义 → **状态**；它是对某次"状态 × 模型"求值得到的答案 → **裁决结果**。
2. **参数归属**：该参数是**持久的实例值**（世界状态）还是**仅本次裁决用的一次性输入**（裁决实例）？两者都不是"另一套模型"。
3. **归属待定**：若两种读法都讲得通，**不得就地二选一**，按下方"归属待定"处理。

### 归属待定（与「未定义」分开）

- **归属待定** = 这条内容**已经存在**，但它该落在机制层还是状态层尚未判定。后果：它**暂时无法被引用**为模型依据或状态输入。
- **未定义**（第 5 章）= 该问题**尚未建模**，所以目前**不存在**可裁决能力。后果：它影响的是**能力范围**，不影响某条已有内容的归属。
- 两者**不得混用同一处置**。〔默认设计〕归属待定以**就地标注**（如 `> 归属待定`）+ 一条登记记录承载，登记字段见第 5 章 `C8` 默认设计。

### 裁决结果的可追溯五项

一次裁决结果须能回到：① 使用了什么模型；② 使用了什么状态；③ **模型版本**；④ 适用范围；⑤ 推导或求解依据。缺任一，不得称为一次完整裁决。

**适用条件**：任何要区分"世界怎样运行"与"现在具体是什么"的场合；机制层与状态层分开承载时。
**已知边界**：谓词处理的是**归属**，不判断内容真假或质量；"已发生并被接受"中"被接受"由谁认定，本版未细定（见未决）。
**未决事项**：① "已发生并**被接受**"的认定责任与留痕方式；② 归属待定记录的**复查触发**（何时必须回到判定）。

### 判断点与协作位

- **判断点**：归属判定（机制/状态/裁决结果）；参数归属；"两者皆通"是否记入归属待定。
- **助手可协助**：按谓词逐条走查并给出候选归属与理由；整理可追溯五项；提示"这条像归属待定"。
- **不得越过**：不得代替创作者认定归属；不得把"两者皆通"直接判成某一层。
- **留痕**：按前言表格记「判断点 / 建议 / 裁定 / 依据」。

## 第 2 章 总流程：按需扩展循环

**本循环即需求原文 §13 的「最低可用结果」**：发现能力缺口 → 构建最低充分模型 → 注册能力 → 完成裁决 → 检查 → 返回创作。

| 步 | 动作 | 出口 |
|----|------|------|
| ① | **出现真实客观裁决需求**（来自真实创作） | 无真实需求 → **停止，不扩展世界模型**；需求**不是客观世界问题** → **回绝并回流**（第 8 章步 ①），不进建模 |
| ② | **能力发现**：查现有世界模型是否已支持这类问题（第 3 章） | 已支持 → 步 ③；否则 → 步 ④ |
| ③ | **确定完成裁决还需要哪些具体状态或参数**（第 1 章谓词） | → 步 ⑧（可直接裁决） |
| ④ | **缺口判定**：缺状态 / 缺组合 / 缺精度 / 缺机制（第 8 章五步） | 非机制缺口 → 按对应路径处理并回 ③ 或终止；确认为机制缺口 → 步 ⑤ |
| ⑤ | **构建最低充分机制模型**（第 7 章十一项）＋**建模期检查**（第 5 章：机制优先、反补丁、冲突六项） | 建不起来 → 记录并终止本轮；建成 → 步 ⑥ |
| ⑥ | **注册能力**：把新增/增强的裁决能力写入能力声明（第 3 章；未完成项按第 7 章限制声明范围） | → 步 ⑦ |
| ⑦ | **完成裁决**：按第 3 章输入-返回契约求值，记录可追溯五项（第 1 章） | 无法裁决 → 第 3 章第 5 类，说明缺什么并回流；可裁决 → 步 ⑧ |
| ⑧ | **检查（裁决后）**：该裁决是否越出模型**已声明的精度或适用条件**？是否触发第 9 章的失效/重算？ | 越界或需重算 → 记录并回到 ④/⑤；无问题 → 步 ⑨ |
| ⑨ | **返回创作**：交付裁决结果，并按第 9 章声明其有效性 | 循环结束 |

### 两种"检查"必须分开

- **建模期检查**（步 ⑤）：检查**模型**——是不是一类问题的机制、有没有针对结果打补丁、与其他模型是否冲突（第 5 章）。
- **裁决后检查**（步 ⑧）：检查**这一次裁决**——有没有超出模型已声明的精度/适用条件、是否需要重算（第 4、9 章）。

二者对象不同，**不得合并成一步**。

### 硬纪律

- **没有真实裁决需求时，不主动扩展世界模型。**
- **现有模型已足以支持当前工作时，停止建模。**
- 每一步都可**失败并明确退出**；"当前无法裁决"是合法结果，不得为了跑完流程而伪造结论。

**适用条件**：本方法是"按需增长"的，因此必须先有真实需求；把本循环用于假想需求或"完善世界"的冲动，均超出适用条件。
**已知边界**：循环保证**可追溯与不空转**，不保证一次就能建出可裁决的模型；⑦/⑧ 可能把流程带回 ④。
**未决事项**：① 步 ⑧ 检查的**最低核对清单**（本版只给两类问句）；② 一轮循环的**预期时限/迭代上限**（本版不设）。

### 判断点与协作位

- **判断点**：本次是否属"真实客观裁决需求"；是否不是客观问题（回绝）；循环是否应当停止（不建模）；步 ⑧ 检查的结论。
- **助手可协助**：追问需求来源与情境、检索现有能力、给候选归类、提示循环可能已可停止、按两种检查逐条走查。
- **不得越过**：不得替创作者认定"这是真实需求"；不得因流程"看起来该往下走"而推动建模；不得把步 ⑧ 的检查结论当作创作者判断。
- **留痕**：进入循环的真实需求、每步结论、停止/回绝/继续的理由。

## 第 3 章 能力发现与客观裁决

### 能力发现（至少声明 8 项）

对每个可用裁决能力说明：① 支持的问题类型；② 问题的准确含义；③ 需要哪些状态或参数；④ 参数的类型、单位或取值要求；⑤ 使用哪些模型；⑥ 适用条件；⑦ 能达到什么精度；⑧ 什么情况下无法完成裁决。

**新增世界模型，本质上应表现为新增或增强某种可用的裁决能力**，因此能力声明须随模型变化同步更新。

**〔默认设计〕能力清单的承载（`C1`）**：以**一处「能力目录」**承载上列 8 项，位置由创作者/下游自定（本方法不指定路径）；新增或修订模型时同步更新其条目。**能力目录、模型依赖（第 1 章 §4.1 的组合关系）与冲突登记（第 5 章）三者相关但不同**——分别回答"能裁决什么""模型之间怎么组合""哪里存在未解决的一致性问题"；**不要求合并为一处**，是否合并由实际使用决定。

### 客观裁决

输入：受支持的客观问题 + 当前世界状态 + 必要参数 + 要求的精度。
返回**五类之一**：① 确定结果；② 结果范围；③ 有明确机制依据的不确定或随机结果；④ 较低精度的可用结果；⑤ **明确说明当前无法裁决**。

**硬纪律：不得为了满足调用方要求而伪造不存在的精度或确定性。**

### "无法裁决"的去向

返回第 ⑤ 类时，须说明**缺的是状态、组合、精度还是机制**，并接回第 2 章步 ④。

**适用条件**：存在可被查询的裁决能力时；对**尚未注册**的能力不得作"已支持"声明。
**已知边界**：本方法不规定能力目录的物理形式（文件/章节/表格），也不规定查询工具。
**未决事项**：⑤ 类返回的**记录字段**（本版只要求"说明缺什么"）。

### 判断点与协作位

- **判断点**：某问题是否"受支持"；返回哪一类；是否应判为"无法裁决"。
- **助手可协助**：比对能力声明与问题、列出缺失输入、给出返回类别的候选。
- **不得越过**：不得为凑出答案而选"确定结果"；不得降低精度要求而不声明。
- **留痕**：每次裁决记入参、返回类别、依据与（若有）"无法裁决"的原因。

## 第 4 章 裁决精度：定性与定量的统一处理

### 统一处理的主张

- **不把"定性模型"与"定量模型"视为两种独立模型。** 一个机制模型可能：只能提供定性关系；可以提供区间或阈值；可以使用具体参数完成数值计算；可以描述具有明确随机机制的结果分布。
- **定量裁决本质上是：把具体世界状态中的参数值代入已有机制模型后进行求值。**
- **具体参数属世界状态或当前裁决实例，不是另一套世界模型。**
- 因此模型应明确：**自己能够支持什么精度的裁决。**

### 精度声明

每个模型须**明确声明当前支持的裁决精度或精度形态，以及其无法支持的精度边界**。

- **不要求每个模型都存在"精度阶梯"**：一个只支持定性判断、不支持区间与数值的模型，只要把自己的支持面与边界声明清楚，即为合格声明。
- **若确实存在多个可用精度层级**，须能表达这些层级之间的关系（例如"有参数时给数值，无参数时退化为区间"，以及各自前提）。

**〔默认设计〕参数归属的判定位置（`C5`）**：参数属**世界状态**还是属**当前裁决实例**，**与第 1 章的归属判定谓词合并在同一处处理**（同一份判定记录同时给出"机制/状态/裁决结果"与"参数归属"两个结论），避免出现两套相似但不同的谓词。

**适用条件**：任何要声明"这个模型能回答到什么程度"的场合；多精度形态并存时。
**已知边界**：精度声明只声明**能力边界**，不保证在该边界内一定给出结果（可能因缺状态而无法裁决）。
**未决事项**：多层精度之间**冲突或退化**时的记录形式（本版只要求"能表达关系"）。

### 判断点与协作位

- **判断点**：本模型声明哪些精度形态；边界划在哪里；多层时的关系。
- **助手可协助**：按形态逐项追问、给边界候选、检查声明与第 3 章能力目录是否一致。
- **不得越过**：不得替创作者把"希望达到"写成"已能支持"。
- **留痕**：精度声明及其依据（例如某个反例或敏感性检查）。

## 第 5 章 模型构建原则与执行检查

| 原则 | 要求 | 执行检查 |
|------|------|----------|
| **机制优先于结果** | 回答"什么条件通过什么机制产生什么结果"，而不是记录个案答案 | 换对象、换地点、换状态后模型是否**仍然可用**？只对当前案例成立 → 不合格 |
| **允许基本前提** | 可以有无需继续解释的前提，但**尽量最少** | 逐条问："这条能否由已有机制推出？"能推出 → **不得**再声明为新前提 |
| **允许未定义** | "尚未建模"≠"不存在"（与第 1 章"归属待定"分开） | 未定义处须**显式标记**，使以后不被读作"不存在"、也不被当作结论 |
| **禁止针对结果补丁** | 不得因当前剧情希望某结果而临时加有利机制、加有利前提、补写关键状态，或在冲突模型中挑对当前剧情有利者 | 对照四种形态逐条自检；**判断由创作者作出**，助手可给反例与追问 |
| **模型需要相互兼容** | 所有模型共同描述同一个世界 | 冲突时按六项检查：输入状态是否相同 / 适用范围 / 时间尺度 / 精度 / 是否需联合求解 / 是否存在版本变化；**不得用"特殊情况"绕过未解释的冲突** |

**冲突不得静默消失**：出现冲突时登记并进入处理流程（待定、修订或拒绝裁决），不允许局部特例掩盖。

**〔默认设计〕未定义与冲突的登记（`C8`）**：两者**各自就地标注**（如 `> 未定义` / `> 冲突：<冲突点>`），并各留一条登记记录；**最小字段**为：`标识`、`类型`（未定义 / 冲突 / 归属待定）、`位置`（所在条目）、`影响`（影响哪条裁决或哪个能力）、`状态`、`去向`（待定 / 修订 / 拒绝裁决）。**本方法只要求"可登记并给最小字段"，不指定登记文件的位置与命名。**

**适用条件**：所有新增或修订模型的场合。
**已知边界**：这些是**检查项**，不是自动校验；发现"补丁"与"冲突"依赖创作者判断。
**未决事项**：六项冲突检查各自的**判定阈值**（本版只给检查维度）。

### 判断点与协作位

- **判断点**：是否属"结果补丁"（四种形态）；冲突是否已解释清楚；六项检查的结论。
- **助手可协助**：给反例与追问、按四种形态与六项检查逐条走查、整理冲突点。
- **不得越过**：不得代替创作者判定"这不算补丁"或"冲突已解释"。
- **留痕**：补丁自检结论、冲突登记与处理去向。

## 第 6 章 现实参考的使用边界

- 现实世界可作**默认参考**，但**不得把个人常识直接等价于现实规律**。
- 借用现实知识时，**必须声明与该参考相匹配、且可能影响裁决有效性的适用条件**——读了这条裁决的人能据此判断"在什么条件下这个结论成立"。
  - 对物理、生理、工程等**适用范围较稳定**的问题，适用条件通常容易给出（如介质、尺度、材料），可直接借用。
  - 对**社会规范、组织行为、家庭关系、权力结构、声誉传播、群体决策**等**高度情境化**问题，**文化、制度、组织等条件必须显式说明**；必要时**建立专门机制**，不得仅以"现实通常如此"完成裁决。
- **本方法不建立统一的"稳定性"总判据**：以**举例清单**＋**强制显式声明**为主，避免把一种判断标准变成新教条。
- **出口**：若**关键适用条件无法明确、且会实质影响裁决结果**，则**建立专门机制**，或**拒绝当前精度的裁决**（与第 3 章第 ⑤ 类返回衔接）。

**适用条件**：任何引用现实知识作为机制依据的场合。
**已知边界**：不提供"哪个参考属哪一类"的总表；分类依赖举例与创作者判断。
**未决事项**：高度情境化问题的**专门机制触发条件**（本版只给"必要时"）。

### 判断点与协作位

- **判断点**：本参考属哪一类；适用条件是否已足够明确；是否需建专门机制或拒绝当前精度。
- **助手可协助**：追问适用条件、给出"条件不明会导致哪种误裁决"的反例、检索同类已建机制。
- **不得越过**：不得以"通常如此""常识上"补位；不得把条件不明当作条件已明。
- **留痕**：本参考的类别、已声明的适用条件、或"条件无法明确 → 专门机制/拒绝裁决"的决定。

## 第 7 章 新模型的最低要求与条目结构

**十一项均须被处理**：① 解决哪一类客观问题；② 为什么现有模型不足；③ 依赖哪些现实参考或基本前提；④ 需要哪些状态输入；⑤ 输入通过什么机制产生输出；⑥ 在什么范围内适用；⑦ 能够达到什么裁决精度；⑧ 与其他模型如何组合；⑨ 什么情况下应拒绝裁决；⑩ 经过哪些最小条件变化或反例检查；⑪ 当前模型版本。

初期允许使用**自然语言模型**，不要求数学化；**结构化和工具化只在重复使用确有价值后进行**。

### 完成语义

- 十一项**均须被处理**，但允许以「**未知**」「**尚待验证**」「**不适用**」作为**显式结果**（写明理由；"不适用"须说明为何不适用）。
- **未完成状态不阻止（暂定）注册**——按需增长要求模型可以在信息不全时先建立。
- 但**限制可声明的裁决能力**：**能力声明（第 3 章）不得超过未完成项所允许的范围**；暂定注册后须同步更新能力目录条目。
- 「**关键项未知**」属**应拒绝裁决**的情形。

**〔默认设计〕"关键项"清单**：本版把 **⑥ 适用范围、⑦ 精度、⑨ 拒绝裁决的条件** 视为关键项——它们直接决定能力声明的边界。若某项为"未知"，则能力声明必须相应收窄或标注为受限。

**适用条件**：确认存在机制缺口、开始构造或修订模型时。
**已知边界**：本方法给的是**条目要求**，不是必填表单；十一项允许显式未完成。
**未决事项**：可填写的「模型条目最小结构」由 **W3** 产出（与本章逐项对应）。

### 判断点与协作位

- **判断点**：某模型是否已达"可注册"；哪些项以"未知/尚待验证/不适用"显式结项；哪些属"关键项未知"。
- **助手可协助**：按十一项逐条追问、给"关键项"候选、检查能力声明是否超出未完成项允许范围。
- **不得越过**：不得替创作者把"未知"写成具体结论；不得把暂定注册说成已完备。
- **留痕**：十一项的逐项结果（含显式未完成项）与能力声明范围。

## 第 8 章 能力缺口判定

**本章展开第 2 章步 ④**：世界模型暂时答不出一个问题时，究竟缺什么——以及什么情况下**不该**新建模型。

**依次检查**（不得跳步）：

1. 这是否真的是一个**客观世界问题**？若否 → **回绝**（见下）。
2. 是否**已经存在**相应裁决能力？（第 3 章）
3. 是否只是**缺少当前世界状态**？
4. 是否可以通过**已有模型组合**得到答案？
5. 是否只是**要求的精度**超过现有模型能力？

**只有上述检查仍无法解决时**，才认定「存在新的世界模型能力缺口」，并启动建模（第 2 章步 ⑤）。

### 第 ① 步的回绝与回流

判定"不是客观世界问题"（例如属剧情走向、角色决策、叙事呈现）时：**明确回绝**、说明理由、记录，并**回流创作**——**不得**把它转成建模任务（这是防空转的关键闸门之一）。

**适用条件**：任何"模型答不出来"的场合；本方法是唯一的"该不该建模"判据入口。
**已知边界**：五步只判定"缺什么"，不判定"值不值得建"（后者由创作需要决定）。
**未决事项**：可填写的「能力缺口判定清单」由 **W3** 产出（与本章逐项对应）。

### 判断点与协作位

- **判断点**：第 ① 步是否成立；五步中停在哪一步；是否认定机制缺口。
- **助手可协助**：按五步逐条走查、给"其实已有能力/其实只是缺状态"的反例、整理结论。
- **不得越过**：不得把非客观问题"翻译"成客观问题以推进建模；不得跳过第 ②～⑤ 步直接建模型。
- **留痕**：五步逐项结论、停步位置或缺口认定。

## 第 9 章 版本、追溯与旧裁决

- **不变量（不可退让）**：**过去裁决必须能追溯到其使用的模型版本**（与第 1 章"可追溯五项"一致）。
- 模型修订后，须能识别：① 哪些裁决能力受影响；② 哪些过去的裁决依赖旧版本；③ 哪些裁决需要重新计算。
- 世界模型**只负责声明**：哪些客观裁决仍然有效、哪些已失效、哪些需重新检查。
- **边界**：具体作品如何处理依赖这些裁决的既有剧情，**不属本方法职责**。

**〔默认设计〕追溯的实现方式（`C4`）**：以**能力段落为单位**维护"受影响能力 → 依赖该能力的裁决"的关系，对确有价值的个案再逐条记录。无论采用哪种方式，**不变量必须成立**。

**与总流程的关系**：第 2 章步 ⑧ 的"裁决后检查"在此落地——越出已声明的精度/适用条件，或命中受影响的旧裁决，即进入失效/重算声明。

**适用条件**：任何模型修订之后；以及每次裁决后的检查（步 ⑧）。
**已知边界**：本方法只声明世界模型侧的有效性，不裁决作品剧情如何处理。
**未决事项**：失效/需重算声明的**最小字段**（本版只要求"能识别三类影响"）。

### 判断点与协作位

- **判断点**：修订影响哪些能力；哪些旧裁决失效或需重算；声明有效/失效/需重查。
- **助手可协助**：按修订点检索依赖、列出候选受影响裁决、整理声明草案。
- **不得越过**：不得以"记录成本高"为由放弃追溯不变量；不得替创作者宣布某裁决仍有效。
- **留痕**：修订、受影响能力、失效/需重算清单与声明。
