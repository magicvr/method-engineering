# 世界模型构建方法（工作版）v0.1

> 本文件是 **W2 草稿**（落 `attachments/`，尚未升格为仓级稳定路径；升格路径见信息项 `I-203`）。它是给**创作者**用的工作方法：说明怎样在没有真实裁决需求时不建模、在有真实需求时按需扩展，以及每一步由谁作决定。

## 前言

### 本方法是什么

一套**按需增长**的世界模型构建方法：让创作者在遇到关于世界客观规律、客观状态或交互结果的问题时，能判断现有世界模型是否已经能回答；不能时识别所缺的是**状态、组合、精度还是机制**，以最低必要成本补足相应的机制模型，并让这类问题以后能够稳定、可追溯地裁决。

**本方法不要求预先建完整世界**，也不给"完整建模理论"。它的最低可用结果是：针对一个真实创作中出现的客观问题，完整跑通「发现能力缺口 → 构建最低充分模型 → 注册能力 → 完成裁决 → 检查 → 返回创作」这一闭环。

### 执行主体与协作位

- **执行主体是创作者**。世界模型的**主题、取舍与最终裁决属于创作者**。
- **助手不得代劳**：不得在创作者未实际参与判断的情况下确定结论并直接采用；不得用自己产出的判断冒充创作者判断。
- **助手应尽可能协助**：可提供提示、引导、候选方案、示例、追问、反例、检查与整理；对判断点**可以给建议与理由**，但**结论由创作者作出**。
- **界线判据**：助手给建议 + 创作者裁定 = **协助**（允许且鼓励）；助手直接定结论并被采用、或创作者退化为**被动确认** = **代劳**（禁止）。
- 本方法**不以任何 AI 能力为前提，也不禁止使用助手**；验收口径是「创作者能据本方法作出决定并完成闭环，且协作位与留痕清楚」。

### 留痕约定（建议与裁定分开）

每次关键判断按下表留痕，使「结论是谁作的」可核对：

| 栏位 | 写什么 |
|------|--------|
| 判断点 | 本章/本步要求作出的决定（如"是否已存在相应能力"） |
| 建议 | 助手（若有）给出的候选与理由；无助手时写"无" |
| **裁定** | **创作者**的结论 + 依据 |
| 依据 | 引用的状态、模型、精度、适用条件或条款 |
| 后续责任 | 下一步由谁做什么 |

**禁止**：只有建议没有裁定；裁定栏写"确认"而无实质内容；用建议栏内容当作结论。

### 明确不主张

- 不主张本方法**普遍有效**；它只声明本轮可用、可检验。
- 不关闭下游承载未知（`U-1`～`U-8`），不替代下游 canon 裁决。
- 不以工具或发布产物为成功条件。

## 第 1 章 最小概念导入：世界模型 / 世界状态 / 裁决结果

**要回答什么**：一条内容是"世界怎样运行"，还是"现在具体是什么"，还是"某次求值的结果"？

| 概念 | 职责 | 回答 |
|------|------|------|
| **世界模型**（机制层） | 描述运行机制：可作为默认参考的现实规律、虚构世界必须直接接受的基本前提、条件→作用→结果的机制模型、模型间必要的依赖与组合关系 | 世界**怎样运行** |
| **世界状态**（状态层） | 记录当前具体事实：对象、位置/资源/能力/关系、环境参数、已发生并**被接受**的历史事实、实例值 | 现在**具体是什么** |
| **裁决结果** | 一次「状态 × 模型」的求值产物 | 给定状态下**会怎样** |

### 归属判定谓词（可操作）

按下述次序判定，**不得凭感觉归属**：

1. **替换检查**：把这条内容里的具体对象、地点、时刻替换掉，关系**是否仍然成立**？
   - 仍成立 → 属**机制**（世界模型）。
   - 只有在特定取值下才有意义 → 属**状态**（世界状态）。
   - 它是对某次"状态 × 模型"求值得到的答案 → 属**裁决结果**。
2. **参数归属**：某个参数是**持久的实例值**（属世界状态）还是**仅本次裁决用的一次性输入**（属裁决实例）？两者都不是"另一套模型"。
3. **两者皆通**：若两种读法都讲得通，**不得就地二选一**；记入待定并标注（见第 5 章「允许未定义」），在后续需求出现时再定。

### 裁决结果的可追溯五项

一次裁决结果须能回到：① 使用了什么模型；② 使用了什么状态；③ **模型版本**；④ 适用范围；⑤ 推导或求解依据。缺任一，不得称为一次完整裁决。

### 判断点与协作位

- **判断点**：归属判定（机制/状态/裁决结果）；参数归属；"两者皆通"时的待定登记。
- **助手可协助**：按谓词逐条走查并给出候选归属与理由；整理可追溯五项。
- **不得越过**：不得代替创作者认定归属；不得把"两者皆通"直接判成某一层。
- **留痕**：按前言表格记「判断点 / 建议 / 裁定 / 依据」。

## 第 2 章 总流程：按需扩展循环

**要回答什么**：什么时候建模、什么时候不该建模、每一步做什么、循环在哪里结束。

### 主循环

| 步 | 动作 | 出口 |
|----|------|------|
| ① | **出现真实客观裁决需求**（来自真实创作，不是假想） | 无真实需求 → **停止，不扩展世界模型** |
| ② | **能力发现**：查现有世界模型是否已支持这类问题（第 3 章） | 已支持 → 步 ③；否则 → 步 ④ |
| ③ | **确定完成裁决还需要哪些具体状态或参数**（第 1 章归属谓词） | → 步 ⑥ |
| ④ | **缺口归类**：缺状态 / 缺组合 / 缺精度 / 缺机制（第 8 章五步） | 非机制缺口 → 按对应路径处理；确认为机制缺口 → 步 ⑤ |
| ⑤ | **构造最低充分机制模型**：定义能力、构造模型、检查（第 7 章）、注册能力（第 3 章） | → 步 ⑥ |
| ⑥ | **完成裁决并返回创作**：记录裁决结果与可追溯五项（第 1 章）、声明有效性（第 9 章） | 循环结束 |

### 硬纪律

- **没有真实裁决需求时，不主动扩展世界模型。**
- **现有模型已足以支持当前工作时，停止建模。**
- 循环的每一步都可**失败并明确退出**（"当前无法裁决"也是合法结果，见第 3 章），不得为了跑完流程而伪造结论。

### 判断点与协作位

- **判断点**：本次是否属"真实客观裁决需求"；循环是否应当停止（不建模）。
- **助手可协助**：追问需求来源与情境、检索现有能力、给候选归类、指出循环可能已可停止。
- **不得越过**：不得替创作者认定"这是真实需求"；不得因流程"看起来该往下走"而推动建模。
- **留痕**：记录进入循环的真实需求、每步结论与停止/继续理由。

## 第 3 章 能力发现与客观裁决

**要回答什么**：现有世界模型能裁决什么、需要什么输入；给定输入能返回什么。

### 能力发现（至少声明 8 项）

对每个可用裁决能力说明：① 支持的问题类型；② 问题的准确含义；③ 需要哪些状态或参数；④ 参数的类型、单位或取值要求；⑤ 使用哪些模型；⑥ 适用条件；⑦ 能达到什么精度；⑧ 什么情况下无法完成裁决。

**新增世界模型，本质上应表现为新增或增强某种可用的裁决能力**——而不是"多了一个文件"。因此能力声明须随模型变化同步更新。

### 客观裁决

输入：受支持的客观问题 + 当前世界状态 + 必要参数 + 要求的精度。
返回**五类之一**：

1. 确定结果；2. 结果范围；3. 有明确机制依据的不确定或随机结果；4. 较低精度的可用结果；5. **明确说明当前无法裁决**。

**硬纪律：不得为了满足调用方要求而伪造不存在的精度或确定性。**

### "无法裁决"的去向

返回第 5 类时，须说明**缺的是状态、组合、精度还是机制**，并接回第 2 章步 ④——这是循环不空转的关键。

### 判断点与协作位

- **判断点**：某问题是否"受支持"；返回哪一类；是否应判为"无法裁决"。
- **助手可协助**：比对能力声明与问题、列出缺失输入、给出返回类别的候选。
- **不得越过**：不得为凑出答案而选择"确定结果"；不得降低精度要求而不声明。
- **留痕**：每次裁决记入参、返回类别、依据与（若有）"无法裁决"的原因。

## 第 4 章 裁决精度声明

**要回答什么**：一个模型当前能支持什么精度、支持不了什么。

每个模型须**明确声明当前支持的裁决精度或精度形态，以及其无法支持的精度边界**。

- 精度形态可包括：只有定性方向判断；可给区间或阈值；可用具体参数做数值计算；可描述有明确随机机制的结果分布。
- **不要求每个模型都存在"精度阶梯"**：一个只支持定性判断、不支持区间与数值的模型，只要把自己的支持面与边界声明清楚，即为合格声明。
- **若确实存在多个可用精度层级**，须能表达这些层级之间的关系（例如"有参数时给数值，无参数时退化为区间"，以及各自的前提）。
- 参数属**世界状态**还是属**当前裁决实例**，按第 1 章谓词判定。

### 判断点与协作位

- **判断点**：本模型声明哪些精度形态；边界划在哪里；多层时的关系。
- **助手可协助**：按上列形态逐项追问、给边界候选、检查声明与能力发现（第 3 章）是否一致。
- **不得越过**：不得替创作者把"希望达到"写成"已能支持"。
- **留痕**：精度声明及其依据（例如某个反例或敏感性检查）。

## 第 5 章 模型构建原则与执行检查

| 原则 | 要求 | 执行检查 |
|------|------|----------|
| **机制优先于结果** | 回答"什么条件通过什么机制产生什么结果"，而不是记录个案答案 | 换对象、换地点、换状态后，模型是否**仍然可用**？只对当前案例成立 → 不合格 |
| **允许基本前提** | 可以有无需继续解释的前提，但**尽量最少** | 逐条问："这条能否由已有机制推出？"能推出 → **不得**再声明为新前提 |
| **允许未定义** | "尚未建模"≠"不存在" | 未定义处须**显式标记**（如 `> 未定义`），使以后不被读作"不存在"、也不被当作结论 |
| **禁止针对结果补丁** | 不得因当前剧情希望某结果而临时加有利机制、加有利前提、补写关键状态，或在冲突模型中挑对当前剧情有利者 | 对照上述四种形态逐条自检；**判断由创作者作出**，助手可给反例与追问 |
| **模型需要相互兼容** | 所有模型共同描述同一个世界 | 冲突时按六项检查：输入状态是否相同 / 适用范围 / 时间尺度 / 精度 / 是否需联合求解 / 是否存在版本变化；**不得用"特殊情况"绕过未解释的冲突** |

**冲突不得静默消失**：出现冲突时登记并进入处理流程（待定、修订或拒绝裁决），不允许局部特例掩盖。

### 判断点与协作位

- **判断点**：是否属"结果补丁"（四种形态）；冲突是否已解释清楚；六项检查的结论。
- **助手可协助**：给反例与追问、按四种形态与六项检查逐条走查、整理冲突点。
- **不得越过**：不得代替创作者判定"这不算补丁"或"冲突已解释"。
- **留痕**：补丁自检结论、冲突登记与处理去向。

## 第 6 章 现实参考的使用边界

**要回答什么**：什么时候可以直接借用现实知识，什么时候必须先把条件说清。

- 现实世界可作**默认参考**，但**不得把个人常识直接等价于现实规律**。
- 借用现实知识时，**必须声明与该参考相匹配、且可能影响裁决有效性的适用条件**——即：读了这条裁决的人能据此判断"在什么条件下这个结论成立"。
  - 对物理、生理、工程等**适用范围较稳定**的问题，适用条件通常容易给出（如介质、尺度、材料），可直接借用。
  - 对**社会规范、组织行为、家庭关系、权力结构、声誉传播、群体决策**等**高度情境化**问题，**文化、制度、组织等条件必须显式说明**；必要时**建立专门机制**，不得仅以"现实通常如此"完成裁决。
- **本方法不建立统一的"稳定性"总判据**：以**举例清单**＋**强制显式声明**为主，避免把一种判断标准变成新教条。
- **出口**：若**关键适用条件无法明确、且会实质影响裁决结果**，则**建立专门机制**，或**拒绝当前精度的裁决**（与第 3 章第 5 类返回衔接）。

### 判断点与协作位

- **判断点**：本参考属哪一类；适用条件是否已足够明确；是否需建专门机制或拒绝当前精度。
- **助手可协助**：追问适用条件、给出"条件不明会导致哪种误裁决"的反例、检索同类已建机制。
- **不得越过**：不得以"通常如此""常识上"补位；不得把条件不明当作条件已明。
- **留痕**：本参考的类别、已声明的适用条件、或"条件无法明确 → 专门机制/拒绝裁决"的决定。

## 第 7 章 新模型的最低要求与条目结构

**要回答什么**：确认必须新增模型时，一个"可注册"的机制模型条目至少要说清什么。

**十一项均须被处理**（缺项须以显式结果标注，见下"完成语义"）：

1. 它解决哪一类客观问题；
2. 为什么现有模型不足；
3. 依赖哪些现实参考或基本前提；
4. 需要哪些状态输入；
5. 输入通过什么机制产生输出（条件 → 作用 → 结果）；
6. 在什么范围内适用；
7. 能够达到什么裁决精度；
8. 与其他模型如何组合；
9. 什么情况下应拒绝裁决；
10. 经过哪些最小条件变化或反例检查；
11. 当前模型版本。

初期允许使用**自然语言模型**，不要求所有机制数学化；**结构化和工具化只在重复使用确有价值后进行**。

### 完成语义（关键）

- 十一项**均须被处理**，但允许以「**未知**」「**尚待验证**」「**不适用**」作为**显式结果**（写明理由；"不适用"须说明为何不适用）。
- **未完成状态不阻止（暂定）注册**——按需增长要求模型可以在信息不全时先建立。
- 但**限制可声明的裁决能力**：能力声明**不得超过**未完成项所允许的范围。
- 「**关键项未知**」（例如"什么情况下应拒绝裁决"不明、适用条件不明、精度不明）属**应拒绝裁决**的情形。

> 本章给出条目**要求**；可填写的「模型条目最小结构」由 W3 产出并与本章逐项对应。

### 判断点与协作位

- **判断点**：某模型是否已达"可注册"；哪些项以"未知/尚待验证/不适用"显式结项；哪些属"关键项未知"。
- **助手可协助**：按十一项逐条追问、给"关键项"候选、检查能力声明是否超出未完成项允许范围。
- **不得越过**：不得替创作者把"未知"写成具体结论；不得把暂定注册说成已完备。
- **留痕**：十一项的逐项结果（含显式未完成项）与能力声明范围。

## 第 8 章 能力缺口判定

**要回答什么**：世界模型暂时答不出一个问题时，究竟缺什么——以及什么情况下**不该**新建模型。

**依次检查**（不得跳步）：

1. 这是否真的是一个**客观世界问题**？（若否 → **回绝**，见下）
2. 是否**已经存在**相应裁决能力？（第 3 章能力发现）
3. 是否只是**缺少当前世界状态**？
4. 是否可以通过**已有模型组合**得到答案？
5. 是否只是**要求的精度**超过现有模型能力？

**只有上述检查仍无法解决时**，才认定「存在新的世界模型能力缺口」，并启动建模（第 2 章步 ⑤）。

### 第 ① 步的回绝与回流

判定"不是客观世界问题"（例如属剧情走向、角色决策、叙事呈现）时：**明确回绝**、说明理由、记录，并**回流创作**——**不得**把它转成建模任务（这是防空转的关键闸门之一）。

> 本章给出判定**次序**；可填写的「能力缺口判定清单」由 W3 产出并与本章逐项对应。

### 判断点与协作位

- **判断点**：第 ① 步是否成立；五步中停在哪一步；是否认定机制缺口。
- **助手可协助**：按五步逐条走查、给"其实已有能力/其实只是缺状态"的反例、整理结论。
- **不得越过**：不得把非客观问题"翻译"成客观问题以推进建模；不得跳过第 ②～⑤ 步直接建模型。
- **留痕**：五步逐项结论、停步位置或缺口认定。

## 第 9 章 版本、追溯与旧裁决

**要回答什么**：模型改了以后，哪些旧裁决还算数。

- **不变量（不可退让）**：**过去裁决必须能追溯到其使用的模型版本**（与第 1 章"可追溯五项"一致）。
- 模型修订后，须能识别：① 哪些裁决能力受影响；② 哪些过去的裁决依赖旧版本；③ 哪些裁决需要重新计算。
- 世界模型**只负责声明**：哪些客观裁决仍然有效、哪些已失效、哪些需重新检查。
- **边界**：具体作品如何处理依赖这些裁决的既有剧情，**不属本方法职责**。

**实现建议（默认设计，可按实际情况替换）**：以**能力段落为单位**维护"受影响能力 → 依赖该能力的裁决"的关系，对确有价值的个案再逐条记录。无论采用哪种方式，**不变量必须成立**。

### 判断点与协作位

- **判断点**：修订影响哪些能力；哪些旧裁决失效或需重算；声明有效/失效/需重查。
- **助手可协助**：按修订点检索依赖、列出候选受影响裁决、整理声明草案。
- **不得越过**：不得以"记录成本高"为由放弃追溯不变量；不得替创作者宣布某裁决仍有效。
- **留痕**：修订、受影响能力、失效/需重算清单与声明。
