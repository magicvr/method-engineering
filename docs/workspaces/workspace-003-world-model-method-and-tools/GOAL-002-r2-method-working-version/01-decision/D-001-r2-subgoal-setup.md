## D-001 · 建立 R2 子目标并以真实问题为适用性判据

### 触发

用户 2026-09-26 指令两点：① 为 Root 纲领的 **R2**（形成方法工作版）**新建一个子目标**承接，并判断其体量较大；② 提供一条**真实世界问题**，作为 R2 的判据，确保方法所构建的世界模型可以回答该问题。

同时，Root `I-002`（有界检验用例）由该问题满足；R1 已冻结交付物构成与工具边界（Root `D-002`）。

### 决定

1. **建立子目标** `GOAL-002-r2-method-working-version`，`parent: GOAL-001-world-model-method-and-tools`，`status: active`，编号 = 当前最大 `001` + 1。承载 R2 全部工作并落实 R3 的工具边界（R3 无独立形成工作）。同时建齐五件套与 `01-decision/`、`02-execution/`、`03-audit/`、`attachments/`。
2. **工作包**：W1 条款映射与差异登记 → W2 方法主文档形成 → W3 两个最小结构形成 → W4 适用性核对。串行，暂不再拆子目标。
3. **真实问题作为判据**：用户提供的问题原文逐字记入 Root 与下游仓材料，并作为 W4 的适用性判据；同时作为 `WRK-002` 的有界检验用例，关闭 Root `I-002`。
4. **判据的边界（不得推定）**：「星际时代」是该用例的**假定切片**，不等于下游 `H-003`（锚定年代）的裁决；「为什么可以实现」触及下游 `H-004`（修真机制范式），同样只作该用例的切片处理。下游 `H-003` / `H-004` 整体**仍为 `open`**（依下游 Root 对 `I-001` 的原有约定：触及年代或机制范式时只作所触及切片的有界裁决）。
5. **交付物构成不变**：仍按 R1 冻结 = 主文档 + 两个最小结构。W4 的走查记录**默认只作 R2 内部证据**，是否并入交付包登记为 `I-202`（required，责任人用户，最晚 W4 结束前）。
6. **草稿落点**：W2 / W3 草稿落本子目标 `attachments/`；是否升格到仓级稳定路径（参照 VP-002 协议升格至 `protocols/` 的先例）登记为 `I-203`（required，责任人用户，最晚 R4 交付前）。
7. **不越界**：W4 核对与任何草稿**不写**下游 `world/` 设定正文、不替下游作 canon 裁决、不关闭其 `U-1`～`U-8`；核对记录不得冒充 R4 交付证据。
8. **审计模式**：R2 阶段审视为 `self`；R4 交付前的独立审计仍由 Root `I-004` 约束，本子目标不替代。
9. **Root 同步**：Root `00-meta.md` 的 R2 记「进行中（由 `GOAL-002` 承载）」；`I-002` 置 `verified`；Root `goal-tree.md` 增加子节点与状态行；Root `progress` **不变**（仍 25%，1/4——R2 未完成，但已非「未开始」）。

### 为什么

- R2 的产出（一份方法主文档 + 两个最小结构 + 一次适用性核对）范围明确但工作量集中，符合「范围大、步骤不明或明显需要拆成多个可独立交付部分」的 P-001 判定；把它立为子目标可让 Root 保持纲领层视角、让证据落点集中。
- 真实问题由需求方给出，正好满足 Root `I-002` 与下游 `I-011` 的「用户书面选定」，且**问题级依据**已在需求原文 §1 / §3 / §10 中，因此不需要再向用户索取额外问题。
- 把「走查记录是否并入交付包」与「草稿升格路径」登记为信息项而不是当场决定，是因为两者都会改变 R1 刚冻结的交付物构成或仓级结构，属 P-004 用户裁决点。
- 「星际时代」按假定切片处理，是沿用下游 Root 对 `I-001` 已登记的规则（触及年代或机制范式时只作所触及切片的有界裁决），而不是本轮新设的宽松解释。

### 未选方案

- **把 W1～W4 各建一个并列子目标**：未选。四者串行、依赖强，且尚无各自独立的交付证据；先以一个子目标 + 工作包阶段计划承接，需要时再拆。
- **把 W4 走查记录直接并入交付包**：未选（本轮）。会改动 R1 冻结的交付物构成，须用户裁决（`I-202`）。
- **让方法正文直接落仓级稳定路径（如 `methods/`）**：未选（本轮）。升格依赖 `I-203` 裁决，先落 `attachments/`。
- **把「星际时代」当作下游 `H-003` 的裁决**：未选。用户表述为「假定」，且下游 `H-003` 属其愿景层内容基线，本仓无权代裁。
- **在 R2 就引入独立审计**：未选。R2 为内容形成阶段，高影响门禁在 R4 交付（Root `I-004`）。

### 影响

- 新增子目标四件套 + `attachments/`；本区 `goal-tree.md` 出现子节点，`progress` 按 0/4 记 0%。
- Root：R2 转「进行中（由 `GOAL-002` 承载）」；`I-002` → `verified`；新增 Root E-004（R2 子目标立项）；`progress` 保持 25%。
- 下游：新落盘真实问题材料与 `D-004` / `E-005`，其 `I-011` → `verified`；其 M1 仍未完成（交付与验收未发生）。
- 运行主记录：追加 EV-004（有界检验用例确定 + R2 子目标立项）；状态保持**「响应中」**（无新的状态转换）。
- 未发生：方法工作版与两个最小结构尚未形成；交付、收件、验收与退出均未发生。
