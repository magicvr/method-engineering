## D-005 · 响应独立审计 A-001：修订 D-004（三层分离、C3/C4 改写、候选分级）

### 触发

独立审计 [`A-001`](../03-audit/A-001-d004-independent-review.md)（`source: independent`，verdict `conditional`）在承认「条款映射与差异登记已完成」的同时，提出 5 条 required（`A-001-F-001`～`F-005`）并明确**不建议 `D-004` 原样作为 W2 输入冻结**。

用户 2026-09-26 逐项确认响应方式：① 按该审计意见 `fixed` 修订；② 采用 `F-005` 建议的升级过滤规则——**仅「语义 / 责任边界 / 成本等级 / 不可逆承诺」升级给创作者裁定**，其余由助手给默认设计、创作者审阅；③ 修订后再跑一次独立复审确认闭合。

### 决定

本条**修订** [`D-004`](D-004-w1-clause-mapping.md) 的三处结构与两条候选；`D-004` 原文保留为历史，其被取代处见下。**W1 的完成判定与出口结论不变**（映射与登记已到位）。

#### 1. 映射改为三层逻辑（`A-001-F-001`）

W1 的产物拆为三层，**不得把第三层写成第一层**：

| 层 | 含义 | 权限 |
|----|------|------|
| **① 原文硬约束** | 需求原文自身直接规定的内容 | 不可改；只可引用 |
| **② 对方法产生的要求** | 由①推出「方法必须具备什么」，是**推导**而非原文 | 可推导，须标明依据① |
| **③ 尚未决定的实现方式** | 满足②的具体做法（记录形态、承载位置、清单形式…） | **属 W2 范围**；W1 只登记，不得当成已定 |

#### 2. 三层映射表（取代 `D-004` 的单表）

| 条款 | ① 原文硬约束 | ② 对方法产生的要求 | ③ 尚未决定的实现方式 |
|------|--------------|--------------------|----------------------|
| **§4.1** | 世界模型描述运行机制，含四类内容（现实规律默认参考 / 基本前提 / 条件-作用-结果机制模型 / 模型间依赖与组合）；回答「世界怎样运行」 | 方法须让创作者能区分并登记这四类；使"世界怎样运行"可从模型读出 | 四类以什么单位登记；"默认参考"是否需登记现实依据与适用条件；依赖与组合的表达形式 |
| **§4.2** | 世界状态记录当前具体事实（对象；位置/资源/能力/关系；环境参数；已发生并被接受的历史事实；实例值）；回答「现在具体是什么」；不得与普适机制混为一体 | 方法须提供机制 / 状态**可操作**的归属判定（否则"不得混为一体"无法执行） | 状态的最小结构与粒度；「已发生并被接受」由谁以何方式判定与留痕 |
| **§4.3** | 裁决结果 = 以状态为输入、调用模型得到的答案；**应可追溯**到：使用了什么模型、什么状态、模型版本、适用范围、推导或求解依据 | 方法须使一次裁决**可追溯**到上述五项 | 「可追溯」如何落为最小记录（`D-004` 曾把"落为一次裁决的最小记录"写成"直接采纳"，即把实现方式当成原文——由本条更正） |
| **§5.1** | 能力发现回答「能回答哪些类型的问题、需要哪些输入」；至少说明 8 项；新增模型应表现为新增或增强某种可用裁决能力 | 方法须使「能裁决什么 + 需要什么输入」**可被查得**，并在新增模型时同步 | 8 项以什么形式承载、放在哪、何时更新；「精度」如何声明 |
| **§5.2** | 客观裁决返回五类之一（确定 / 范围 / 有机制依据的不确定或随机 / 较低精度可用 / 明确无法裁决）；**不得伪造精度或确定性** | 方法须给出五类的判定与记录方式，并使「无法裁决」接回缺口判定 | 五类的记录形式 |
| **§6** | 不把定性与定量视为两种模型；一个模型可支持定性关系 / 区间阈值 / 数值计算 / 随机分布；定量 = 状态参数代入机制模型求值；参数属世界状态或当前裁决实例；模型应声明支持的精度 | 方法须让每个模型**声明其精度阶梯**，并让「参数属状态还是属裁决实例」可判定 | 精度阶梯的表达形式；参数归属与 §4.2 归属谓词是否合并成一处（原 `C5`） |
| **§7.1** | 机制优先于结果；模型能处理一类问题，对象 / 地点 / 状态改变后仍可用 | 方法须给出**可操作检查**（换对象 / 地点 / 状态是否仍可用） | 检查的形态（问句清单 / 示例集） |
| **§7.2** | 允许基本前提；应尽量最少；能由现有机制推出的事实不应再声明为新前提 | 方法须给出「前提最小化」的核对步骤与前提的登记处 | 核对形式与登记处形态 |
| **§7.3** | 允许未定义；"尚未建模"不等于"不存在" | 方法须使未定义状态**不被误读为「不存在」** | 未定义如何记录（清单 / 就地标注 / 其他；原 `C8` 的一部分） |
| **§7.4** | 禁止四种针对结果的补丁（加有利机制 / 加有利前提 / 补写关键状态 / 在冲突模型中挑有利者） | 方法须给出发现补丁的对照检查；**判断点归创作者** | 自检问句的措辞 |
| **§7.5** | 冲突时检查 6 项（输入状态、适用范围、时间尺度、精度、是否需联合求解、版本变化）；不得用"特殊情况"绕过未解释的冲突 | 方法须给出六项检查的执行方式，并让冲突**可登记、可追踪** | 冲突登记的位置与形式（与原 `C1` 相关但**不同**，见第 3 节） |
| **§8** | 现实可作默认参考但不得把个人常识等价于现实规律；物理/生理/工程可较直接借用；社会规范/组织/家庭/权力/声誉/群体决策需明确适用条件，必要时建专门机制 | 方法须让借用现实知识**附带适用条件声明**；高度情境化问题须条件明确 | **是否给出可操作的「稳定性」划界判据** → `C2`（创作者裁定） |
| **§9** | 新模型最低要求 **11 项**；初期允许自然语言、不要求数学化；结构化和工具化只在重复使用确有价值后进行 | 方法须让 11 项**均被处理**（不得缩水），并给出可填写的结构；允许自然语言起步 | **哪些项允许以「未知 / 尚待验证 / 不适用」作为显式结果；未完成状态是否阻止注册或限制可声明的裁决能力** → `C3`（创作者裁定，已按 `A-001-F-003` 改写） |
| **§10** | 缺口判定五步；只有仍无法解决才认定缺口并启动建模 | 方法须把五步落成可执行顺序，并明确第①步判"不是客观世界问题"时的回绝与回流 | 清单形态 |
| **§11** | 模型允许扩展与修订；修订后**应能识别**哪些能力受影响、哪些过去裁决依赖旧版本、哪些需重算；世界模型只声明有效 / 失效 / 需重查；作品如何处理既有剧情不属本方法职责 | **追溯不变量**：过去裁决必须能追溯到其使用的模型版本（与 §4.3 一致） | 实现方式（逐条记录 / 反向索引 / 按能力维护索引）——属实现技术（原 `C4` 已按 `A-001-F-004` 改正） |
| **§13** | 十项指导；最低可用结果（针对一个真实客观问题跑通完整闭环）；末段授权（可指出原文不合理假设并提替代方案） | 方法须让十项各有落点；"最低可用结果"作为可执行判据；并给出提出异议的位置 | **是否单设「对原文假设的异议」一节**（原 `C7`） |

#### 5. 对 `I-205` 的影响

`I-205` 收窄为**三项需创作者裁定**（`C2` / `C3` / `C6`）；`C1` / `C4` / `C5` / `C7` / `C8` 由 W2 给默认设计，创作者**审阅**（不再作为前置裁定门禁）。最晚需要阶段仍为 **W2 冻结前**（`C2` / `C3` / `C6` 的裁定在 W2 正文定稿前完成即可，不阻断 W2 起草）。

### 为什么

- `A-001-F-001` 指出的混淆是真问题：把"助手推出的实现方案"写成"直接采纳"，等于让 W1 悄悄替 W2 定设计；三层分离让 ①②③ 各自可核对，也让 W2 有明确的设计空间。
- `A-001-F-002` 的更正防止我们在 W1 阶段就锁定一个架构（共用权威索引），而那是 W2 该决定的事。
- `A-001-F-003` / `F-004` 防的是两种做歪方法的方式：**把"最低要求 11 项"缩水成小表单**，以及**把追溯不变量降级为存储粒度选择**（后者会让人挑一个便宜但满足不了 §11 的方案）。
- `A-001-F-005` 的过滤规则解决"审批瓶颈"：创作者的时间应花在语义 / 责任边界 / 成本 / 不可逆承诺上，而不是文档组织。

### 未选方案

- **保留 `D-004` 原样、只补一句"部分为推导"**：未选。不解决"哪一层是哪一层"的可核对性。
- **把 §4.1 / §5.1 / §7.5 合并为一个权威索引**：未选（暂）。三者相关但不同，先由 W2 给默认设计；若 W2 认为应统一，再在 W2 决定并留痕。
- **把 §9 十一项设为"最小必填集 + 其余可空"**：未选。这正是审计指出的语义降级；改为"均须被处理 + 显式未完成状态"。
- **把 `C4` 作为二选一交给创作者**：未选。不变量已由 §11 + §4.3 确定，实现方式不需创作者裁定。
- **`C1`～`C8` 全部保留为创作者裁定**：未选。用户已确认改用过滤规则，避免审批瓶颈。
