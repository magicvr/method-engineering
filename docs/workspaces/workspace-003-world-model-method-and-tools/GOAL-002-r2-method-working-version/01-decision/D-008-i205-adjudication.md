## D-008 · `I-205` 三项裁定落盘并开始 W2（含默认章节顺序）

### 触发

用户 2026-09-26 就 `I-205` 的三项需创作者裁定的方法设计选择给出结论（`C2` / `C3` / `C6`）。W1 产物已由 [`D-007`](D-007-w1-freeze.md) 冻结为 W2 输入，审计门禁已解除，故本条同时**开始 W2**。

### 决定

#### 1. `C2`（§8 现实参考的使用边界）——**采纳选项 1，并按创作者细化后的措辞**

- **不建立统一的「稳定性」总判据**；以**举例**与**显式适用条件声明**为主。
- **措辞细化（取代 [`D-005`](D-005-w1-mapping-revision.md) / [`D-006`](D-006-response-a002.md) §8 行的 ② 措辞；① 层与 ③ 层的分层原则不变）**：
  > 不是所有现实参考都必须声明"文化 / 制度 / 组织条件"，而是**必须声明与该参考相匹配、且可能影响裁决有效性的适用条件**；对于**社会规范、组织行为、家庭关系、权力结构、声誉传播、群体决策**等高度情境化问题，**文化 / 制度 / 组织等条件必须显式说明**。若**关键适用条件无法明确、且会实质影响裁决结果**，则应**建立专门机制**或**拒绝当前精度的裁决**。
- 由此，"拒绝裁决"在 §8 有了与 §5.2 一致的第二个触发点（适用条件不可明确），不再是只由精度不足触发。

#### 2. `C3`（§9 十一项的完成语义）——**采纳：不阻止注册，但限制可声明的裁决能力**

- §9 的**十一项均须被处理**，但允许以「**未知 / 尚待验证 / 不适用**」作为**显式结果**；
- **未完成状态不阻止（暂定）注册**，但**限制可声明的裁决能力**：能力声明**不得超过**未完成项所允许的范围；
- 「**关键项未知**」属**应拒绝裁决**的情形（与 §5.2「明确说明无法裁决」衔接）；
- 理由：既不阻碍按需增长（不要求一次填满），也不把"未知"当作"已支持"。

#### 3. `C6`（§3 按需扩展循环）——**确认立为「总流程」章；章节顺序授权助手默认设计**

- **确认**：把需求原文 §3 的按需扩展循环立为方法的「**总流程**」章，它是**整套方法的运行主线**——没有真实客观裁决需求时**不主动扩展世界模型**；出现真实需求后，**能力发现、缺口判定、最低充分建模、注册、裁决、检查与返回**均作为该循环各步骤的**展开**。
- **明确不作裁定**：「总流程章必须置于三概念章之前」**不是**本次裁定的一部分。**章节顺序属 W2 的文档组织设计，由助手给出默认方案**（创作者审阅），可在**必要的最小概念导入之后**再进入总流程。
- 依此，助手采用的**默认章节顺序**（见第 4 节）不构成本条的门禁项；创作者审阅时可直接调整。

#### 4. W2 章节顺序（**助手默认设计**，创作者审阅）

R1 冻结的「九章结构（§4～§11 + §13 映射）」原文为**至少含**，`C6` 新增总流程章后共 **10 章**；顺序如下：

| 序 | 章节 | 对应需求原文 |
|----|------|--------------|
| 前言 | 本方法是什么 / 执行主体与协作位 / 留痕约定 / 不主张 | §13 最低可用结果、协作约束 `D-003` |
| 1 | **最小概念导入**：世界模型 / 世界状态 / 裁决结果 + **归属判定谓词** | §4 |
| 2 | **总流程**：按需扩展循环（六步 + 不主动扩展纪律） | §3（`C6`） |
| 3 | 能力发现与客观裁决（两类对外服务、五类返回、不得伪造精度） | §5 |
| 4 | 裁决精度声明 | §6 |
| 5 | 模型构建原则与执行检查 | §7 |
| 6 | 现实参考的使用边界 | §8（`C2`） |
| 7 | 新模型的最低要求与条目结构 | §9（`C3`） |
| 8 | 能力缺口判定（五步） | §10 |
| 9 | 版本、追溯与旧裁决 | §11 |
| 10 | 条款映射与对本方法假设的异议 | §13 |

理由：先给**必要的最小概念**（读者需先知道"模型/状态/裁决"指什么），再给**运行主线**（总流程），随后按循环的步骤次序展开各章；§13 的映射与异议放末尾作为对照与修正入口。

#### 5. 信息项

`I-205`（`C2` / `C3` / `C6` 三项裁定）→ **`verified`**。`C1` / `C4` / `C5` / `C7` / `C8` 已按 [`D-005`](D-005-w1-mapping-revision.md) 第 4 节降为「助手默认设计 + 创作者审阅」，不构成裁定门禁。

### 为什么

- `C2` 的措辞细化解决了原措辞的一个过宽之处：若要求**所有**现实参考都声明"文化/制度/组织条件"，会把物理/生理/工程类参考也套上不必要的负担；改为"**与该参考相匹配、且可能影响裁决有效性**的适用条件"后，要求仍严格，但边界正确。而"关键适用条件无法明确 → 建专门机制或拒绝当前精度"给了可执行出口，避免用"现实通常如此"糊过去。
- `C3` 的选法把"知识不完备"变成**能力声明纪律**而不是**注册门槛**：按需增长要求模型可以在信息不全时先建立，但**不得声称超出实际支撑的裁决能力**。
- `C6` 的确认使方法有了**单一主线**；而顺序授权避免了把文档组织问题升级成创作者裁定——这正是 [`D-003`](D-003-executor-boundary-revision.md) 过滤规则的用意。

### 未选方案

- **`C2` 给出统一的"稳定性"总判据**：未选（用户裁定）。判据过硬会变成新教条，而原文只给了两组举例。
- **`C2` 要求所有现实参考都声明文化/制度/组织条件**：未选。对物理/生理/工程类参考不必要；改为"相匹配且影响有效性的适用条件"。
- **`C3` 未完成即阻止注册**：未选。会阻碍按需增长。
- **`C3` 未完成不影响能力声明**：未选。会把"未知"当成"已支持"。
- **`C6` 由本条一并决定总流程章的**位置**：未选。用户明确不作裁定，属 W2 文档组织设计。
- **把 10 章顺序作为裁定项提交创作者**：未选。违反升级过滤规则（结构设计由助手给默认方案）。
