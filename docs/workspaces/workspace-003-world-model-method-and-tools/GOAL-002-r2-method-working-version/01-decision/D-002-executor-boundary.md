## D-002 · 方法执行主体约束：构建人是创作者，不是 AI 助手

### 触发

用户在 R2 启动后提出需求澄清：「世界模型主要的构建人其实是创作者，而非 AI 助手，这一点非常重要。否则我们可能会搞出一个空转的方法。」

该澄清已由下游仓登记并交付：`WorldModel.ModernCultivation` @ `8219dc6`（分支 `dev/vp-002`）的 `exchange/WRK-002-world-model-method-and-tools/需求澄清-2026-09-26-构建主体.md`、其 `D-005` / `E-006`。它收敛的是需求原文 §13「希望方法工程最终提供一套**可以实际运行**的工作方法」中的**执行主体**——原文没有写明由谁执行。

### 决定

1. **执行主体 = 创作者（人）**：方法必须由创作者本人执行完成；**不得以任何 AI 助手能力为前提**，也不得把建模判断设计成需要 AI 代为完成。
2. **助手边界**：AI 助手不是构建人。在本目标内，助手只承担**记录、整理、检索、格式核对**等非判断性工作，且须逐次授权、逐条标明。**不得**由助手承担「这是不是一个客观问题 / 现有模型够不够 / 缺的是状态、组合、精度还是机制 / 新模型是否只是当前案例的补丁」这类判断，也不得用助手产出的判断冒充创作者判断。
3. **方法须自证可人工执行**：W2 的每一章须标明——判断主体（创作者）、所需的人工判断、可委派的非判断性工作、**不得委派项**；W3 的两个最小结构须逐项核对**人工可填性**（字段不依赖任何程序或 AI 输出）。
4. **空转的四种禁止形态**（W2 与 W4 须逐条对照检查，并在 W4 结论中给出证据）：
   - **A 判断外包**：把判断交给助手或工具，创作者只做确认；
   - **B 过程代替内容**：只在登记表、清单或索引里流转，不产出可裁决的机制模型正文；
   - **C 框架先行**：要求先建完整框架再建模，违背按需增长；
   - **D 不可复现**：产出依赖未留痕的助手推理，创作者或他人无法复核。
5. **W4 的核对执行主体是独立问题**：由本约束推出——若 W4 的适用性核对由**助手**执行，它就不能证明「方法对创作者可用」。本项登记为 `I-204`（required，责任人用户，最晚 W4 开始前）；**裁决前不把助手执行的走查当作 W4 证据**。
6. **与 R1 冻结的关系**：交付物构成**不变**（方法工作版 + 两个最小结构）。本约束只提高方法正文与最小结构的自证要求，**不构成范围扩张**。
7. **与下游纪律同向**：下游 `world/README.md` §3 与 workspace-001 `I-005` 的「纯人工纪律、不引入工具」是同一取向；本决定**不新设**更松或更严的规则，只把「谁执行方法」写明。

### 为什么

- 需求原文 §13 的「最低可用结果」是**创作者**针对真实创作问题跑通闭环。若方法只在 AI 执行下成立，这个检验就是假的——这正是用户指出的空转风险。
- 世界模型由创作者在创作实践中形成与使用；AI 产出不可复现、不可追责，把它写进方法会使其成为事实上的成功条件，与下游 Charter「不以工具或发布产物为成功条件」及其 `I-005` 冲突。
- 把「判断主体 / 不得委派项」定为方法正文的必填内容，使「创作者可用」这件事**可被核对**，而不是靠承诺。
- 把 W4 的执行主体登记为 `I-204` 而非当场决定，是因为它会实质改变 W4 的工作量与证据归属，属 P-004 用户裁决点。

### 未选方案

- **把澄清当作范围扩张（新增「人机协作方法」等交付物）**：未选。用户说的是**构建主体**，不是新增交付物。
- **借澄清把工具禁令收紧为永久禁止**：未选。工具化的触发条件与再议路径仍按 R1 冻结（重复使用确有价值后另行澄清，按下游 `I-005` 裁决）。
- **沿用默认分工、直接规定 W4 由助手执行**：未选。会与刚登记的约束直接冲突，使 W4 失去证明力。
- **直接规定 W4 必须由创作者全程手跑**：未选（本轮）。这是对用户工作量的实质安排，须用户裁决（`I-204`）。
- **只在 D/E 里记录约束、不写进 W2/W3/W4 的退出条件**：未选。那样约束不会被核对，等于没有约束。

- 本目标 `progress` **仍为 0%**（0/4）：本决定只改退出条件，**不完成任何工作包**。
- 目标树同步子目标备注；Root 级事项不变（约束经子目标落地）。
- 运行主记录追加 [`events.md`](../../../../../runtime-records/WRK-002-world-model-method-and-tools/events.md) EV-005（需求澄清：构建主体为创作者）；状态保持**「响应中」**。
- **未发生**：方法工作版与两个最小结构尚未形成；交付、实际收件、验收与退出均未发生。
