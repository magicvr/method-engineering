## D-003 · 修正执行主体约束：助手应尽可能协助，但不得代劳

### 触发

用户在 [`D-002`](D-002-executor-boundary.md) 登记后立即指出该约束**过强**，原话：「事实上我们希望 AI 助手尽可能的协助创作人，只是不能代劳（创意的主题和决策应当属于创作人，但是 AI 助手完全给与提示和引导）。」

`D-002` 把助手限制在「记录、整理、检索、格式核对」等非判断性工作，并禁止其对「是否客观问题 / 现有模型够不够 / 缺哪一类 / 是否只是补丁」给出判断——这与用户意图不符。下游已同步修正材料与台账：`WorldModel.ModernCultivation` @ `e9054c9`（分支 `dev/vp-002`）的 `exchange/WRK-002-world-model-method-and-tools/需求澄清-2026-09-26-构建主体.md`（第 2 版修正节）与其 `D-006` / `E-007`。

### 决定

**本条取代 `D-002` 第 1 项后半、第 2 项与第 4 项 A 形态；`D-002` 原文保留，其余各项继续有效。**

1. **决策权属于创作者——这就是「不代劳」的含义**：世界模型的**主题、取舍与最终裁决**属于创作者。助手**不得代劳**：不得在创作者未实际参与判断的情况下确定结论并直接采用。
2. **助手应尽可能协助**：助手**可以且应当充分**提供提示、引导、候选方案、示例、追问、反例、检查与整理。对「这是不是客观问题 / 现有模型够不够 / 缺的是状态、组合、精度还是机制 / 新模型是否只是当前案例的补丁」等判断点，助手**可以给出建议与理由**；但**结论必须由创作者作出**。
3. **界线判据（可操作）**：助手给建议 + 创作者裁定 = **协助**（允许且鼓励）；助手**直接确定结论并被采用**，或创作者退化为**被动确认** = **代劳**（禁止）。
4. **方法须标明人机协作位**：每章写明——① 必须由创作者作出的决定（决策点）；② 助手可用的协助形式（提示 / 候选 / 反例 / 检查 / 追问 / 整理）；③ 不得越过的界线；④ **留痕要求：建议与裁定分开记录**，使「结论是谁作的」可核对。
5. **不以 AI 为前提，也不禁止**：方法不把 AI 助手设为成功条件，也不假定必须无助手；二者都不是验收口径。验收口径是「**创作者能据方法作出决定并完成闭环，且协作位与留痕清楚**」。
6. **两个最小结构**：由创作者填写即可（无论是否借助助手协助）；字段不依赖任何程序输出。若借助助手填写，结构与留痕应能区分「建议」与「创作者裁定」。
7. **四种空转形态（修正 A）**：
   - **A 代劳**：判断结论由助手直接确定并被采用，或创作者只做被动确认；
   - **B 过程代替内容**：只在登记表、清单或索引里流转，不产出可裁决的机制模型正文；
   - **C 框架先行**：要求先建完整框架再建模，违背按需增长；
   - **D 不可复现**：产出依赖未留痕的助手推理，无法核对「结论是谁作的」。
8. **其余不变**：交付物构成、限额、需求范围均不变（见 `D-001` 与 `D-002` 第 6、7 项）。

### 为什么

- 用户要防的是**空转**，而不是助手参与。空转的根源是「决策无人负责、结论不可复核」，不是「助手给了建议」。
- 把助手压到只能做文书工作，会让创作者失去有价值的提示与反例，方法反而可能更难用——这与「可以实际运行」背道而驰。
- 「建议与裁定分开记录」使「谁作的结论」可核对：既允许充分协助，也守住了不代劳的界线。
- 因此本约束的落点从「限制助手做什么」改为「确定谁作结论、并要求留痕可核对」。

### 未选方案

- **保留 `D-002` 原约束**：未选。用户明确指出过强。
- **改成「助手可自由判断、创作者事后抽查」**：未选。会让创作者退化为被动确认，正是用户要防的代劳。
- **要求方法必须在无助手条件下完成**：未选。用户未提出该要求；强加会变成另一种过强约束。
- **把「尽可能协助」写成必须使用助手**：未选。会把助手变成成功条件，与下游 Charter「不以工具或发布产物为成功条件」冲突。
