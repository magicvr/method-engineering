## D-010 · 响应独立审 A-005：出草稿 v0.3、收回 W2 完成标记、处理 F-004

### 触发

独立审 [`A-005`](../03-audit/A-005-w2-independent-review.md)（`source: independent`，auditor = Grok 4.7，保证等级 **L0**，verdict **`conditional`**）对草稿 `v0.2` 与 `A-004` 的自闭合做复核：**3 条 required**（`F-001` / `F-002` / `F-003`）+ **1 条 recommended**（`F-004`）；明确**不能确认** `A-004-F-001` 完全闭合；并指出两处台账分歧。

用户 2026-09-26 逐项裁决：① **收回 W2 完成标记**（子目标 `progress` 50% → 25%）；② `F-004` 按「**机制未知可暂定注册，但能力声明必须收窄**」处理；③ 三条 required 修完后**另交一次独立 closure check**。

### 决定

1. **出草稿 `v0.3`**（`v0.1` / `v0.2` 均**保留**为历史）：
   - **`F-001`**：第 2 章步表重排——步 ⑦「完成裁决」**成为每条向下路径的必经步**；**分开写明五条出口**（已支持 / 缺状态 / 缺组合 / 缺精度 / 缺机制）并逐条标明"经过步 ⑦"；补一句"步 ③ / ④ 只确定输入与路径，不产生裁决结果"。
   - **`F-002`**：第 10 章第 7 行改指 **第 7 章新增的「适用范围与条件敏感性的最低核对」**；该节写明最低核对动作（写出适用范围边界 → **挑一类条件改到边界之外**、核对结论是否确实改变 → 记录"改了哪一类、改成什么、结论如何变化"；**只写"做过检查"不算完成**）。
   - **`F-003`**：第 8 章新增「**本方法不覆盖的事项（需求原文 §12 十一项）**」一节（逐项列出、写明走步 ① **回绝并回流**、给出与"客观影响"的区分）；**不新开章**——W2 退出条件冻结的是"共 10 章"，`A-005` 用的词也是"一节边界声明"。
   - **`F-004`**：第 7 章"关键项"默认清单改为 **关键项** = ⑥适用范围 / ⑦精度 / ⑨拒绝裁决条件；**条件关键项** = **⑤机制**——机制未写明**不阻止暂定注册**，但**能力声明必须收窄**（不得声称可独立裁决，并写明允许的返回类别）。附录 C `D-e` 同步。
2. **收回 W2 完成标记**：本目标 `progress` **50% → 25%**（1/4）；W2 记「**整改中**」，待 `F-001`～`F-003` 经独立 closure check 确认闭合后**重新记完成**。理由：`A-005` 明确列出两条 W2 退出条件行为"不满足"（总流程闭环与全部出口；`E2` 的 §12 边界节），则当时"W2 记完成"的主张不成立——与上一轮更正 `A-001-F-001` 同一口径。
3. **修正以 `fixed` 落盘，但不自行宣告闭合**：`A-005` 系**独立审**，按 `A-002` → `A-003` 先例交**独立 closure check** 确认；台账记「修正已落盘、待 closure check」。请求包见 [`../attachments/closure-check-request-A-006.md`](../attachments/closure-check-request-A-006.md)。
4. **`A-004-F-001` 的闭合主张按 `A-005` 要求收窄**：改为「新建模型路径（⑤→⑥→⑦→⑧→⑨）已改、**其余路径仍开放**」，指向 `A-005-F-001`；该更正**追加**在 `A-004` 响应节，**不改写**其原文。
5. **两处台账分歧已修**：`goal-tree.md` 中 `GOAL-002` 备注末句的过时句；Root `00-meta` 成功标准 R2 行**不再复制派生进度数字**（改为指向子目标 `00-meta`），以免两处分叉。

### 为什么

- `A-005-F-001` 是**真缺陷**：上一轮整改只补了"无真实需求 → 停止""非客观问题 → 回绝"两个出口，**没有逐条核对每条向下路径是否都经过步 ⑦**。步 ⑧ 检查的对象是"**那一次裁决**"；"已支持"与"非机制缺口"两条路径上根本不存在这一拍。**独立审抓到的是自审的盲区**（自审容易只核对自己改过的地方）。
- **收回标记而非保留**：`progress` 若在"退出条件未满足"时仍显示 2/4，数字就变成装饰；P-003 也要求未闭合 required 时不得推进对应门禁。收回后 W3 自然冻结，直到闭审确认。
- **`F-003` 放在第 8 章而非新开章**：冻结结构是"共 10 章"；边界声明属"节"不属"章"，放回绝闸门所在章最贴合执行点。
- **`F-004` 按裁定**：机制未知仍允许暂定注册（不阻碍按需增长），但**能力声明必须收窄**（不把"未知"当"已支持"）——与 `C3` 的精神一致。

### 未选方案

- **保留 W2 完成标记到复审**：未选（用户裁定收回；且会让台账同时存在"已完成"与"退出条件未满足"两个口径）。
- **把 §12 边界新开一章**：未选（破坏冻结的 10 章结构）。
- **由编排器自行宣告三条 `fixed` 闭合**：未选。`A-005` 是独立审；按 `A-002` → `A-003` 先例，闭合须由独立 closure check 确认。
- **把 `F-004` 记 residual 而不改 `D-e`**：未选（用户裁定按"收窄能力声明"处理）。
