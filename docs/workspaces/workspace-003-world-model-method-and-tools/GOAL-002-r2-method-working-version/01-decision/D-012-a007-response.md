## D-012 · 响应独立审 A-007：修订 D-008 关键项绝对句、出草稿 v0.4

### 触发

独立审 [`A-007`](../03-audit/A-007-w2-v03-prefreeze-review.md)（`source: independent`，GPT Web 会话、由用户转述并代贴，verdict **`conditional`**）：草稿 `v0.3` 五处**局部规则过强**——**3 条 required**（`F-001` 替换检查未限定在所声称的适用范围内；`F-002` 条件敏感性的负向结果被写成可**自动删除边界**；`F-003` 「关键项未知 → 应拒绝裁决」的**绝对句**与同章收窄纪律冲突）+ **2 条 recommended**（`F-004` 第 6 章判断点仍在要求给现实参考**分类**；`F-005` 第 8 章入口句把"缺口是否存在"写成"该不该建模"）。`A-007` 明确**不收回** W2 完成标记，但**在三条 required 合法闭合前不建议把这三处规则写进 W3**。

用户 2026-09-26 三项裁决：① `F-003` 按审计建议**改为依赖式**（即修订 `D-008` 第 2 节那一点）；② 三条 required 与两条 recommended **一并修**；③ 出草稿 `v0.4` 后**交独立 closure check**。

### 决定

1. **修订 `D-008` 第 2 节的关键项绝对句**（本条即该点的正式修订留痕；`D-008` **原文不改写**，仅追加修订说明）：
   - 原（绝对句）：「关键项未知属应拒绝裁决的情形」。
   - **修订为依赖式**：「关键项未知，**且当前裁决依赖该未知部分、无法证明处于已知有效边界内**时，应拒绝裁决；若当前裁决**完全落在已经明确、且不受该未知项影响的子范围内**，可按**收窄后的能力声明**裁决。」
   - 依据：与同条「**不阻止（暂定）注册，但限制可声明的裁决能力**」的收窄纪律一致，也与 [`D-010`](D-010-a005-response.md) 对机制未知的裁定（可暂定注册、能力声明须收窄）一致；原绝对句会把"已知子范围内本可裁决"一并禁掉。
   - **`C3` 的其余内容全部不变**（十一项均须被处理、允许「未知 / 尚待验证 / 不适用」为显式结果、不阻止暂定注册、能力声明不得超过未完成项所允许的范围、⑤机制为**条件关键项**）。
2. **出草稿 `v0.4`**（`v0.1` / `v0.2` / `v0.3` 保留）：
   - `F-001`：第 1 章归属判定谓词与第 5 章「机制优先于结果」的执行检查**限定在"所声称的适用范围内"**；明确"机制可以合法依赖地点、制度或对象类型；跨出其自身适用边界后失效只说明**越界**，**不因此变成世界状态**"；**保留**"若适用范围只覆盖当前这一个案例，仍不合格"。
   - `F-002`：第 7 章条件敏感性核对改为 **challenge test**（故意改变一个**已声明**的边界条件，观察**失效 / 需换机制 / 精度下降 / 依据不足**）；**没有暴露变化时只记"本次检查未证明该条件敏感"，然后重新审视边界依据，明确"不得据此自动删除该边界条件"**。
   - `F-003`：依赖式落文；附录 C `D-e` 同步。
   - `F-004`：第 6 章判断点改为"哪些适用条件可能影响该参考的有效性""是否属需要显式文化 / 制度 / 组织条件的高度情境化问题"；**留痕栏位同步去掉"本参考的类别"**；协作位增"不得替创作者给参考贴分类标签"。
   - `F-005`：第 8 章入口句改为"**是否存在新的世界模型能力缺口**的判定入口"；已知边界仍写明"不判定值不值得建"。
3. **不收回 W2 完成标记**：`A-007` 明确不改 `status` / `progress` / `goal-tree`，且其 scope **不是** W2 退出条件的重审——它指出的是 `v0.3` 的**局部规则过强**，而非退出条件行不满足。子目标 `progress` 保持 **50%**（2/4）。
4. **W3 暂缓**：按 `A-007` 的建议，三条 required 合法闭合前**不把这三处规则写进 W3 的两份最小结构**。
5. **不自行宣告闭合**：`A-007` 系**独立审**，按 `A-002` → `A-003`、`A-005` → `A-006` 先例交**独立 closure check**；请求包见 [`../attachments/closure-check-request-A-008.md`](../attachments/closure-check-request-A-008.md)。

### 为什么

- **`F-001` 是真缺陷**：机制**可以合法依赖制度或地点**——"某制度下组织如何运作"仍是机制。原文把"跨出自身适用边界后失效"与"不是一类问题的机制"混为一谈，会让合法的情境化机制被误判成世界状态。
- **`F-002` 是我写下的逻辑错误**：一次越界扰动**没有**改变结果，只证明"**这次**扰动没暴露边界"（扰动幅度不够、结果局部稳定、真正失效点更远，都可能）；据此自动删除边界条件，等于用一次无效实验反证边界不存在。
- **`F-003` 必须经创作者裁决**：绝对句是 `D-008` 的**落盘原文**，不是草稿抄错；编排器不得当笔误改字。改为依赖式与 `C3` 的全部其他内容自洽，并保住了"已知子范围内仍可裁决"。
- **不收回 W2 标记**：与 `A-005` 那次不同——`A-005` 明确列出**两条 W2 退出条件行"不满足"**；`A-007` 明确声明不审退出条件、不改标记。为"看起来一致"而机械收回，会造成另一种台账失真。

### 未选方案

- **保留绝对句、把收窄纪律限定为"仅非关键项可暂定注册"**：未选（用户裁定依赖式；且那会把"已知子范围内本可裁决"也一并禁掉，与 `C3` 的按需增长意图相悖）。
- **在 `v0.3` 上就地改字而不留修订决定**：未选（绝对句是 `D-008` 的落盘内容，必须有正式修订留痕；`D-008` 原文不改写）。
- **收回 W2 完成标记**：未选（`A-007` 明确不改，且其 scope 非退出条件重审）。
- **修完由编排器自行宣告闭合**：未选（独立审的 required，按先例交独立闭审）。
