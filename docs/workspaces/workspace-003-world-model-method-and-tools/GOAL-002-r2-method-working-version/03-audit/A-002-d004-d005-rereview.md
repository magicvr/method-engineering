## Findings

### `A-002-F-001`（**required**）§6 将"支持什么精度"强化为"必须声明精度阶梯"

**现状**：`D-005` 已规定三层结构；但 §6 第二层写为「方法须让每个模型**声明其精度阶梯**，并让「参数属状态还是属裁决实例」可判定」。而 `D-004` 所映射的原文要求是：「一个机制模型可能只给定性关系、可给区间或阈值、可用具体参数做数值计算、可描述有明确随机机制的结果分布；**模型应明确自己支持什么精度**。」

**问题**：原文要求的是「模型应明确其能够支持什么裁决精度」，这**并不必然推出**「每个模型都必须存在一套『精度阶梯』」。例如一个模型当前只支持定性方向判断、不支持区间、不支持具体数值，它已经可以完整、准确地声明自己的精度能力，并不需要形成"阶梯"。因此「精度阶梯」**属于一种可能的表达或组织方式**，应留在第三层，而不应作为第二层的强制方法要求。

该问题与 `A-001-F-001` 属**同一种问题**：将一种合理的 W2 实现设计提升成 W1 已经推出的方法义务。

**Required fix**：第二层改写为类似——

> **方法须让每个模型明确声明当前支持的裁决精度或精度形态，以及其无法支持的精度边界；若存在多个可用精度层级，应能够表达这些层级之间的关系。**

第三层保留：精度能力采用何种形式表达；是否采用"精度阶梯"；多层精度如何记录及展示。完成此修改后，本 finding 可关闭。

### `A-002-F-002`（**advisory**）§7.2 第二层提前规定"前提登记处"

**现状**：§7.2 第二层为「方法须给出『前提最小化』的核对步骤与**前提的登记处**」；第三层已写「核对形式与登记处形态」。

**问题**：原文约束要求的是基本前提允许存在、应尽量保持最少、可由既有机制推出的事实不得重复声明为新前提。由此第二层确实可推出「方法必须让基本前提**能够被明确识别**，并允许检查它是否可由既有机制推出」；但"**必须存在一个登记处**"已略微接近第三层的承载设计。

**建议修订**：第二层改为——

> **方法须使基本前提可被明确识别、引用，并提供「是否能够由已有机制推出」的最小化核对步骤。**

第三层再决定：是否集中登记；是否就地声明；登记位置及记录形态。本项**不致方法语义错误，列为 advisory，不阻断 W1 冻结**；但既然本轮修订目标正是严格清理 ②/③ 边界，建议一并修正。

### `A-002-F-003`（**advisory**）§13 第二层提前要求"给出提出异议的位置"

**现状**：§13 第二层为「方法须让十项各有落点；『最低可用结果』作为可执行判据；并**给出提出异议的位置**」；第三层又把「是否单设『对原文假设的异议』一节」作为实现问题 `C7`。

**问题**：§13 原文只是**授权**——"如果现有要求中存在不合理假设，应指出具体问题并提出替代方案；不要求为了保持本文结构而保留没有实际价值的设计"。由此可推出的第二层要求是「**方法必须允许提出异议，并能够承载替代方案**」，但**不能**直接推出「必须存在一个专门的『异议位置』」。"异议在哪里出现、是否单设一节"仍属第三层文档组织设计。

**建议修订**：第二层改为——

> **方法须允许并承载对需求原文不合理假设的异议及替代方案，不得因既有文档结构阻止必要修正。**

第三层继续保留：是否单设异议章节；是否就地记录；如何与需求原文建立引用关系。同为 advisory，可与 `F-002` 一并顺手修正。
