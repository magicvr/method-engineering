## Findings

### `A-007-F-001` · 机制 / 状态的替换检查没有限定在声明的适用范围内

| 字段 | 值 |
|------|-----|
| 严重度 | med |
| 建议 | **required** |
| 状态 | **open** |

**证据**（`v0.3`）：

- 第 1 章归属判定谓词：「把这条内容里的具体对象、地点、时刻替换掉，关系是否仍然成立？仍成立 → 机制；只有在特定取值下才有意义 → 状态」。
- 第 5 章「机制优先于结果」的执行检查：「换对象、换地点、换状态后模型是否仍然可用？只对当前案例成立 → 不合格」。

一条机制可以合法依赖地点、制度或对象类型。「某制度下组织如何运作」仍是机制；换到另一个制度环境后失效，只说明越出了它自己的适用条件，不因此变成世界状态。现行两处检查把「跨出适用边界后不再成立」当成「不是机制」。

**关闭要求**：第 1 章与第 5 章统一改为在所声称的适用范围内作替换：对具体对象、地点、时刻或状态取值作替换后，该关系是否仍作为同一机制适用。检查的是「是不是一类问题的机制」，不是要求机制跨越自己的适用边界。

### `A-007-F-002` · 条件敏感性的负向结果被写成可以删除边界

| 字段 | 值 |
|------|-----|
| 严重度 | med |
| 建议 | **required** |
| 状态 | **open** |
| 关联 | `A-005-F-002` 已要求写出最低核对；本条不重开该闭合，只审核对规则的负向推论 |

**证据**（`v0.3` 第 7 章「适用范围与条件敏感性的最低核对」）：挑一类条件改到范围之外；结论改变则记下变化；结论不变则「该条件其实不构成限制，应从适用范围中移出，或说明真正的边界在别处」。

一次越界扰动没有改变结果，只证明这次扰动没有暴露边界。越界幅度不够、结果局部稳定、真正失效点更远，或该范围是知识有效范围而不是结果突变范围，都会得到「结论不变」。据此自动删除边界条件，在方法上不成立。

**关闭要求**：改成 challenge test。改变一个已声明的边界条件，观察模型是否失效、需要换机制、精度下降或依据不足。若没有暴露变化，只记录「本次检查未证明该条件敏感」，然后重新审视边界依据，不能自动删除边界条件。

### `A-007-F-003` · 「关键项未知 → 应拒绝裁决」与同章收窄规则冲突

| 字段 | 值 |
|------|-----|
| 严重度 | med |
| 建议 | **required** |
| 状态 | **open** |
| 关联 | `D-008` 的 `C3`；`D-010` 对 `A-005-F-004` 的裁定；附录 C `D-e` |

**证据**（`v0.3` 第 7 章）：

- 完成语义写明：未完成不阻止暂定注册，但能力声明不得超过未完成项所允许的范围。
- 同节下一句：「关键项未知属应拒绝裁决的情形」。
- 默认设计又写：⑥ 适用范围、⑦ 精度、⑨ 拒绝裁决的条件任一为未知时，能力声明必须相应收窄或标注为受限。⑤ 机制未写明不阻止暂定注册，能力声明收窄。

按绝对句，关键项只要未知就拒绝裁决。按前后的收窄句，当前裁决若落在已经明确的已知子范围内，仍可裁决；只有依赖未知部分时才收窄或拒绝。两套读法不能同时作为规则。

**台账核对（代贴时补记，不改审计者的关闭要求）**：`D-008` 第 2 节同时写下了收窄纪律，以及「关键项未知属应拒绝裁决的情形」。绝对句是已落盘裁定的原文，不是草稿抄错。审计者把已定口径称为「依赖传播」，与这句字面不完全一致；与同条「能力声明不得超过未完成项所允许的范围」、以及 `D-010`「机制未知可暂定注册，但能力声明必须收窄」则一致。因此本条成立的是规则冲突。把绝对句改成依赖式，是在修订 `D-008` 的那一点，闭合须有创作者书面裁定，不能当成笔误由编排器直接改字。

**关闭要求**：将拒绝句改为——关键项未知，且当前裁决依赖该未知部分、无法证明处于已知有效边界内时，应拒绝裁决。使第 7 章与 `C3` 的收窄纪律、以及 `D-010` 对机制未知的裁定一致。

### `A-007-F-004` · 第 6 章判断点仍要求给现实参考分类

### `A-007-F-005` · 第 8 章把「缺口是否存在」写成了「该不该建模」
