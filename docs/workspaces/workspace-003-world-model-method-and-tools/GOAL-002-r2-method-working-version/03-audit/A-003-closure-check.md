## 通过的三点理由

1. **§6 这次确实修到了正确层级**。第二层现在要求的是模型必须明确声明「当前支持的裁决精度 / 形态」与「**不支持的精度边界**」，只有**若确实存在**多个精度层级时才要求能表达层级关系；「是否采用精度阶梯」已明确降到第三层。这解决了上一轮的核心问题：**只有定性能力的模型不再被迫人为构造"阶梯"**。
   并且「无法支持的精度边界」**不构成新的越界**——它可由 §5.1 / §5.2 支撑：原始映射已要求说明「什么情况下无法裁决」，并禁止为满足调用方伪造不存在的精度或确定性。因此新的 §6 第二层可合理视为**方法能力要求**，而非实现设计。
2. **两条 advisory 已真正清干净**。§7.2 第二层现在只要求「基本前提可明确识别、引用，并进行『能否由已有机制推出』的最小化核对」，集中登记 / 就地声明 / 登记位置与记录形态全部留给第三层；§13 第二层只要求「允许并承载异议和替代方案，不得因文档结构阻止必要修正」，是否单设章节 / 是否就地记录 / 如何引用需求原文都在第三层。二者均符合三层原则，可一并视为 `fixed`。
3. **`D-006` 没有借修复之机改动 W1 的其他语义**。它明确只替换 `D-005` 中这三行的 ② / ③ 单元格，**① 层保持不动，其余 14 行也不动**。这对 closure check 很重要：本轮确实**只是验证并修掉已知 finding**，而没有把 closure check 变成另一轮方法设计。

## 非阻断 bookkeeping advisory（不阻断 `pass`）

`D-006` 写道当前"开放 required 仍记 2"（`A-002-F-001` + `A-001-F-001`）。严格来说这**不是两个独立问题**：`A-001-F-001` 是**父 finding**，`A-002-F-001` 是它在 `A-002` 中发现的**唯一残留实例**。继续同时计为"2 个开放 required"会有**重复计数**。

**建议（面向未来）**：若做自动统计，**父 finding 处于 `partially fixed / waiting child finding` 时，不要与其残留 child finding 重复计入 open-required 数量**；按「独立的开放必改项」计数。
