## Findings

### `A-005-F-001` · 第 2 章已支持路径与非机制缺口路径跳过「完成裁决」

| 字段 | 值 |
|------|-----|
| 严重度 | med |
| 建议 | **required** |
| 状态 | **open** |
| 关联 | `A-004-F-001` 的闭合主张；§13 最低可用结果；W4 将要沿用的主循环 |

**证据**（`v0.2` 第 2 章步表）：

- 步 ② 的出口：「已支持 → 步 ③」。
- 步 ③ 的出口：「→ 步 ⑧（可直接裁决）」。
- 步 ⑦ 才是「完成裁决」：按第 3 章五类返回求值，并记录可追溯五项。
- 步 ⑧ 的定义是「检查（裁决后）」：检查**已经作出**的那次裁决有没有越出已声明的精度或适用条件。

按这张表，现有模型已经支持时，下一步是步 ③，再下一步是步 ⑧。步 ⑦ 不在这条路径上。步 ⑧ 要检查的裁决，在这条路径上没有对应的完成步骤。

步 ④ 写：「非机制缺口 → 按对应路径处理并回 ③ 或终止」。回到步 ③ 之后，出口仍然是步 ⑧。缺状态、缺组合、缺精度没有各自的下一步；「按对应路径处理」在同表中没有对应行。

第 2 章开头把本循环定义为 §13 的最低可用结果：「发现能力缺口 → 构建最低充分模型 → 注册能力 → 完成裁决 → 检查 → 返回创作」。新建模型路径（⑤→⑥→⑦→⑧→⑨）与这个次序一致，两种检查也已分开。已支持与非机制缺口这两条路径没有「完成裁决」这一拍。

`A-004` 响应节与 `D-009` 第 6 项之外的闭合句写的是：九步已对齐，并且「补上全部出口」。步表里的「无真实需求 → 停止」和「非客观问题 → 回绝」确实写上了。上表两条路径的出口与该闭合句不一致。

**关闭要求**：改第 2 章出口，使每条继续向下的路径都先完成裁决（第 3 章五类返回 + 第 1 章可追溯五项），再进入裁决后检查。至少分开写明：已支持、缺状态、缺组合、缺精度、缺机制五条出口。建模期检查仍留在构建模型那一步；裁决后检查仍检查这一次裁决。

### `A-005-F-002` · §13 第 7 项的映射落点里没有条件敏感性核对

| 字段 | 值 |
|------|-----|
| 严重度 | med |
| 建议 | **required** |
| 状态 | **open** |
| 关联 | W2 退出条件中的「可核对映射表」；`D-006` §13 行 ②「十项各有落点」 |

**证据**：

- `D-004` 附表 B 第 7 项的冻结落点是：「章 6（适用范围 / 精度）+ 章 5（§8 适用条件）」。按当时的九章编号，前者是 §9 十一项所在章，后者是现实参考边界。
- `v0.2` 第 10 章把同一项指到「第 4 章、第 6 章」。重编号之后，第 4 章是精度声明（§6），第 6 章是现实参考边界（§8）。
- 第 4 章写的是精度形态、边界，以及「若存在多个层级则表达关系」。第 6 章写的是借用现实知识时要声明的适用条件。两章都没有「改变条件后，结论是否仍然成立」的核对。
- 十一项里的第⑩项（「经过哪些最小条件变化或反例检查」）在第 7 章，映射行没有指向它。该项只要求这项**被处理**，没有写最低核对动作。

读者按映射表去验证「基本适用范围和条件敏感性」时，读到的是精度声明和现实参考条件。适用范围字段与条件变化核对留在第 7 章，且没有操作步骤。

**关闭要求**：改正第 10 章第 7 行的落点，使它指向实际写出适用范围与条件敏感性核对的章节；在该处写明最低核对（改变哪一类条件、什么结果算通过）。只保留「记录做过哪些检查」的字段名，不足以关闭本条。

### `A-005-F-004` · 「关键项」默认清单未包含机制本身

| 字段 | 值 |
|------|-----|
| 严重度 | low |
| 建议 | **recommended** |
| 状态 | **open** |
| 关联 | `D-008` `C3`；`v0.2` 附录 C `D-e` |

**证据**：`D-008` 裁定「关键项未知」应拒绝裁决，但没有枚举哪些项是关键项。`v0.2` 第 7 章把关键项默认定为第⑥适用范围、第⑦精度、第⑨拒绝裁决的条件，并正确标了〔默认设计〕。第⑤项「输入通过什么机制产生输出」不在这三项里。

**建议**：创作者审阅 `D-e`。若机制未知仍允许某类裁决，写明允许的返回类别；否则把第⑤项写入关键项，或写明机制未知即拒绝裁决。
