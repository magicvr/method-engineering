# D-007 · VP-002 与 Root 改为双边协议联调演练

- 日期：2026-09-26
- 状态：accepted
- 决策来源：用户本轮书面指令；编排器整理落盘。
- 影响：VP-002 退出判据、当前 Root 的 R3、I-003/I-007/I-008 和指南演练程序。

## 用户裁决与理由

用户指出原目标既要求完成真实需求响应链路、又排除输出领域方法，会把协议验证卡在方法构建上；要求修改目标，使本 VP 只跑通对接流程，不要求跑通构建流程。依此将 VP-002 与 Root 的退出验证调整为双边协议联调演练。Charter 的长期意图与 VP-001 的真实运行语义保持原义。

## 决定

1. 在真实下游实践仓库，由消费方与方法工程共同使用明确标注的合成、非敏感内容完成一条共享追踪线。双方须实际消费对方交接：信号、回执/澄清、演练专用范围与授权、响应交接、消费方收件/反馈及结束。两侧独立 walkthrough 拼接不构成联调证据。同一人可承担两类角色，但须留存逐步角色切换证据，且不得据此声称独立团队已达成共识。
2. 合成内容仅验证协议交接。演练回应不得被称为真实领域方法响应，不产生方法构建或有效性声明，不创建虚假的 runtime-records/WRK-* 主记录。演练证据由本目标执行台账与附件引用承载。
3. 下游保有路径、格式与工具最终选择权（D-005）。联调及任何下游写入前须确认演练场景、角色、共享追踪与证据、下游选定的承载及写入授权；本决定不预选路径，也不替代具体写入授权。
4. WRK-001 是真实需求，保持「待判定」，移出本次 R3 范围；具体处理须另行确认，不自动建立 VP-003 或接受处理承诺。
5. I-003 改为本 VP 的 non-blocking/open，不声称已验证；日后处理 WRK-001 时仍需其具体授权。I-007 由本次范围裁决解决（resolved）。新增 I-008 required/open，阻断联调与任何下游写入。I-006 指南升格门禁继续保留。
6. Root 保持 active / 67%，R1/R2 历史完成事实保留，R3 为联调准备。范围修订本身不是联调完成或关门证据；修订须经审视。

## 未采用方案

- 保留真实需求完整处理作为退出条件：继续依赖领域方法构建，超出用户明确的本 VP 目的。
- 现在扩展为领域方法交付或直接新建 VP-003：用户尚未决定该真实需求的承接规划，不能静默扩大承诺。
- 删除全部集成验证、仅审核文本：无法证明双方真的消费交接，不能满足对接流程可用性的验证方向。
