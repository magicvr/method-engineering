# D-005 · 将“元规则”请求收敛为 Method Engineering 主导的需求澄清目标

## 决定

保留 book_green 已提交、维护者曾接收的“元规则”请求历史，不把它改写为无效或从未发生；但当前工作授权收敛为需求澄清目标，而不是候选方法构建、比较或试用目标。

P2 由 Method Engineering 主导收集和核对最小必要事实：具体创作情境、希望完成的判断或工作、已经观察到的需要/问题、目标和限制。作品仓提供其已有的创作事实、目标、限制和使用反馈，不承担方法的工程化分解、候选设计、方法验收方案、根因诊断、候选比较或工程证据整理。当前不要求 book_green 额外回答方法设计问题。

只有在形成具体创作情境和可核查问题，并判断其具有足够具体且局部有界的方法工程边界后，才进入 Method Engineering 主导的研究、设计、构建、内部验证和交付阶段。若事实仍不足，则记录等待条件，不构建猜测性方法。

## 理由与影响

旧解释把真实需求澄清提前扩展成了候选方法分析，并把作品方的创作边界探索、方法候选比较和试用责任混在一起。那不是本次需求入口的必要条件，也不符合 Method Engineering 应承担方法构建责任的边界。

本决定不改变 Root S1 状态，不把 GOAL-002 D1 探索写成已完成，不改变 VP-002 的大纲终点，也不声称方法响应、真实使用、反馈或作品验收已经发生。既有 P2 工作稿保留供 Method Engineering 内部参考，但其旧的执行建议不再是当前任务，不要求 book_green 使用、比较或验证。
