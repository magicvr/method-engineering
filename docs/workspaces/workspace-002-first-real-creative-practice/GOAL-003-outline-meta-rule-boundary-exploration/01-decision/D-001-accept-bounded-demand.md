# D-001 · 接受有界元规则环节需求并建立 draft 目标

## 决策

维护者选择方案 A：接受 book_green 关于小说大纲构建中“元规则”环节的真实方法需求，并在 `[workspace-002-first-real-creative-practice]` Root `GOAL-001-first-real-creative-practice` 下建立本直属 `draft` 目标。

接受的不是某个最终“元规则”，而是一项独立且可核对的方法工程范围：澄清单一环节的职责和边界，识别必要信息与假设，比较候选方法，设计有限试用与证据观察，并列出由 book_green 决定的事项。

## 范围与非目标

- 允许重新命名或否定“元规则”这一工作性称谓。
- 只分析与相邻环节确有必要的接口，不重设计整个六步创作流程。
- 不预先选择 book_green 最终采用的规则、模板、工具、条目数量或严格门禁。
- 不把候选分析、试用建议或 method-engineering 交付写成 book_green 已验证或接受。

## 门禁与审视

本决定只授权建立 `draft` 目标结构。Root I-003 仍为 `required/collecting`，Root S1 尚未退出；在该门禁按治理要求解除前，不开始 P2 方法响应、P3 试用或任何实际创作推进。后续阶段默认采用 `self` 审视；若范围、风险或证据状态发生变化，再按 P-004 重新判断。

## 理由

提报已满足 D-004 的真实问题、现状依据和希望获得的帮助三类最小信息；请求边界独立、交付物可核对且明确不要求冻结最终方法。建立 `draft` 目标可保留真实需求的追踪性，同时不把未完成的 S1 信息门禁或尚不存在的作品证据伪装成已满足。
