# D-008 · P3.1 将最小背景世界模型工作定义操作化为可执行步骤

## 决定

P3.1 采用下列操作化，全文见 [`attachments/p3-1-min-background-world-model-procedure.md`](../attachments/p3-1-min-background-world-model-procedure.md)。该文件是 Method Engineering 可据以执行的步骤和最小记录形态，仍待 P3.2 内部验证，不是 P3.3 交付，也不是作品仓使用证据。

1. **记录用类型条目，不用世界观栏目模板。** 一次构造只维护：参考切片 R、显式差异 D、已成立事实 W、未知 U、可能后果 P、冲突 C，外加充分性核对与重开条件。
2. **继承写成一条常驻规则，不枚举常识。** 未被 D 覆盖的部分默认继承 R；不把「人要吃饭、建筑有门」等写入 W，除非后来要覆盖或出现冲突。
3. **必要后果用可反驳测试，不用类型惯例。** 仅当「承认 D 同时否认该句」会与 D 矛盾，或使主题选择所依赖的默认无法被参与者共享时，才写入 W。其余记入 P 或 U。
4. **停止用两问，不用完整度清单。** Q1 默认是否稳定共享；Q2 是否足以进入主题选择。两问皆是才停止。未达到则只补 R、D 或必要推论，不新开独立元规则层。
5. **D 可以为空。** 纯继承参考切片是合法的最小背景世界模型。
6. **空仓可跑第一遍。** 若 R 粗到无法共享默认，本方法的合法输出是「尚未充分」，不是补一层「元规则」。

## 理由

P2 工作定义已经规定对象、充分性、内容和构造职责，但还不能直接执行。P3.1 需要把「继承 / 构造 / 推论 / 维护 / 停止」落成有先后、有停止、有记录位置的动作。

类型条目避免重新滑向地理—历史—政治栏目表。常驻继承规则避免把世界模型写成百科。必要后果测试是为了把「闭包」收成可停止的一步，而不是无界推演。两问停止直接对应 D-006/D-007 的充分性边界。允许空 D 和「尚未充分」输出，是为了让空仓筹备也能执行，而不倒逼虚构设定。

## 未选方案

| 方案 | 未选理由 |
|------|----------|
| 直接把 P2 工作定义当作可执行方法 | A-001 F-001：尚未操作化，也无内部验证。 |
| 固定世界观字段清单（地理 / 历史 / 政治等） | 与最小充分性冲突；会把「写全」当成停止条件。 |
| 把继承的常识逐条写入 W | 记录负担高，且把默认伪装成显式设定。 |
| 把类型惯例或「常见后果」一律写成必然 | 会把 P 写成 W，无法停止，也容易误导主题选择。 |
| 本拍同时做 P3.2 内部验证 | P3 三步顺序执行；本拍只形成可执行步骤和记录形态。 |

## 影响

- G-003 改为 `collecting`：步骤与记录形态已形成，内部验证未做，P3 未退出。
- A-001 F-001 仍开放：P3.1 完成操作化，P3.2/P3.3 完成后才关闭。
- 独立元规则层零假设不变。本拍若发现无法由 R/D/W/U/P/C 及本步骤承载的持续前置约束，须回流残余分析，不得在步骤里恢复独立层。
- 不创建子目标，不进入 P4，不向 book_green 索取「元规则」定义或方法设计。
