# P2 工作稿 · 候选边界与方法分析

> 本文是 GOAL-003 在旧版“D1 内有限前置方法分析”解释下形成的历史工作稿。VP-002 v0.4.0、GOAL-003 D-005/E-005 已取代其作为当前工作任务的地位；内容仅保留供 Method Engineering 内部参考，不是当前方法、作品方接受标准或独立审计结论。不得要求 book_green 使用、比较或验证其中候选，也不得把其中材料写成已成立的具体方法需求。此前的 `meta-rule-preliminary-exploration.md` 只作为普通参考；其中的“现实参考态—差异—传播/闭包”保留为待检验假设。

## 1. 当前真正要解决的问题

目前已确认的是：作品方提出了小说大纲构建中一个被称为“元规则”的工作性环节，但其职责、必要性和使用方式尚未明确。当前没有证据证明问题一定来自“缺少现实默认值”“差异后果没有传播”或“世界观不一致”。

因此，本轮要解决的不是先定义一个完整世界，也不是证明必须存在一个叫“元规则”的独立层，而是回答：

> 为了支持大纲构建中的一个具体判断，我们需要怎样处理已有设定、默认假设、推论和未知？这种处理是否值得被单独表达并重复使用？

需要区分：

- **问题线索**：不知道从哪里开始设定、担心设定无限扩张、未声明内容理解不一致、或新增设定后不知道哪些后果需要处理。这些目前只是待验证线索。
- **本目标产出**：可操作的职责边界、候选方法和有界试用设计，使后续真实试用能够判断帮助、成本和失败方式。
- **非目标**：定义完整世界、推导所有社会后果、规定所有小说的统一流程、提前固定整份大纲的接受标准，或证明“元规则”必须成为独立环节。

## 2. 候选职责与相邻环节

本稿中的“当前判断”指一个尚待作出或仍可修改的具体创作判断，不等于已经接受的作品结论、事实或方法标准。

| 对象 | 主要回答 | 候选规约的接口 |
|---|---|---|
| 候选规约 | 当前判断依据什么成立？哪些推论依赖额外前提？何时保留未知或重新检查？ | 管理判断依据、推论强度和探索边界 |
| 世界模型 | 在作品中哪些事物、关系、规律和状态成立？ | 保存具体世界内容；不另建第二套事实 |
| 主题 | 作品要观察、讨论或突出什么？ | 帮助选择值得探索的问题，但不替代世界因果 |
| 叙事窗口 | 从谁、何时、何处、以什么信息权限观察？ | 限定当前需要关注的范围，并区分世界事实、角色认知和读者获知 |
| 故事线 | 哪些事件发生、如何关联并形成推进？ | 提出设定需求并检验设定后果，也可反向触发设定修订 |

候选规约最多暂时承担四项职责：

1. 标明判断依据是作者设定、参考知识、暂定假设还是推论；
2. 暴露会改变判断结果的缺失前提和冲突；
3. 区分可推出的后果、依赖额外假设的后果和仅供选择的可能性；
4. 为当前问题设定探索边界、停止条件和重开条件。

这些接口允许来回触发；不把现有六步主线冻结为必须线性执行的流水线。

## 3. 候选路径

### A · 参考框架与偏离描述

选择一个当前可用的参考背景，说明哪些内容继承、哪些内容改变，再检查改变对当前问题的影响。

优点是可能减少重复设定；风险是参考背景未必被参与者稳定共享，多个偏离可能使默认继承失效，也容易把常见后果误写成必要后果。

### B · 具体判断驱动的局部规约（暂定推荐）

从一个当前确实需要处理的创作问题出发，记录相关设定、依据、缺失前提、推论分支及其对当前判断的影响，只展开足以支持该判断的部分。

最小操作形态暂定为：

```text
当前判断
→ 相关设定及其依据
→ 缺失前提 / 冲突 / 推论分支
→ 对当前判断的影响
→ 暂定处理
→ 停止条件与重开条件
```

优点是不要求已有完整世界或接受标准，容易观察实际帮助和成本；风险是局部处理可能漏掉其他场景的冲突，也可能只是增加记录负担而没有创作收益。

### C · 不设独立环节，嵌入世界模型维护（成本基线）

直接在具体设定旁记录依据、未知和修订原因，只有在需要时进行局部一致性检查。

优点是成本低、避免维护额外抽象层；风险是规则可能散落，重复问题或协作需求出现时不易复用。

### 暂定取舍

建议先检验 B 是否比 C 带来明确帮助；A 作为 B 的可选技术，只在具体问题确实需要参考背景/继承描述时使用。若 B 与 C 的效果没有可感知差异，保留 C、取消独立“元规则”环节是合法结果。

## 4. 仍然只是待验证的假设

- 作品确实需要独立表达的判断规约；
- 记录依据和推论分支能改善判断，且收益大于新增负担；
- 局部探索能够控制遗漏，而不会变成无界世界模拟；
- “元规则”比更具体的名称更有帮助；
- 参考背景可以被参与者稳定理解；
- 判断规约需要产出单独文档，而不是世界模型中的局部注记。

“现实参考态”“只写差异”“必要后果传播/闭包”均不在本稿中被提升为规则；只有真实试用能够支持时，才考虑保留、缩减或改写。

## 5. P3 的最小试用与反证条件

P3 至少需要一次真实且会影响作品的创作判断；不要求完整大纲，也不要求事先存在失败案例。最小证据应能定位：

- 使用前的问题、已有想法和不确定处；
- 实际采用的步骤、额外假设和投入；
- 使用后保留、修改、放弃或暂缓的内容；
- book_green 对有用、无用、过重或误导之处的判断。

P3 不只记录失败。条件允许时，应在同一个真实问题上记录 B 与成本基线 C 的可比处理，或记录两个足够相近的真实判断，并至少比较：是否更清楚地暴露了影响决策的假设、是否改变了可选方案或修订方向、额外投入是否可接受，以及 book_green 是否认为这种差异确实帮助了当前判断。一次试用最多支持本问题、本片段和本次条件下的局部保留，不支持对其他作品或场景的普遍结论。

结果应按以下范围记录，而不是只写“有效/无效”：

| 结果分类 | 最低依据 | 后续处理 |
|---|---|---|
| 暂定保留 | 相比 C 有明确的、与当前判断相关的帮助，且额外成本可接受 | 保留为候选，并限定适用问题和条件 |
| 有界保留 | 只在特定问题、信息权限或推论类型下有帮助 | 缩小边界，继续收集针对性证据 |
| 嵌入 C | 没有足够独立收益，但局部记录仍有用 | 取消独立环节，将其并入世界模型维护 |
| 否定/暂停 | 成本明显超过收益、反复误导，或无法处理核心失败现象 | 否定候选、暂停使用，必要时回流重新定义问题 |

如果无法形成 B 与 C 的可比证据，应记录为证据不足，而不是把“没有观察到差异”写成候选已被否定。

以下结果应触发调整：

| 观察 | 处理 |
|---|---|
| 参考背景反复造成不同理解 | 收缩或放弃默认继承，显式记录关键假设 |
| 推论不断引入新设定，无法回到当前问题 | 缩小问题和传播范围，检查问题是否定义过大 |
| 规约只是复述原判断，却增加记录成本 | 缩减为世界模型中的局部注记，转向 C |
| 局部判断反复被其他场景推翻 | 增加有针对性的跨场景核对，重新评估 B 的适用范围 |
| 把概率、惯例或类型偏好当成必然性 | 修订推论分类；若属于核心缺陷，则否定该候选 |
| 规约妨碍有意保留的寓言、荒诞或模糊性 | 缩小适用范围，必要时停用 |
| 输入并非真实问题或作品方未实际使用 | 证据不足，不判定有效或无效 |

## 6. 当前 P2 结论边界

本稿推荐一个轻量、具体判断驱动的候选路径，暂不把它命名为最终“元规则”，也不把它认定为独立创作环节。下一步应围绕一个真实的设定选择或创作判断，把 B 的最小操作形态具体化；试用时要把待决/候选判断、B 与 C 的处理差异和结果分类一并记录。自造微例只能检查表达是否清楚，不能替代作品证据。

若未来在真实需求澄清后确实形成了具体方法需求，Method Engineering 可以重新审视本文中的局部线索；但必须重新核对创作情境、问题、目标和限制，不能直接把本稿候选作为方法交付或试用方案。本文不再要求作品仓执行其中的比较、记录或证据收集。此前“下一步围绕真实判断具体化候选”的建议已随旧解释一并退出当前工作。

## 历史状态

本文保留旧阶段已经形成的分析内容和假设，不证明这些内容有效，也不证明“元规则”已经成为独立方法需求。当前工作以 GOAL-003 的 P2 需求澄清为准；任何后续方法设计、验证和交付均由 Method Engineering 重新承担并另行记录。
