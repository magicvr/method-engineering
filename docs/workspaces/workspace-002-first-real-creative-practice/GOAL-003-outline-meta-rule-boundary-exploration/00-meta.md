# GOAL-003 · 澄清小说大纲构建中“元规则”诉求对应的真实方法需求

## 概述

本目标承接 book_green 已提交、并曾被维护者按独立方法需求方向接收的“元规则”需求信号。P2 已将该信号澄清为有界方法/工具需求：**最小背景世界模型及其构造方法**。P3 在本目标内启动；本拍不派生子目标，也不把该需求另建为 Root 兄弟 Goal。

本目标以澄清例外起步，P2 完成后由其自身 P3/P4 承接本条已澄清需求的方法响应。该安排只适用于当前这条需求，不改变后续“未接受信号先进入澄清、方法响应另行建立”的一般规则。

本目标不把“元规则”写成已确认的最终概念或独立层，不替 book_green 作创作判断，不把当前六步主线冻结为线性流程，也不扩展为整套创作流程重设计。P2 工作零假设仍然有效：独立元规则层暂不成立。P3 必须把工作定义操作化并做内部验证，不得把澄清附件直接当作交付方法。VP-002 v0.4.0 已取代旧的 D1 前置方法分析解释。

## 成功标准（暂定）

- [x] 由 Method Engineering 记录足以界定需求的最小事实：具体创作情境、想完成的判断或工作、已观察到的需要/问题、目标和限制；不足之处明确标为待澄清。
- [x] 由 Method Engineering 主导判断问题属于创作对象、方法/工具还是运行机制，并决定是否形成有界方法工程需求；不要求 book_green 完成工程化分解或根因诊断。
- [x] 若需求尚不足以进入方法响应，记录等待条件，不构建猜测性候选；若已足够具体，进入 Method Engineering 的研究、设计、构建和内部验证阶段。
- [ ] 若发生交付和正常使用，作品仓只反馈实际现象、影响和预期；Method Engineering 负责诊断、修正、验证和再交付。
- [ ] 将作品方对创作目标、实际有用性和作品成果的判断，与 Method Engineering 对方法设计和工程证据的责任分开记录。

### 与 D1 探索目标的关系

Root 原 `I-003` 已重分类为 VP-002 D1 的创作接受边界探索目标，由 `GOAL-002-real-work-repo-info-readiness` 的 P4 承载。GOAL-003 的 P3 不要求 D1 先完成，也不向 D1 提供前置方法分析；不要求 book_green 定义「元规则」或产生候选方法。

## 父目标与门禁关系

- 父目标：`GOAL-001-first-real-creative-practice`。
- 本目标是 Root 下的直属目标，保持 `active`；P2 已完成，P3 已在本目标内启动。它不改变 Root S1 状态，不把 D1 探索目标写成已完成，也不替代 GOAL-002 的 P4/P5 交接。
- 本条需求的方法响应由本目标 P3/P4 承载，本拍不派生子目标。作品仓不承担定义「元规则」、候选设计、方法验收方案、根因诊断、候选比较或工程证据整理。

## 审计模式

当前按 `self` 规划后续阶段审视：范围可逆，且本目标不修改治理协议、生产发布或安全门禁。若后续方法响应影响范围扩大、出现证据冲突或维护者要求第二视角，再单独按治理要求决定是否引入 independent/cross。

## 台账布局

本目标使用平铺的 `01-decision/`、`02-execution/`、`03-audit/` 和 `attachments/`。新增决定、事实和正式审计意见分别写入对应 ledger 目录；既有 P2 工作稿和 D1 前置分析授权保留为历史记录。`p2-minimum-background-world-model.md` 是现行 P2 工作定义与残余分析，仍不是 P3 交付方法。P3 已启动但尚未完成操作化、内部验证或交付；没有把真实使用或 book_green 对方法的接受写成已发生事实。
