# D-004 · 将首轮信息请求进一步收敛为最小事实集

- **日期**：2026-09-18
- **状态**：accepted
- **决策来源**：用户进一步明确 Root 门禁只保留真实运行所需信息；沟通节奏等问题留给仓外协调。
- **交付状态**：已生成、待发送；本条记录不表示真实作品仓已经收到或回复。

## 决定

1. 保留五组直接影响 Root I-001～I-005 的事实：作品仓与当前状态、范围与起点、固定终点与接受条件、实际责任边界与决定/接受权、投入限额。
2. 删除对联系人、沟通渠道、沟通节奏、响应时间、反馈格式、交接记录方式和完整协作者名册的请求。它们不属于 Root S1 门禁，除非后续事实证明某项具体细节影响门禁，再单独提出针对性问题。
3. 不要求固定回复模板或状态标签。作品方可以用自然语言、已有文档或仓库引用提供事实；我们在收到后自行登记来源、状态和缺口。
4. 不要求一次性提供整个作品仓或与当前门禁无关的材料。若当前下一创作阶段不是 VP-002 固定的“包含故事线规划、足以进入下一创作阶段的大纲”，立即暂停并回流 `/vision`，不扩张“大纲”定义。

## 可直接发送正文

### 主题

VP-002 首个真实作品实践：首轮信息确认

### 正文

你好。为了判断这次实践是否可以从作品当前真实状态出发进入下一步，请提供以下与本次实践直接相关的事实即可。不要求特定回复格式，也不需要一次性发送整个作品仓；可以直接用自然语言、已有文档或仓库引用回答。

1. **作品仓与当前状态**

   请说明作品仓的名称及稳定 URL/路径；提供能够代表本次实践的分支、tag、commit 或版本号；说明当前已经完成什么、正在推进什么、下一步原计划是什么，并给出与本次判断直接相关的文档、素材或目录路径。

2. **本次范围与起点**

   请说明本次大纲要覆盖什么、明确不覆盖什么、从哪些已有文档/素材/版本或创作状态开始，以及已经存在的硬约束、依赖或不可改变条件。

3. **固定终点与接受条件**

   请说明对这部作品而言，什么样的成果算作“包含故事线规划、足以进入下一创作阶段的大纲”；最低需要满足哪些条件；接受后作品实际进入哪一个下一创作阶段；由哪一类角色拥有最终接受权；哪些反馈仍属于本次范围，哪些会超出范围。

4. **实际责任边界与决定权**

   请说明：作品方负责哪些创作事实和创作决定；Method Engineering 负责支持什么、不负责什么；是否有其他角色拥有会改变本次范围、固定终点或接受结论的决定权，以及其实际责任是什么。只需要这些责任和权力事实，不需要联系人、渠道、节奏、响应时间、反馈格式、交接方式或完整协作者名单。

5. **投入限额**

   请说明作品方和本次实践可投入的时间、轮次、工作量或其他等价上限；如果超过上限，是否需要重新作出范围/投入决定。没有明确限额的部分请直接说明未知，不要用推测替代。

如果当前下一步并不是“包含故事线规划、足以进入下一创作阶段的大纲”，请直接说明实际下一步。我们会暂停并重新判断方向，不会扩张“大纲”定义或要求作品适配预设流程。

收到后，我们会逐项核对哪些信息已足够、哪些缺失、哪些需要澄清或存在冲突，再只就实际缺口提出补充问题。首轮回复不等于 Root S1 已通过。

谢谢。

## 内部映射与使用边界

| 请求部分 | 对应 Root 信息项 | 本轮边界 |
|----------|------------------|----------|
| 1. 作品仓与当前状态 | I-001 | 只请求能确认作品身份、版本和真实状态的事实；不要求额外资料格式 |
| 2. 范围与起点 | I-002 | 只请求本次大纲的实际边界、起点和硬约束 |
| 3. 固定终点与接受条件 | I-003 | 只请求作品级最低接受条件、下一阶段和接受权 |

| 5. 投入限额 | I-005 | 只请求可执行的时间/轮次/工作量上限及是否需要重新决策 |
