# D-001 · 采用迭代式真实作品仓信息就绪闭环

- **日期**：2026-09-18
- **状态**：accepted
- **决策来源**：用户本轮明确要求新增该子目标，并描述了迭代式收集与审视流程。

## 决定

1. 在 workspace 002 的 Root `GOAL-001-first-real-creative-practice` 下创建本子目标，专门处理真实作品仓相关的 D1 信息发现与就绪判断。
2. 采用“定义请求 → 作品仓提交 → 完整性/一致性审视 → 补充或澄清 → 再审视”的可重复闭环，直到 Root I-001～I-005 均有可核对证据，或发现必须回流 `/vision` 的固定终点不匹配。
3. 每轮只把有来源、版本/日期或其他可核对依据的内容登记为事实；缺失、歧义和冲突保持开放，并形成下一轮的具体请求。
4. 本目标的产物是供 Root 核对的信息就绪包；它不自动改变 Root `status`，不自动关闭 Root 信息项，也不预先创建 S2 的方法工程 Goal。

## 理由

用户描述的工作不是一次性问卷，而是信息提供方与治理方之间的逐轮校正。将循环边界、证据门槛和回流规则单独落在一个子目标中，可以让 Root 保持其稳定的 D1 门禁，同时避免把未确认的作品事实或未来需求提前写入 Root。

## 未选方案

- **一次性收集全部信息后直接推进 Root**：无法可靠处理缺失、歧义或互相矛盾的回答，不采用。
- **先预设作品方法 Goal 再等作品适配**：会违反 VP-002 真实需求驱动与不预先创建未来方法 Goal 的边界，不采用。

## 影响与后续

- 首轮工作是形成覆盖 Root I-001～I-005 的请求包，不是假定作品仓已经提供信息。
- 若真实作品的下一阶段不符合 VP-002 已冻结终点，必须停止扩大“信息收集”语义并回流 `/vision`；不得为了通过 D1 改写终点或要求作品方适配预设流程。
