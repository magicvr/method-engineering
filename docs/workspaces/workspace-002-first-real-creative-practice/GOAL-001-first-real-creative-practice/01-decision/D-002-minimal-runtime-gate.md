# D-002 · 将 Root S1 信息门禁收敛为最小真实运行集

- **日期**：2026-09-18
- **状态**：accepted
- **决策来源**：用户明确要求把 Root 门禁收敛为只要求真实需要的信息。

## 决定

1. 保留 Root I-001、I-002、I-003、I-005：它们分别回答作品身份/状态、范围/起点、固定终点/接受条件和投入限额，直接影响 D1、S1 或后续扩张控制。
2. 将 Root I-004 收敛为：作品方、Method Engineering 及必要协作者的实际责任边界，以及谁有权作出影响本次范围/终点的决定或确认接受。它不再要求交接方式、反馈格式或其他沟通协议。
3. 联系人、固定渠道、沟通节奏、响应时间、反馈格式和完整协作者名册不属于 Root S1 的信息门禁，留给仓外协调；首轮请求不得把这些格式信息当作必填项。
4. 若真实运行后来证明某项协调细节确实影响实施、反馈闭环或门禁，再登记针对性的新增信息项；在此之前不预收集，也不把未知伪装成已验证事实。
5. 本次只修订门禁定义和信息请求边界，不关闭任何信息项、不改变 Root 状态，也不改变 VP-002 的固定终点。I-001～I-006 继续保持 `required/open`。

## 理由与取舍

Root 门禁需要的是能够决定范围、终点、接受和投入边界的真实事实，而不是便于格式化协作的资料。将沟通节奏和记录格式放入门禁会增加作品方负担，却不能证明 D1 已就绪。取舍是：如果运行中出现实际阻塞，再以具体事实为依据补充，不预先建立无证据的格式要求。

## 影响

- GOAL-002 的当前首轮信息请求改为只请求上述最小事实集。
- S1 的退出条件改为检查“实际责任边界与接受/范围性反馈的决定权”，不检查联系人、渠道、节奏、格式或名册。
- Root 仍需等作品仓提交并完成逐项核对，不能因请求收敛而提前通过 S1。
