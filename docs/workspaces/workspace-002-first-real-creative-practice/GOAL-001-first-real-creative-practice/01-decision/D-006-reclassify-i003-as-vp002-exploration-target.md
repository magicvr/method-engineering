# D-006 · 将 I-003 重分类为 VP-002 内部探索目标

## 决策

将原 Root `I-003` 的当前治理角色从“预先存在的 P-005 required 信息与启动门禁”重分类为 **VP-002 D1 的有界探索目标**。`I-003` 这一历史编号保留用于追踪，但不再作为 GOAL-003 开始 P2 候选分析的前置条件。

当前由 `GOAL-002-real-work-repo-info-readiness` 的 P4 承载该探索目标；`GOAL-003-outline-meta-rule-boundary-exploration` 作为已经接受的独立方法边界目标，可以在该探索尚未完成时进入 P2，并将其分析结果作为 D1 探索的候选输入。

本决策不表示接受条件已经形成，不表示 Root S1 已完成，也不授权 S2 方法响应、作品验收或 VP-002 关门。D1 探索的候选边界及其真实作品证据，仍须在后续由 book_green 判断并记录。

## 理由

1. 当前 VP-002 尚不存在可供事先验证的最低接受条件或下一阶段进入条件；把它作为同一实践的启动门禁会产生循环依赖。
2. VP-002 已明确允许在 D1 内通过真实推进形成候选、证据和边界；探索对象本身不应再被当作探索的前置输入。
3. 将其作为探索目标可以保留范围、投入上限、证据和退出条件，同时允许 GOAL-003 贡献问题分析和候选方法工作。
4. 后续 VP 或工作区可以在已有本次实践证据的基础上，把形成的边界作为新的 required 门禁；这不等于本 VP 在起点就拥有该门禁。

## 未选方案

- **继续把 I-003 作为 GOAL-003 P2 的硬门禁**：会把“需要被探索的未知”误当成“必须先具备的输入”，保留当前死锁。
- **以用户 residual/overruled 直接绕过 I-003**：不采用；这里不是接受一个已知风险，而是修正门禁的对象分类。

## 影响与后续

- Root 仍保持 `draft`，S1 仍未退出；其退出需要 D1 探索形成候选边界、作品证据并由 book_green 确认。
- `GOAL-002` 保留为 D1 探索的承载目标，但不再把 I-003 当作其必须先验证的输入。
- `GOAL-003` 改为 `active`，允许开始 P2 候选边界与方法分析；G-001 仍阻断 P3 的真实试用结论。
- 同步更新 Root、工作区、目标树及两个相关目标的当前门禁说明；不改写既有历史决策和执行事实。
